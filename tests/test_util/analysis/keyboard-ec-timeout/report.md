# Таймер гашения клавиатуры: аппаратная настройка пока не установлена

Дата анализа: 13.10.2026. Плата: WUJIE Series-X5SP4NAG / Wujie 15X Pro.

## Свежая проверка 13.10.2026

Получены один начальный снимок и две серии: 181 снимок (11:45:23–11:48:24
по Москве) и 301 снимок (11:51:50–11:56:50). Всего **483 снимка по 4096 байт**,
ошибок чтения нет. `settings_writes=false`. Это RAM EC; исполняемая прошивка
контроллера этим чтением не извлечена.

Серии лежат в `tests/test_util/logs/keyboard-native-series/`:

- `MECHREVO-X15PRO_windows_20261013_084523_709Z`;
- `MECHREVO-X15PRO_windows_20261013_085150_199Z`.

Утилите добавлен `--ec-only`: кроме EC RAM записываются состояние питания,
режим Windows, политика процессора AC/DC и время ввода. Во второй серии
отдельно считаются заголовки Raw Input клавиатуры. Коды клавиш, скан-коды
и символы не читаются и не записываются. Обе серии завершены.

### Гашение и возвращение Мульти

Во время первой серии пользователь несколько раз сообщил о гашении и
возвращении подсветки. Во второй серии отдельный счётчик клавиатуры
зафиксировал два события заголовка — нажатие и отпускание обычной клавиши.

| Событие | Москва | `0x741` | Без клавиатуры |
|---|---|---|---|
| После нажатия | 11:55:04 | `0x84 → 0x80` | около 0,2 с перед чтением EC |
| После паузы, пользователь подтвердил гашение | 11:55:35 | `0x80 → 0x84` | около 31,2 с перед чтением EC |

Байт `0x741` прочитан на 0,29 с позже отметки ввода. При частоте снимков 1 Гц
наблюдаемый момент установки bit 2 находится примерно в диапазоне
30,5–31,5 с после последнего клавиатурного события. Активность мыши
сбрасывала общий Windows idle, но клавиатурный idle продолжал расти.
Это подтверждает связь штатного гашения с отсутствием клавиатурного ввода.

Во всех 482 кадрах серий `0x767 = 0x80` (Мульти), `0x78C = 0x80`
(выбран уровень 4), `0x78D = 0`. Цветовые настройки `35/0/50` сохранены.
Следовательно, гашение не сбрасывает выбор эффекта или уровня яркости.
**Bit 2 в `0x741` — наблюдаемый признак гашения, а не найденная уставка времени.**
Применимость записи этого бита для изменения таймера не установлена.

### Подключение зарядки и Офисный

Во второй серии записан полный цикл, подтверждённый пользователем:

| Состояние | Москва | Windows effective mode | `0x751` |
|---|---|---|---|
| Батарея | 11:51:50 | 1, Better Battery | `0xA0`, Офисный |
| Зарядка подключена | 11:52:32 | 2, Balanced | `0xA0`, Офисный |
| Зарядка отключена | 11:53:24 | 1, Better Battery | `0xA0`, Офисный |

Во всех кадрах EC сохранял Офисный; таблица `0x734/0x735/0x736 = 45/45/65`,
пользовательские overrides `0x783/0x784/0x785 = 0/0/0`. Эти байты — данные EC,
не непосредственное измерение применённых SMU-лимитов.

Активная схема Windows не менялась:
`381B4222-f694-41f0-9685-ff5bb260df2e`. Из базовой схемы прочитаны:

| Политика процессора | От батареи | От сети |
|---|---:|---:|
| Energy Performance Preference | 80 | 20 |
| Ограничение частоты | 2900 МГц | 0, без ограничения этой настройкой |
| Boost mode | 2 | 2 |

Температура CPU в EC при питании от сети достигала 53 °C; на батарее во
второй серии — 37–43 °C. Нагрузка не контролировалась, поэтому это не
доказывает единственную причину нагрева. Запись показывает смену политики
Windows без сброса Офисного в EC. Лимиты EC задают верхние пределы,
а не постоянную частоту или температуру.

При подключении `0x7CC = 0xA4`, `0x7CD = 0`, `0x7CE = 65`.
OEM `GetPowerFromTypeC` вернул бы max(0,65)=65. Напряжение/ток PD-контракта
эта запись не измеряет. После отключения: `0x7CC=0x80`, оба байта мощности 0.

## Предварительный разбор до свежих наблюдений

## Требование

Пользователь наблюдает гашение подсветки и включение при нажатии клавиши
без MagicControl. Нужен контрол «Погаснуть [значение со стрелками] сек»,
который изменяет таймер в EC и сохраняет действие после выхода из приложения.
Программный таймер, фоновая служба и периодическое восстановление яркости
этому требованию не соответствуют.

## Подтверждено исходниками

- `C:/Users/admin/Documents/mechrevo/Decompiled/DefaultTool/MyControlCenter/KeyboardCloseTimer.cs`:
  `SetKeyboardCloseTime(int seconds)` задаёт `_TimersTimer.Interval = _Seconds * 1000`.
  Клавиатура и мышь перезапускают программный таймер; `ControlBrigtnessEvent`
  сообщает о гашении/возврате. Этот класс не записывает время в EC.
- `.../DefaultTool/MyControlCenter.MyRgbKeyboard/SingleZone.cs`:
  обработчик `CreateInstance_ControlBrigtnessEvent` вызывает
  `SetPowerDisable_EC`, который изменяет bit 1 регистра `1932 = 0x78C`.
  Это переключатель подсветки, а не длительность бездействия.
- `.../GCUService_Reference_w568w/GCUService/MyControlCenter/MySettingManager.cs`:
  `SetCloseTimer` сохраняет `CloseTimer` в реестре Windows.
  `Init` передаёт значение в `KeyboardCloseTimer`.
  Это дополнительное свидетельство программной реализации; версия службы
  отличается от установленной на этой плате.
- `.../DefaultTool/Define/ECSpec.cs` определяет `ADDR_SINGLEKBL_ENABLE = 1932`
  и `ADDR_SINGLEKBL_SUPPORTPOWER = 1934`, но не именует регистр таймера клавиатуры.
- Сохранённая DSDT содержит доступ к EC RAM и клавиатурное ACPI-устройство,
  но подтверждённого метода установки таймаута подсветки в ней не найдено.

## Сохранённые снимки

`saved-snapshots.json` получен `scan_keyboard_timeout.py` из существующих
журналов SensorProbe. Во всех 130 снимках: `0x741 = 0x81`, `0x7C6 = 4`.
Следовательно, это RAM-управление с флагом присутствия приложения;
штатный режим с `0x741.0 = 0` ими не исследован. `0x78C = 0x80`,
`0x78D = 0` во всех снимках. Физическое гашение и нажатия клавиш в этих
журналах не отмечены.

Поиск изменений с темпом около одного отсчёта в секунду нашёл, в частности,
`0x6FA`: значение растёт и циклически возвращается примерно раз в минуту.
Назначение не установлено. Такая последовательность не доказывает связь
с клавиатурой и не даёт оснований записывать туда требуемое время.

Дампы 4096 байт по `0xFED50000` — снимки RAM EC. Они не содержат полного
исполняемого кода BIOS/EC. Отдельного образа EC flash в проверенных папках
`mechrevo` и `mechrevo_dsh` пока не обнаружено.

## Состояние реализации

Геометрия поля общая для Windows и Linux. Windows использует EDIT + UPDOWN
и `NumericFieldTheme` из FANs; Linux — тот же `createNumericField`, что FANs.
Поле пустое и отключено, поскольку текущее значение, адрес, единицы,
допустимый диапазон и команда применения аппаратного таймера не установлены.
Запись настроек и программный таймер не добавлены. Контрол пока отображает
неизвестное значение и не изменяет настройки.

Для продолжения нужен полный образ EC/BIOS с кодом контроллера либо
новое наблюдение EC RAM в штатном режиме с отмеченными моментами
«светится / погасла / клавиша / снова светится». Даже найденный счётчик
потребует отдельно доказать наличие записываемой уставки и сохранение после
выхода приложения. Сам факт штатного гашения не доказывает регулируемость.
