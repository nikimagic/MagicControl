# Wujie: временный ROM-ID04 в EC RAM при платформе7

Проверка22.10.2026,09:37:09–09:37:43Москва (06:37UTC).
Владелец отдельно подтвердил адрес770 и значение04. Это диагностическое
исключение; production writer и остальные режимы не получили записи ROM-ID.

## Условия и физический результат

- Точная MECHREVO WUJIE Series-X5SP4NAG, identity82/72/26.
- SOC96, AC, исходные7C3=07,770=FF, верхний10, WMI087F.low7=10, lower90.
- Baseline10отсчётов:1088–1224мА, state2,742=22,7B9=0A.
- Одна RAM-запись770FF→04 через существующий UWACPIDriver/ECRW transport.
  Fresh read-modify-write maskFB сохраняет общий bit2. Платформа/порог,
  WMI, другие байты ROM-ID и служебная пара77E/77F не записывались.
- На следующем отсчёте state стал0,742=26,7B9=8A; ещё через секунду ток0.
  Восемь последних отсчётов из10:0мА и state0, SOC96.
- Через10с770 возвращёнFF той же owned-mask процедурой. Gate/Reached
  очистились, state вернулся2. После переходных трёх нулевых отсчётов
  зарядный ток1190–1258мА; последний1224мА. Это обратимый A/B/A результат.

Вывод: при исходном upper10 иSOC96 значение ROM-ID04 физически разрешает
исполнение ограничения при7C3=7 в течение этого10-секундного опыта.
После возврата исходного ROM-IDFF ограничение снова не исполняется.
Это не доказательство точной остановки при подходе снизу к любому выбранному
проценту, работы после AC reconnect/сна/выхода или отсутствия побочных эффектов
в других ветках прошивки. В production ничего не перенесено.

## Сохранение и восстановление

Сравнены initial/trial/final4096-byte RAM snapshots:

- Из ROM770–77F во время опыта менялся только770; после возврата все16байт
  совпадают с исходными. Set_ROMID не вызывался; NVM persistence не проверена.
- Все96байт FAN tablesF00–F5F совпадают во всех трёх снимках.
- APU783–785 совпадают. FAN-related72680,72740,74181,75180,7C508,7C604
  совпадают во всех трёх снимках; duty/RPM не являются конфигурацией таблицы.
- 7C3 остаётся07,7D0=5A,7A6=00,7CC=A4.7B9 меняет только пересчитанный
  прошивкой Reached:0A→8A→0A. WMI stored остаётся10.
- Завершение exit0, restored=true,configuration_unchanged=true,
  stored_unchanged=true, battery-restore.txt пуст.

Сессия `20261022-063709-858Z-27788/`: raw JSONL, initial/trial/final dumps.
До неё первый launcher потерял stderr из-за PowerShell NativeCommandError;
после исправления редиректов следующая попытка штатно отказала из-за

владельцем приведённый опыт действительно выполнен.

## Утилита

Режим `--battery-romid-ram --apply --output DIR`; аварийное восстановление
`--battery-romid-ram --restore SESSION_DIR --output DIR`. Общие транспорт,
журнал и durable owned rollback. Жёсткий allowlist только770/FB/0 илиFB,
проверки платы/конкурирующего владельца/AC/температур и неизменности контекста.
Обычный writeAllowed по-прежнему запрещает770. Новое разрешение включается
только конструктором этого отдельного режима.
