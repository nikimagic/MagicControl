# GPU NVIDIA

Вкладка добавлена18.10.2026 для Windows и Linux. Видна только при обнаружении
NVIDIA GPU: Windows SetupAPI Display PCI VEN_10DE с DXGI fallback vendor0x10DE,
Linux PCI vendor0x10de/class0x03.
Повторное обнаружение обрабатывает подключение/отключение. При удалении активной
NVIDIA вкладки открывается FANs. Обнаружение не инициализирует NVML.

## Мониторинг

Общий сервис `src/platform/common/NvidiaGpu.cpp`, публичный typed API
`MagicControl/NvidiaGpu.h`. Установленная NVML загружается динамически:
Windows абсолютный System32/nvml.dll или старый ProgramW6432/NVIDIA Corporation/
NVSMI/nvml.dll; Linux libnvidia-ml.so.1. DLL/SO не скачиваются и не входят в поставку.
Не запускаются nvidia-smi, утилиты OEM, CUDA-задачи или установщики драйверов.

Опрос раз в секунду, только пока видна вкладка. Доступ к NVML идёт в worker,
не в потоке UI. Возможна инициализация/пробуждение GPU самим драйвером при чтении;
поэтому скрытая вкладка не опрашивается. Несколько GPU — отдельные карточки.
Если PCI-адаптер есть, но NVML недоступна, вкладка объясняет причину.

Показываются название, температура, загрузка, частоты GPU/VRAM, P-state,
потребление, VRAM всего/занято/свободно, версия драйвера/VBIOS, UUID,
запрошенный/действующий/штатный Power Limit и диапазон драйвера.
Данные каждой функции проверяются отдельно; недоступное значение — прочерк,
не0. Статистика памяти соответствует NVML и может зависеть от модели памяти ОС.
GPU fan NVML не используется вместо EC-вентиляторов ноутбука.

## Управление

Явные кнопки «Применить» Power Limit и «Штатный лимит». Ватты UI переводятся
в милливатты NVML. Никаких записей при открытии, опросе, запуске или выходе.
Настройки драйвера не подменяются сохранённым заданием.

Перед записью GPU заново выбирается по UUID (не по изменяемому индексу),
считываются текущий лимит и диапазон. Запрос за границами отклоняется. Результат
подтверждается ограниченной серией чтений. Действующий enforced-limit показан
отдельно от заданного. Readback не является нагрузочной проверкой потребления.
Записи и ошибки журналируются в канале nvidia. Неудачное подтверждение не
перезаписывает стороннее изменение старым снимком.

Наличие getter/диапазона и setter export позволяет сделать запрос, но не
доказывает поддержку записи конкретной GeForce Laptop. При NOT_SUPPORTED или
NO_PERMISSION setter отключается для этого UUID до перезапуска, причина видна.
Возврат штатного лимита также является записью и требует доступного управления.

OEM TGP и Dynamic Boost не приравниваются к NVML Power Limit. В активном
GCUService1.0.2.70 найден GCUService.MyFan.Overclocking.GpuFeatures:
0x743.2 включает ConfigurableTGP,0x744 содержит target минус SmartAPC DefaultTGP;
0x743.0/.1 — функция/включение Dynamic Boost,0x745 — TotalProcessingPowerTarget,
0x746 — MaxinumTGP. Это **не разрешение** писать эти адреса любому NVIDIA GPU.
Для отдельного OEM setter нужны точный профиль, живые SmartAPC границы и
сопоставление внутреннего GPU. Этот путь не включён догадкой о модели RTX.

## Проверка

Windows/Linux GUI и CLI собираются общим билдером, portable обновляются.
Аппаратное чтение и запись NVIDIA на GM6IR0C ещё не проверены. Тесты/нагрузка автоматически
не запускаются. Первый материал владельца — скрин вкладки и свежий журнал.
