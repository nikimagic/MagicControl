# Последние подтверждённые показания

Прямое поручение владельца24.10.2026: при временной недоступности EC сохранять
прошлые данные для всех ноутбуков, общей политикой ядра.

## Единый механизм

`core/include/MagicControl/DisplayContinuity.h` содержит общую функцию
`retainDisplayValue` и типизированные кэши отображения. Отсутствующий/нечисловой
ответ не заменяет последнее число нулём или прочерком. Полученный0/false — новое
успешное наблюдение и заменяет старое значение. Пока успешного наблюдения не было,
значение остаётся неизвестным. Кэш в памяти текущего запуска; старые значения не
выдаются за новые измерения и не переносятся между подтверждёнными разными устройствами.

| Потребитель | Общая политика |
|---|---|
|FANs Windows/GTK|MonitoringDisplayCache: CPU/GPU/RPM/PWM, температуры, память/диски, питание, NPU/SoC; исходные source и retained field times|
|GPU NVIDIA/Radeon Windows/GTK|GpuDisplayCache: последние значения на том же provider ID/physical identity; raw availability/powerControl не копируются|
|SETs Windows/GTK|EcBatteryDisplayCache/LaptopDisplayCache: данные отдельного EC/typed источника сохраняются при временном отказе|
|SingleZone SETs|KeyboardDisplayCache: последние raw/effect/level отображаются с retained flag, аппаратная доступность остаётся свежей|
|KEYs|Последний известный выбор сохраняется для отображения; available/ошибка текущего запроса сохраняются отдельно|
|Здоровье батареи|retainBatteryReadings: transient healthReadUnavailable сохраняет прошлую оценку/healthSource/healthAtMs и ставит healthStale|

Механизмы общие для всех16 каталожных моделей и обеих ОС. Наличие модели в меню
не создаёт отсутствующий источник или setter. Honor использует свой typed HWMI/
sysfs/PNPCFG, HYDROC — свои HID/EC допуски, остальные реальные профили — прежние
источники. Unknown/preview не получают искусственных чисел или аппаратных прав.

## Достоверность и безопасность

- Кэш отображения применяется после свежего raw read/верификации команды.
  Он не используется в setter, Manual online, аварийной защите, диагностическом
  collector или для подтверждения readback. При потере источника controls могут
  стать недоступными, но старые измерения остаются на экране.
- Каждый retained field отмечен отдельно. Временная метка прошлого наблюдения
  не обновляется при повторном отображении. Source остаётся исходным, а статус
  сообщает «последние подтверждённые данные». Raw ответы в логах не заменяются кэшем.
- Подтверждённое удаление батареи/диска/GPU и смена известной идентичности не
  продолжают старые измерения нового устройства. Свежая согласованная невалидная
  ёмкость сбрасывает здоровье; это отличается от временного пропуска запроса.
- Проценты/амперы/температура, использованные только для отображения, могут быть
  старше прежнего10с окна. Управляющие пути сохраняют собственные deadlines/guards.
- Здоровье EC при паузе не подменяется Windows100% из design-substituted BIF.
  При успешном следующем чтении обновляются данные и источник, stale снимается.
  OS-карточка по-прежнему показывает собственные оригинальные значения.

## Наблюдаемость

`FANs.presentation` пишет фактически выбранный GPU/причину/всех кандидатов,
retained fields/timestamps и здоровье с source/возрастом. `SETs.presentation`
добавляет selected brightness/upper index и признаки retained EC/keyboard.
GPU page presentation отдельно показывает старые данные и текущие права.
Native Windows snapshots сохраняют MC.Selected, GTK — CSS primary. UI callback/
queued не равны физическому исполнению. В итоговом SingleZone состоянии есть полный7C5.

Новые аппаратные запросы ради кэша/журнала не добавлены. Геометрия, скролл,
размеры/позиции карточек и глобальная шапка не меняются.
