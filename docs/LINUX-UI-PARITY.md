# Linux UI: соответствие Windows

02.11.2026: в расширенной карточке мощности поля CPU, GPU и дополнительных
параметров используют общие столбцы. При нехватке места для мощности
используется короткая подпись Package/APU. Ширина столбца определяется
максимальной шириной переведённой подписи текущего языка и DPI; в узком окне
подписи сокращаются с многоточием, а для измеренного значения резервируется место, если доступно. Общий helper
используют Windows и Linux. Размеры контролов, высота карточки и scroll не
меняются; карточки без дополнительных полей сохраняют прежнюю раскладку.

02.11.2026: Windows SETs при обновлении батареи инвалидирует область заголовка
Project/Platform/ROM, нарисованную самим page canvas. Сравнение принятого
snapshot включает все три ID; обновления и чтение остаются у общего владельца.
Linux уже перерисовывает canvas целиком. Координаты и scroll не менялись.

01.11.2026: общий NativeDefaultFan/DefaultFanGraph поддерживает Honor RPM
в дополнение к прежнему Wujie PWM. На обоих renderer сохраняются координаты,
шрифты и скролл; контур — запрос, заполненный маркер — факт. RPM/percent
не смешиваются. Windows HLYL BIOS1.09 поставляет guarded read-only контекст;
Linux без реального транспорта не получает выдуманного запроса/температуры.
Правила source selection находятся в ядре, не в GTK/Windows графике.

30.10.2026: графики native Default Wujie читают один core DTO через принятый
ResourceState; общий DefaultFanGraph.h форматирует легенду и подписи четырёх
языков. Обе GUI используют прежний график/геометрию и различают запрос
(контурный маркер) и фактическийPWM (заполненный). Для выбранного набора обе
температуры — управляющийEC CPU input, не ADLX/PawnIO. Параметры не попадают
в Manual и не изменяют диапазоны/кривые. Неизвестный/stale/default без reader
не подменяется драйверной температурой. Linux не получает неподтверждённого
EC-транспорта; при его отсутствии native-view остаётся недоступен. Никаких
дополнительных таймеров, hardware commands или иной механики UI.
Короткий пропуск native-чтения сохраняет снимок в общем core display cache до10с
с исходным временем и подписью «последнее чтение». Подтверждённая смена режима
убирает кривую сразу. Порог2,5с означает пометку, а не мигание всей карточки.

## Нативный счётчик подсветки Wujie,30.10.2026

Общий KeyboardIdleDisplay размещает read-only поле справа в заголовке карточки:
«Выключение подсветки через [значение] сек». Существующие кнопки, размеры карточек
и скролл не меняются. Измеряются переведённые строки встроенным шрифтом; все
координаты масштабируются общей Scale. Windows использует прежний numeric theme
без стрелок и редактирования. Linux показывает то же поле, но «—»: текущий SETs
Linux backend не имеет подтверждённого reader данного счётчика. Карта EC Wujie
не переносится на другие устройства. Unknown/stale также показывают «—».

На подтверждённом Windows Wujie короткое чтение запускается раз в1сек через
ту же очередь SETs. Полный SETs/SMU poll остаётся раз в3сек. Core читает native
8A5:8A6,741,6E6,7C3 и рабочую яркость826;825/827 и490.0 фиксируют AC/DC.
Порог выбирается платформой:4 ->30,иначе600. При APP741.0 или host-disable78C.1
поле показывает «Отключено». При истёкшем741.2 показывает0, что не является
гарантией физического погасания после AC/DC relight. Новых writers, persistence,
startup restore, FAN/power commands в этом пути нет. CLI keyboard status
выдаёт ту же core observation отдельным idle объектом.

27.10.2026: правило единого скролла записано вAGENTS.md/ScrollModel.h.
LicenseView и оставшиеся Windows drag/page-click обработчики подключены к
PageMechanics. Независимые состояния сохранены. Параметры общего helper
сохраняют прежние единицы EDIT lines и page-overlap1, а также whole-width
округление ползунка лицензии; обычные страницы сохраняют прежнюю symmetric
half-width геометрию. Не унифицировать эти округления с пиксельным сдвигом.
Native позиционирование EDIT/HWND остаётся в адаптере. Linux scrolledWidget,
GTK adjustment, geometry/card/frame/gutter/отступы и fan bounds не меняются.

27.10.2026: единый FanControlLimits задаёт поля температуры 20–100 °C и
PWM / RPM 5–100% в обеих GUI, включая повторное обновление диапазонов и
ручной ввод. Read-only данные EC показываются без зажима; пустая точка
хранится как 255 только внутри модели. HPBSD Windows Manual показывает
7/2 обычные точки без отключённых полей; MAX-защита показана отдельно.
Неподтверждённый Linux HPBSD транспорт не добавляется. Геометрия прежняя.

## WUJIE Auto,27.10.2026

Общий CpuPowerLabels добавляет Wujie пятую кнопку Auto. Обе GUI используют
прежний layout на5кнопок и прежние контролы/шрифты/DPI, без переноса карточек
или скролла. Windows имеет отдельный Auto intent и verified zero override reset;

Индексы Custom в сохранённых файлах не меняются. Другие модели сохраняют
свой состав кнопок, кодеки, writers и правила Auto.

## HPBSD native FANs,26.10.2026

Windows reuses the existing native fixed editor/async dispatch and full four
preset rectangles for Default/Manual/Min/Max. RPM targets are distinct from PWM;
actual PWM remains unknown. No card/scroll/DPI geometry is moved. Honor keeps
its old visible controls and PWM protocol. Shared GPU status no longer accepts
an unavailable fallback over a fresh ADLX reading. Linux recognises HPBSD but
does not acquire Windows I2EC fan-write or full RAM-dump capability.

## EliteMini HPBSD,26.10.2026

Общий каталог добавляет HPBSD в конце стабильных индексов (17), статус monitoring,
официальную поддержку MINISFORUM и общую GPU-проекцию с physicalId aliases.
Windows показывает подтверждённые CPU/system RPM и EC System temperature,
переводы подписей EN/SC/TC добавлены в общий каталог. Windows I2EC/PawnIO
не включаются на Linux; неподтверждённые setters недоступны. Размеры/геометрия/
карточки/скролл не менялись. Raw GPU/LUID наблюдения сохраняются в диагностике.

26.10.2026: блок keyboard auto-off (caption/check/seconds field/unit) скрыт
во всех профилях и предпросмотрах обеих ОС, включая Honor. Места остальных
контролов, card bounds, extent и скролл сохранены. Заголовок получает прежнюю
ширину карточки. Кликабельные заголовки используют общий стиль без пунктирной
рамки фокуса; обычные кнопки, клавиатурный фокус и открытие меню сохранены.

## Фактическая пульсация GM6 и скрытие picker,25.10.2026

После проверки владельцем родной XAML не считается доказательством реального
цвета GM6: прежние команды4/1/2/3 давалиBlue/White/Red/Green. Для exact GM6
установлена фактическая таблица1=White,2=Red,3=Green,4=Blue. Внешний порядок
как у WUJIE — White/Red/Green/Blue. GM5 и L16 не получают эту чужую коррекцию.
Окончательное указание владельца заменяет прежнее «оставь кнопку»: picker
«Свой цвет» скрыт в Pulse у всех реализованных путей, включая ITE HID; handler
также отклоняет скрытую Pulse-команду. Mono сохраняет свой RGB picker. Размеры
карточки, brightness, effect buttons и scrollbar не меняются.

## Краткие сообщения INFO,25.10.2026

Уточнение владельца заменяет вывод технического журнала в окно. Общая модель
OperationMessages пропускает только значимые сообщения и типизирует их цвет:
обычный текст, Error красным(kError), Success зелёным(kOk). Начало — «Сбор данных
начался.», успешный итог — «Сбор данных завершён успешно.». Отмена/ошибка/ошибка
сохранения/неподтверждённый возврат FANs не дают зелёного успеха. Повторные
сообщения объединяются, timestamps/action/JSON в окно не выводятся.

Полные записи recordLog и сырые файлы читалок остаются прежними. Windows
использует цветовые диапазоны системного RichEdit, GTK — text-buffer tags;
сам scrollbar, ScrollModel/PageMechanics/scrolledWidget и геометрия не меняются.

## Окно сообщений INFO,25.10.2026

Операции INFO автоматически открывают отдельное окно сообщений780×440DIP:
сведения, EC, BIOS/VBIOS и установка драйвера там, где соответствующий action
реально поддерживается. Общая OperationMessages хранит всю историю и итог,
не зависит от ротации и AllLogs; background workers не трогают UI handles.
Закрытие во время операции запрашивает существующую безопасную отмену,
не завершает vendor reader/installer принудительно. Завершённое окно остаётся
открытым до закрытия пользователем. Другие команды продолжают свои guards.

Windows расширяет существующий MessageDialog: переносимый текст, выделение/
копирование, общие ScrollModel/page::scrollThumb/drawThumb/wheel. Press/drag
вынесены из существующего INFO в PageMechanics и переиспользованы; геометрия
карточек, их scroll и ширина не меняются. Linux использует прежний
scrolledWidget и тот же scrollbar/CSS, без отдельной полосы. Длинные пути
переносятся по символам. Обычное информационное/choice окно также расширено.

Linux collection теперь background task с отменой и безопасным временем жизни;
неподключённые BIOS/PawnIO действия остаются недоступны. Для WUJIE preview
числовой диапазон до255 согласован с Windows, нового аппаратного writer нет.

## Края всех карточек SETs,24.10.2026

контента и был сужен ещё на12DIP с обеих сторон. Теперь все четыре внешние

Поля/тексты редактора используют те же внутренние края. Вертикальные позиции,
высоты, нижние отступы и extent сохранены. Изменение в общей Geometry.h действует
для Windows/Linux и всех моделей; отдельные модельные UI не добавлены.
Точные размеры и запрет создавать пустое место под полосу записаны в коде и AGENTS.md.

вложенные рамки на7DPI,5ширинах, с Logger on/off и вариантами рядов/режимов.
Это проверка координат без запуска приложения/EC, не визуальное live-испытание.

Windows/Linux обновляют ссылки при смене профиля без замены inventory текущего ПК.

Windows: показ вкладок выполняется через PageMechanics::present после layout
и синхронизации UI. Общий place не вызывает немедленный repaint каждого HWND
и не перемещает неизменённые контролы. MainWindow сначала готовит/рисует новую

Меню языков/авторства/донатов и выбор модели в Windows также используют

## Установка PawnIO вместо проверки BIOS

На BIOS-вкладке первая строка сохраняет общую геометрию: «Обновить сведения»
и «Установить драйвер PawnIO». Windows по явному нажатию скачивает официальный
PawnIO.Setup2.2.0, сверяет точные размер/SHA256 и Authenticode, затем открывает
обычный мастер установки. Фоновой установки, silent/unrestricted параметров нет.
Подготовка идёт в worker, статусы — в существующей строке; запуск мастера
не объявляется завершённой установкой. Требуется завершить мастер и перезапустить
MagicControl. В просмотре чужой модели установка отключена.
Linux показывает ту же кнопку отключённой, с подписью, что PawnIO нужен Windows.
Системные драйверы Linux не устанавливаются. Ссылки поддержки/Nahimic сохранены.

## Intel + NVIDIA / GM6IR0C

MonitoringSnapshot передаёт vendor CPU/GPU и поля TjMax/VRAM. Общий
MonitoringCards::processorCard выбирает подписи по этим данным: Intel показывает
CPU/Package/TjMax, NVIDIA — NVML/VRAM, AMD сохраняет SoC/APU/NPU.
При отсутствии данных показывается прочерк с корректным источником. Дизайн,
геометрия, кнопки и скролл не создаются отдельно под производителя.
Windows на Intel не вызывает AMD ADL/ADLX, AMD SMN/SMU или AMD XRT NPU-опрос.
NVIDIA FANs и вкладка GPU используют один NVML-бэкенд и одно преобразование данных;
тахометры и PWM вентиляторов остаются за EC, не за NVML.
Intel Raptor Lake Windows: read-only IntelMSR/PawnIO для Package DTS и RAPL,
Windows ProcessorInformation для частоты, GetSystemTimes для загрузки. SETs
показывает измеренную Package мощность отдельно от EC PL1/PL2/PL4 overrides.
Linux использует Intel coretemp/RAPL и NVIDIA NVML при их реальной доступности.
Новые Intel/NVIDIA FANs показания требуют проверки на целевом ноутбуке.

Ревизия18.10: карточка памяти поддерживает физический адрес SPD/I2C вместо S/N,
если соответствие SMBIOS не установлено. Температуре не приписывается серийник
по порядку модулей. Геометрия и отрисовка остаются общими. GM Windows EC overrides=0
показываются «Авто» (штатная политика), не как0Вт; Linux без EC остаётся с прочерками.

## Диагностический дамп (19.10.2026)

В BIOS добавлена общая кнопка «Снять дамп», третья в верхнем ряду.
Геометрия biosHeaderGeometry и общий renderer/скролл сохранены на обеих ОС.
Пакет: logs/dumps/dump-UTC-counter/, уникальная папка без перезаписи старых.
Windows X5SP4NAG/GM6IR0C: EC RAM0x000–0xFFF, ec.bin + ec-valid.bin + ec.csv;
при ошибке остаток не выдаётся за нули EC. Linux/Honor/неизвестные модели пока
не имеют полного EC dump transport и получают явный статус, системную диагностику,
батарею и доступную NVIDIA NVML. Просмотр чужой известной модели отключает кнопку. NoName разрешает диагностический дамп текущего компьютера без активных проб вентиляторов.
Сохраняются report.txt, comment.txt для владельца, inventory.json, battery.json,
текущий session.jsonl, разрешённый список настроек и nvidia.json с ответами API.
Все данные — настоящего компьютера, не презентационного профиля.

По явному запросу пользователя dump включает краткие пробы вентиляторов:
EC Fan Boost на X5 через существующий FanController worker, GM через typed
Gm6Controller. Затем отдельная NVML100% проба только на реальном GM6IR0C
с единственной RTX4060 Laptop и читаемыми исходными fan policy/target.
Никаких команд «15000RPM»: задаются Max/100%, измеряется фактический пик.
Пробы ограничены12с, могут закончиться после стабилизации за≥4с, возвращают
исходное управление; при внешнем изменении не перезаписывают его старым снимком.
Закрытие страницы отменяет сбор и ждёт только аппаратный возврат через общий
hardware gate; медленный inventory/WMI может завершиться в отменённом worker.
Порог батареи, подсветка, мощность, напряжения и частоты пробами не меняются.

## NoName / Radeon / hybrid GPU (19.10.2026)

Четвёртая модель NoName — универсальный UI/fallback для неизвестного ноутбука,
без выдуманного EC-протокола. Ручной выбор другой модели сохраняет просмотр
без аппаратных записей. На настоящем неизвестном ноутбуке работают независимые
GPU API, EC-команды остаются отключены. NoName всегда показывает GPU NVIDIA и
GPU Radeon. Вне NoName видимость зависит от обнаруженной dGPU; GM preview
сохраняет статическую RTX4060. Шесть tab slots используют общую visibility mask,
скрытая NVIDIA не оставляет пустое место перед Radeon; размеры текста измеряются.

NVIDIA/Radeon используют одну DiscreteGpuPage на каждой ОС и общий
DiscreteGpuCard/geometry, NumericField/кнопки/скролл. Radeon Windows: ADLX Type
исключает iGPU из вкладки, metrics/VRAM/hotspot/fan RPM, Power Limit в процентах
с диапазоном/шагом/readback; default только через GetPowerLimitDefault,
не ResetToFactory всей GPU. ADLX инициализация общая с AMD APU мониторингом.
Linux: FUSION flag read-only AMDGPU_INFO_DEV_INFO для типа, amdgpu hwmon/sysfs
для metrics и power1_cap в ваттах при наличии диапазона и прав.

Hybrid: перечисляются все GPU, не только primary. Windows DXGI/DXCore дают
тип/driver/память. DXGI CurrentUsage — только память текущего процесса, отдельно
от общей VRAM; Linux boot_vga не объявляется выбором GPU рабочего стола.
Неизвестный тип не считается discrete по имени/VRAM. Неактивная карта остаётся
в inventory, недоступные датчики обозначаются прочерками и ошибками API.
Синтетическая графическая нагрузка не запускается.

Дамп: graphics.json — все Intel/AMD/NVIDIA, radeon.json — все AMD iGPU/dGPU.
Intel получает отдельные IGCL (Windows) / i915/xe hwmon/sysfs (Linux) readings
в intel.json и общем sensors.jsonl; статусы API и неизвестные значения явные. Автоматические Radeon setters/пробы при дампе не выполняются.

Подробный состав sensors.jsonl и ограничения источников: [DIAGNOSTIC-DUMPS.md](DIAGNOSTIC-DUMPS.md). Общий сборщик формирует одинаковую схему для обеих ОС.

на известном компьютере. Операции относятся к реальному компьютеру; такой просмотр
снимает только диагностические данные, без Max EC/NVML. Для чужих известных моделей
