## 1. Паспорт проекта

| Параметр | Значение |
|---|---|
| Тип | Кроссплатформенный control center ноутбуков |
| Стек | C++20, CMake, Win32/GDI + GTK4, без Qt |
| Цели | FANs/кривые, телеметрия, battery limit, RGB/zones, KEYs, OSD, BIOS dump, обновления |
| Модели | 16 в каталоге: **5 full + 1 battery-only + 10 inventory** |
| Платформы | Windows (основной) + Linux (GUI есть, EC write off) |
| Релизы | portable + VERIFICATION JSON, единый Build-All.ps1 |
| LOC (оценка) | platform ~14k, gui ~17k, core ~5k, devices ~5k, protocols ~2k; third_party ADL/ADLX/IGCL ~20k |
| Гиганты | SettingsPage.cpp ~164KB, FansPage ~116KB, gm6 ControlWindows ~121KB, FanControlWindows X5 ~110KB |

## 2. Архитектура — оценка

```
gui/{common,windows,linux}  →  core (EcAccess, DeviceProfile, Battery*, Fan*)
                                ↓
devices/<vendor>/<board>    →  capabilities + writers
                                ↓
platform/{windows,linux}    →  uniwill-acpi, pawnio, battery class, ADL/ADLX
protocols/uniwill|huawei    →  codec/register maps per family
```

**Сильно:**
- Разделение core / devices / platform / protocols
- `DeviceProfile` + `ensureCapability(feature, protocolId)` перед записью
- Evidence-подход (D0–D3, Факт/Код/Кандидат/Инвентаризация)
- Единый UI-mechanic (AGENTS: одна реализация скролла/контролов)
- Межпроцессный gate EC: `Global\MagicControl.EcTransactions.v2` (закрыл A01 из PROJECT-AUDIT)

**Слабо / рискованно:**
- Несколько **огромных** cpp (SettingsPage, FansPage, device ControlWindows) — сложность ревью и merge
- GUI Windows живёт без симметричного Linux write-path
- third_party SDK в git-дереве (лицензии ADL/ADLX уже лежат — хорошо, но шум в LOC)

Это правильно для науки, но в UI пользователь может понять «лимит включён» как факт остановки зарядки. **Рекомендация:** явный статус `configured / readback / physical-unverified`. |
