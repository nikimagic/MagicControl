# Журнал действий всех моделей

Фоновые снимки FANs/SETs/GPU, typed LaptopControl и NVML: изменения режимов,
управляющих значений, статуса, ошибок и доступности записываются сразу;
изменения измерений и времени опроса объединяются в снимок не чаще 10 секунд.
Внутри активного действия снимки по-прежнему записываются сразу. Правило общее
для всех профилей и неизвестных устройств на Windows и Linux. Счётчики и сырые
управляющие регистры не маскируются. Если снимок не удалось разобрать, действует
прежнее сравнение полного текста. В Windows краткое отсутствие доступа EC в
одном из сборщиков не записывается как переход при работающем втором сборщике;
непрерывная недоступность после 5 секунд и восстановление видны в журнале.
Независимые наблюдатели карточки FANs сравнивают каждый собственные снимки;
`observer_id` различает их внутри запуска и не содержит адресов памяти.
Измеряемые регистры батареи входят в 10-секундные/SOC снимки без дублирования
в CHANGED; смены доступности и ошибки остаются отдельными событиями.

Дополнение24.10.2026: `FANs.presentation`, `SETs.presentation` и GPU page пишут
реальное выбранное UI состояние отдельно от raw cooling/processors snapshot.
Windows MC.Selected/GTK primary включены в control snapshots. Сохранённые
значения отмечены retained/stale с исходными timestamps. SingleZone result
содержит полный7C5. Queued/UI callback outcome не выдаётся за hardware ACK.
Общая политика: [DATA-CONTINUITY.md](DATA-CONTINUITY.md).

24.10.2026. Общая реализация Windows/Linux, без отдельного логгера на модель.

## Где искать

При включённом AllLogs действия попадают в существующий `MagicControl-N.jsonl`.
Остаются ровно три пары с `battery-N.jsonl`, весь запуск в одном файле, без
`.part`. Переключатели AllLogs/BatteryLog сохраняют прежний смысл. История
`rom_id` независима и не ротируется. Старые файлы не переписываются.

Каждая новая обычная запись содержит `app_version`, `actual_board`,
`actual_profile`, UTC, session, seq и `action_id` либо null. Фактическая плата
берётся из OS SMBIOS; выбор модели в preview записывается отдельным событием
и не подменяет аппаратную идентичность.

## Цепочка

- `ui`: кнопка/меню/вкладка/выбор модели, ID, подпись и параметры GUI.
- `command_requested`: команда и запрошенные значения.
- `state_observed`: уже полученный снимок, а не дополнительное чтение железа.
- Ответы EC/ACPI/HWMI/sysfs/PawnIO/HID/BLE с доступными сырыми данными.
- `command_result`: результат, время, ошибка либо подтверждение чтением.
- Отказы busy/preview/unsupported сохраняются; завершение GUI dispatch не
  считается завершением аппаратной команды. DeviceOperation/worker/очередь
  переносят action_id для связанных действий.

`readback_confirmed` означает совпадение существующего контрольного чтения.
`transport_returned`/`transport_accepted` означает только возврат транспорта.
`returned_unconfirmed` означает отсутствие явно опубликованного результата.
`exception_escaped` означает выход исключением, подробная ошибка сохраняется
на обрабатывающем уровне. `physical_response_measured=false` не позволяет
объявлять свет, скорость вентилятора или мощность измеренными по одному ACK.
Независимые сообщения/телеметрия могут иметь action_id=null.

## Покрытие

| Путь | Данные |
|---|---|
| Общий UI Windows | Native кнопки, numeric step/commit, combo, slider; состояния native контролов до/после; нарисованные KEYs, шапка, меню, диалоги |
| Общий UI GTK | Shared actionButton, tagged numeric/check controls, меню/модель/вкладка; состояния и результат callback |
| Wujie/GM SingleZone | Уровень/эффект/pulse/RGB, полные уже прочитанные78C/767/7C5, маски/strobe, before/after, rollback |
| EC-профили GM/Wujie | Чтения внутри команды, все записи, requested/before/readback, backend, ошибка; FAN параметры и очереди; GM native profile/PL/индикация |
| Honor/Huawei | Typed LaptopControl request/state/error; HWMI command/response; существующий I2EC/PawnIO; Linux sysfs read/write |
| HYDROC HID | Зона и конфигурация отдельно, VID/PID, полный feature frame, firmware response; сохранённая конфигурация отдельно от неизвестного физического RGB |
| HYDROC LPP | BLE исходящие кадры/уведомления и transport outcome; физическая работа помпы не выводится из GATT success |
| CPU/GPU/KEYs/INFO | UI параметры, общий EC путь, NVML коды и limit readback, микрофон/system device setter, результат сборщика дампа/инвентаря |
| Catalogue/Unknown/preview | Те же UI события и доступность; отсутствие backend не создаёт неподтверждённое управление |

Все16 моделей используют общие UI hooks и metadata. Детальность аппаратных
ответов соответствует существующему backend: неподключённая модель не получает
придуманную телеметрию. Неизменные фоновые снимки подавляются; внутри активной
команды снимок сохраняется даже при совпадении. Потоковые подсветка/online
изменения могут заметно увеличить журнал при включённом AllLogs.

## Границы реализации

Не добавлены hardware probes, частый таймер, новые команды или readback только
ради журнала. Существующая burst-policy Windows сохранена для прежних кнопок
и numeric step; новые edit/combo/slider события её не запускают. GUI snapshots
читают только собственные контролы; поля пароля исключены. Схема аппаратного
управления, допуски моделей, startup/resume/rollback и геометрия UI сохранены.

Компиляция и сверка portable не являются проверкой runtime/железа. Помощник
не запускал GUI, диагностический helper, EC/BIOS операции или аппаратные тесты.
