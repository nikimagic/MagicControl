## 2. Сильные стороны (теперь ещё сильнее)

### A. Resource model — реализован честно
- `ResourceCatalog`: observation **не** даёт write admission  
- `ResourceEvidence`, `ResourceTimestampOrigin`, `unsignedValue` (без double)  
- `ResourceProjectionCheck::verified()` = «были сравнения и нет mismatch»  
- Live monitoring → **authoritative ResourceState**; shadow в `archive/resource-shadow-0.1.384`  
- Тесты: DTO-изменения не тянут отображение, clear() без fallback, NaN fixture  

### B. Control routing — единые входы
`CONTROL-RESOURCE-ENTRYPOINTS.md` + `ResourceControlTable`:

| Домен | Общий вход |
|---|---|
| Battery | `executeBatteryResource` |
| Charge pair | `writeChargePairResource` |
| Power/Custom | `executePowerResource` |
| RGB / HID zones | `applyLighting` / `executeSettingsAction` |
| KEYs / INFO / FAN | resource dispatch GUI=CLI |

Правила в коде: ключ ≠ разрешение; **fallback-маршрута нет**; чужой backend не наследуется по имени.

### C. Architecture audit (build-time)
`architecture_audit.cmake`:  
- один определение write-функции  
- запрет прямых write в GUI/CLI  
- запрет raw battery setters в `ConfigurationRestoreWindows` (закрыт **P-разрыв 0.1.387**)  

Это **не** hardware-check, но сильный структурный гейт.

### D. SETs / Coordinator — серьёзная работа
- `SettingsOperationCoordinator`: admit / enqueue / launch / finish, passive vs interactive  
- `test_settings_queue_windows.cpp` **~115 KB** — крупнейший тест  
- 0.1.382–384: worker из страницы в сервис  
- LINUX worker/queue/sleep dbus тесты  

### E. KEYs — упрощение
- Удалён software **CopilotKeyBlocker**; один аппаратный путь (`copilot-lock`)  
- `KeysLifecycle` + `keys-settings.ini`; BT/OSD/Copilot не auto-restore  
- Hardware-подтверждение Copilot на Wujie 28.10 (натурный прогон)  

### F. Honor / multi-model
- Сериализация charge transactions, HWMI gate тесты, sysfs fixtures  
- Не размазаны модели по общему маршруту  

### G. Документация — опережает код
PERIODIC-READS, KEYS-PERSISTENCE, ARCHITECTURE-WORKLIST, CONTROL-RESOURCE-ENTRYPOINTS, BATTERY-RESTORE-DISPATCH, CONTROL-CUTOVER, RESOURCE-ARCHITECTURE-PLAN.
