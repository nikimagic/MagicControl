# Исправление переключений вентиляторов — 13.10.2026

## Причина регрессии

В предыдущем изменении добавлено определение пробуждения по интервалу между началами циклов контроллера: более 10 секунд считалось потерей управления после сна. Реальная запись таблиц EC и проверка PWM/RPM на этом ноутбуке сама занимает более 10 секунд. В результате обычное нажатие Min запускало восстановление предыдущего подтверждённого Max.

Доказательство: `MagicControl/windows/logs/MagicControl-2.jsonl`, сессия PID 14844:

- `15:33:24Z`: выбран Max, фактически подтверждены 100% обоих каналов.
- `15:33:29Z`: нажат Min; установлен целевой PWM 10%.
- `15:33:39Z`: CPU фактически 10%, GPU ещё 21%, идёт снижение оборотов.
- `15:33:40Z`: началось ложное восстановление после питания.
- `15:33:51Z`: восстановлен старый Max; цель снова 100%.

В этом интервале журнал не содержит событий `windows_power_event`. Ошибка вызвана логикой приложения.

## Изменения

1. Удалено определение сна по длительности цикла. Восстановление вызывается только событиями пробуждения и подтверждённой сменой AC/DC. Обычное обновление статуса батареи не перезапускает вентиляторы.
2. При начале изменения EC новым режимом старое подтверждённое намерение снимается. Ожидание PWM нового Min/Manual больше не позволяет воспроизвести прежний Max.
3. Блокировка переключений удерживается до завершения применения EC. Физическое изменение оборотов отображается отдельно и не блокирует Default, Manual, Min и Max на десятки секунд.
4. Готовность состояния публикуется под той же блокировкой, под которой освобождается переключение. Следующее нажатие не получает старый признак «применяется».

Default передаёт оба канала прошивке; Max включает общий Fan Boost; Manual и Min применяют соответствующие сохранённые кривые. Подтверждение фактических PWM/RPM и защита при 85 °C сохранены.

## Проверка

`tests/test_fan_buttons_windows.cpp` создаёт настоящую Windows-вкладку FANs. EC и мониторинг заменены имитаторами, поэтому тест не управляет аппаратурой. Через `WM_COMMAND` проверяются все 16 упорядоченных пар четырёх кнопок на каждой из двух строк CPU/GPU — всего 32 пары.

Дополнительные сценарии: цикл более 11 секунд; задержка фактического PWM после Max → Min; доступность Default во время снижения оборотов; настоящее событие сна при неподтверждённом Min, которое не должно возвращать старый Max. Файл профилей тестового исполняемого файла сохраняется и восстанавливается; пользовательский портативный конфиг не меняется.

Итог: тест всех 32 пар, дополнительный медленный сценарий, общие тесты fan/performance и тест FANs DPI прошли без ошибок. Реальные физические переходы этой новой сборкой ещё не подтверждены; предыдущий сбой установлен по аппаратным журналам.
