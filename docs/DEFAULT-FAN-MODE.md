## Состояние вентиляторов в дампе

| Адрес | Маска | Значение поля | Назначение |
|---|---|---|---|
| `0x7C6` | `0x04` | `0` | RAM-управление выключено |
| `0x741` | `0x01` | `0` | Присутствие приложения; отдельный срок жизни APExist |
| `0x727` | `0x40` | `0` | Пользовательский профиль выключен |
| `0x726` | `0x80` | `0` | Ручной контекст выключен |
| `0x7C5` | `0x80` | `0` | Общий аппаратный режим EC |

Все 96 байтов `0xF00–0xF5F` равны `0`; байтов `255` в этом диапазоне нет.
Здесь нет численной штатной кривой для графика: охлаждением управляет прошивка.
`255` в логическом редакторе MagicControl остаётся маркером незаданной точки.
Флаг APExist не включает RAM-кривые; в работающем эталонном приложении он может
быть установлен отдельно для обслуживания специальных клавиш.

## Проверенный максимум вентиляторов

Fan Boost определяется битом 6 регистра `0x751`, маска `0x40`. Остальные биты
этого байта относятся к режиму производительности и сохраняют отдельный смысл.
Источник декодирования — `Fan_X15Pro\EcPerformanceMode.cs`.

В `Diagnostics\FanControl\fan-maximum-verified-20260930-200746.json`
аппаратная проверка зафиксировала `0x751 = 0x40`, CPU PWM 100% и три отсчёта
CPU RPM: 5989, 5956, 5940. Источник чтения: `ACPIDriverDll.dll`, адреса
`0x464`, `0x465`, `0x75B`. Эти три отсчёта относятся к CPU-вентилятору.
В дампе после перезагрузки 05.10 `0x751 = 0xA0`, Fan Boost выключен.

MagicControl читает этот флаг вместе с режимом EC. Включённый Fan Boost не
считается активным Default или применённой Min/Manual RAM-кривой. В текущем
редакторе Max показывает постоянные 100% и в Windows включает аппаратный Fan Boost.

## CPU=GPU и аппаратное разделение

В эталоне CPU=GPU связывает программные кривые: используется большая из температур
CPU/GPU и одинаковая команда для обоих каналов. При активном программном управлении
эталон включает аппаратное разделение EC, чтобы оба канала принимали команды.

Фактический аппаратный режим всегда читается отдельно: `0x7C5 & 0x80 == 0` означает
общий режим, ненулевое значение — раздельный. Он не определяется надписью CPU=GPU.
Даже в общем штатном режиме фактические RPM/PWM двух вентиляторов могут различаться.

В эталонном `EcFanCurveController.cs` (комментарий к сессии
`native-20261002-014348-142`) зафиксировано, что аппаратный общий режим не исполнил
запрос RAM PWM 10%. Поэтому программная связь не сбрасывает `0x7C5.7`: он остаётся
равным 1 и при CPU=GPU, и при CPU≠GPU. Равенство команд обеспечивается вычислением
одного PWM по большей температуре. Сброс физического разделения нельзя считать
применением общей программной кривой.

В текущем интерфейсе MagicControl переключатель меняет и сохраняет связь редакторов
и активное управление Windows. Независимая GPU-кривая сохраняется и возвращается
в редактор при развязывании. В графике Default показано «управление прошивкой EC».
При переключении работающих кривых Default не вызывается, RAM-таблицы не очищаются.
Если активная RAM осталась от прежней сессии без управляемых текущим контроллером
логических точек, сначала требуется Min или Manual; флаг общего режима не сбрасывается
поверх такого управления.

## Применение кривых в Windows

`FanControlWindows.cpp` переносит `EncodeOutput`, `SelectLevel` и последовательность
активации из `Fan_X15Pro\EcFanCurveController.cs`. Контроллер получает собственные
свежие температуры из тех же источников, что и UI: CPU PawnIO Tctl/Tdie (резерв —
AMD ADL CPU), GPU AMD ADL GFX/Edge. Выбирает PWM с гистерезисом и обновляет первые шесть
CPU-duty / все 16 GPU-duty. Аварийная ступень CPU из эталона сохраняется, при
температуре ≥85 °C программно выбираются 100% на управляемых каналах.

Перед записью сохраняются 96 байтов RAM и управляющие поля. Владелец использует
те же CPU/GPU mutex, что эталон, и временно останавливает GCUBridge. Запись и
чтение сериализованы общим EcAccess; несвязанные биты подсветки и питания
сохраняются. На старте программы, после пробуждения и смены AC/DC общий
восстановитель применяет сохранённые настройки SETs/KEYs, затем выбранные
профили из `fan-curves.csv`. Автоподхват требует свежих температур и проверяет
фактические PWM/RPM; выбранная кнопка не считается доказательством применения.

При закрытии, Default, отсутствии температуры или ошибке выход возвращается
прошивке; Fan Boost выключается по маске 0x40, режим мощности сохраняется.
При внешнем изменении EC контроллер прекращает запись. Служба возвращается в
исходное состояние, тип запуска не изменяется. В программе подсветка пробуждается
по активности ввода с повторным чтением текущей яркости, без сохранения кодов клавиш.

Состояние «применена» для программной кривой требует совпадения с применёнными
логическими точками и фактических PWM/RPM; сохранения конфига для этого недостаточно.
Блокировка кнопок действует во время применения EC, а ожидание физических оборотов
не запрещает новое переключение. Долгий цикл EC не считается признаком сна:
восстановление запускается только при пробуждении или подтверждённой смене AC/DC.
Новые аппаратные измерения этим описанием не заявляются: перенос собран из
проверенного эталонного алгоритма, фактическое применение записывается в
`fan-control.log` после нажатия пользователем.
