# Lenovo Legion KWCN

## Диагностика совместной мощности CPU/GPU, 02.11.2026

При включённом общем журнале существующий Windows collector для точного
KWCN54WW записывает power.sample раз в 10 секунд при высокой мощности GPU и
раз в 60 секунд при низкой или недоступной мощности. Вход/выход нагрузки
имеют гистерезис 105/95 Вт и минимальный интервал 5 секунд; в штатной короткой
диагностической серии запись чаще. Это частота записи;
аппаратные источники обычно обновляются раз в 10 с и имеют свои timestamps.
Переход обнаруживается при следующем опросе GPU; короткий пик может пройти
между опросами, особенно когда окно FANs скрыто.
Рядом с CPU/GPU и Windows power flags публикуются отдельно MSR
606/610/613 и MMIO 59A0/59A4: сырые значения, лимиты, enable/clamp, окна и
раздельные timestamps. Пересчёт в ватты/секунды использует единицы из 606;
без них значение неизвестно. MSR 613 — накопительный счётчик, не текущая
причина ограничения. Записи не выполняются; невключённый лимит не считается
действующим. Другие контроллеры могут ограничивать мощность ниже.

Под существующим I2EC owner дополнительно читаются кандидатные C5E0/E1/E3/FB/FF
и C41D, а также кандидатные C4A3/C439/C22F/C2A7/C2DE-DF/C450-451/C93F/C930-933
для разбора адаптера с повторным сравнением, отдельно от FAN snapshot. C5FB.7 — кандидат
соответствия ACPI F9FB, но не подтверждённый прямым MMIO cross-check; C5FF.4
и C41D.0 трактуются аналогично. Источники и timestamps раздельные, общий снимок
не атомарен; результаты не используются для управления. Ошибка диагностики
не должна отменять нормальное наблюдение вентиляторов. Длительная запись
использует имеющуюся ротацию логов, без бесконечного 1-секундного burst.
I2EC чтение использует записи в адресные селекторы; данные EC RAM не записываются.
`candidate_acty` вычисляется по BIOS ACTY из доступных C4A3/C439/C41D; это
класс питания, а не измеренная мощность или подтверждённый тип разъёма.
На клиентском Lenovo аппаратная работа новой диагностики не проверена.

Номинал адаптера для карточки — отдельный предварительный EC candidate, не
потребление от сети и не подтверждение разъёма. Только при согласованных
повторных чтениях C450 (LE), C22F, C2A7, C4A3 и точном совпадении таблицы
class4/5/6/7/8 → 135/170/230/300/330 показывается «БП EC ≈ … Вт»;
иначе мощность неизвестна. Записи в EC RAM не выполняются. В прежних дампах
class7/C450=300, но свежий лог 0.1.466 эти байты не содержит. Другая ветка
EC копирует C93F, полученный вычислением из C930/C932; её единицы и источник
ещё не установлены. DC/USB-C и форма разъёма из этого не выводятся.

## CPU temperature WMI readback, 02.11.2026

KWCN54WW `01040000` задаёт F5E2 как `100 - request`. Ветка `offset==100`
заменяет его на3 только для запроса 0°C, а не для запроса 100°C. Поэтому
запрос100 должен проверяться обычным readback100; старое ожидание97 удалено.
Диапазон остаётся тем, который сообщает WMI данного устройства. Статический
разбор ASL не является аппаратным подтверждением установки100°C.

## Lenovo: RPM и сырые PWM, 02.11.2026

Controller читает текущие обороты `C406/C4FE` и сырые зеркала PWM
`DFE1/DFE2` в одном существующем пассивном FAN-снимке. Сырые байты
публикуются через общие диагностические сенсоры с обозначением `raw` и
временем наблюдения. Шкала для перевода в duty% не подтверждена: опорный
регистр периода находится за пределами доступного SRAM-окна. Поэтому PWM%
остаётся неизвестным. Отношение оборотов к WMI nominal max применяется только
к графику RPM и не подставляется в измеренный PWM. Команды FAN и кривые не
менялись. По сохранённому SKU 82WK подтверждены все девять WMI-полей Custom;
лимиты и диапазоны по-прежнему читаются непосредственно из WMI firmware.
Физическая работа изменения на устройстве ещё не проверена.

## Текущий статус: Max через штатный Full Speed

02.11.2026: Maximum использует существующий executeFanResource и тот же Controller,
как Wujie Boost. NativeFixedFans::setMaximum у Lenovo меняет только штатный
WMI feature04020000/FNST; чтение до/после допускает только0/1. Прежний Max через
setFixed(100) и перекодирование Manual больше не вызывается. Переданные profiles
в запросе Maximum игнорируются как аппаратная кривая, включая startup/resume.
Остальные модели сохраняют свои прежние fixed PWM/RPM и Uniwill Boost команды.

Настройки, пресеты и Manual draft/пакет при Max не переписываются. Mode2 в
снимке означает прочитанный FNST, а не старый kind2 lease с RAM-пакетом100%.
Default и Manual снимают FNST; возврат к уже применённой той же кривой не
записывает FAN RAM. После смены мощности при Max новый OEM map лишь фиксируется
в прежнем ownership journal, аппаратная индирекция откладывается до Manual.
Старые форматы файлов принимаются. Ошибка WMI/флага не включает fallback на RAM.

Условия Full Speed из прошивки сохраняются: флаг не обходит Custom gate,
нагрузочные/питающие условия EC. Приложение не переключает CPU mode ради Max.
Подтверждение флага и фактический разгон RPM — разные результаты, они отдельно
видны в статусе и Max-пробе. Проверки только offline; реальный запуск не выполнялся.

Дамп снова использует обычный Default → RAM8КиБ → Max30с → Default → прежний
режим через те же resource entries, без отдельного диагностического writer.
ReadOnly исключает все переключения. Новый epoch не позволяет cleanup старой
пробы сбросить более свежую команду. EC raw/valid сохраняются атомарно с flush
до производных таблиц/ACPI/Max; сохранение отмечается ec_snapshot_saved.

## История инцидента0.1.441 и отменённого общего запрета

Реальный архив `logs_LNVNB161216 (4).zip`,0.1.441: EC RAM8192/8192 прочитана
за8,027с; Default подтверждён. В23:38:51,600МСК начат `mode.maximum`, через
269мс подтверждены RAM-байты. До последней сохранённой телеметрии23:39:03,558
обороты оставались1700/1700RPM, CPU около45–49°C, GPU около40°C. Нет результата
Max/cleanup/restore, пользователь сообщает о выключении и сбросе настроек
Vantage/LLT. Аппаратный механизм выключения и изменение их файлов не доказаны.
В этом проходе дампа EC MagicControl не запускал FPT/H2OFFT.
Путь Max был `mode.maximum → setFixed({100,100}) → setCurves`: все точки
нашей Manual-кривой становились100%. Это не отдельный штатный FullSpeed setter;
совпадение RAM-пакета в этом пути не подтвердило изменения оборотов.

В0.1.442 был добавлен общий запрет FAN-записей. Владелец отклонил это ограничение:
оно снято, три файла реализации Controller/I2EC/codec возвращены побайтно к0.1.441.
Default/Manual/Min/Max, общий Custom и lifecycle сохраняют один прежний writer,
identity/ownership/readback/rollback, не получают обходную реализацию.
Профили/черновики/пресеты/lease сохраняются. Это отмена общего запрета, а не
подтверждение исправности аппаратного Max или совместимости с Vantage/LLT.

В0.1.443 collector принудительно был ReadOnly по фактическому профилю, даже
при `--probes`; это временное ограничение заменено текущим контрактом выше.
Остальные устройства сохраняют прежние режимы/проверки. Штатные WMI power
methods здесь не изменены; конкуренция Vantage/LLT остаётся гипотезой, не
объяснением, на которое можно переложить наш неподтверждённый FAN writer.

Автоматического отключения/заморозки Vantage/LLT не добавлено. По поручению
владельца их штатный механизм передачи управления исследуется отдельно;
службы/драйверы клиента не останавливались, повторного аппаратного опыта нет.

Профиль: точные LENOVO / LNVNB161216 / 82WK или82WQ. Запись Windows дополнительно
требует фактический KWCN54WW. Маркетинговое имя не заменяет сообщённый код SKU.

GUI/CLI/ConfigurationRestore используют существующие executePowerResource и
executeFanResource, общие Custom1/2/3 и16-ячеечное хранение. Один Controller
владеет WMI и FAN-транзакциями. Активны10 точек CPU=GPU:8+2, без ресэмплирования.
Значение255 в файлах приложения обозначает пустую точку; Manual и Custom
пропускают её при кодировании. Для завершающей аппаратной строки кодировщик
использует127, как в исследованной штатной таблице EC; остальные неактивные
поля исходной таблицы сохраняются. Это не разрешение вводить127°C в редактор.
Manual online для Lenovo не подключён и не имеет собственного кодировщика.
Default показывает действующую SRAM-таблицу и управляющий температурный вход.
Input bounds прежние:20–100°C и5–100% включительно. RPM кодируются по WMI-лестницам;
проценты RPM не объявляются аппаратным PWM.

Custom: Cross Loading / PL1 / PL2, GPU Power Offset / cTGP / Dynamic Boost,
PL1 Tau и температурные пределы CPU/GPU. SKU-зависимые диапазоны, writable flags,
шаги и дискретные значения читаются из фактических WMI GUID/schema/capability rows.
Перед записью они обновляются. Имена/единицы объявлены отдельно как данные профиля:
все девять полей видны также в preview, где показания«—» и запись запрещена.
Старая библиотека пресетовv1–v4 читается; дополнительные значения сохраняютсяv5.

FAN admission: физический5507, S0, ISA mutex, WMI/EC sensor alias, принадлежность
таблицы и56 отпечатков разобранных factory-вариантов. Разрешена только проверенная
SRAM-таблица/служебные поля; целые пакеты подтверждаются readback. Apply и Default
имеют журнал префикса. ROM-loader удерживается, firmware governor работает.
Custom использует индирекцию1..10; исходные байты сохраняются для восстановления,
включая неактивные sentinels. Flash, GPIO/PWM и соседние Cross Loading поля не пишутся.

Канонические файлы в settings: lenovo-legion-kwcn-fan-profiles.csv,
lenovo-legion-kwcn-power.ini, lenovo-legion-kwcn-fan-lease.txt и общая библиотека
lenovo-legion-kwcn-custom-presets.txt. Legacy root files мигрируют через прежний
механизм без удаления личных данных. Startup/resume идут через те же resource entries.

INFO: SRAM8КиБ C000–DFFF, valid mask, исходные FAN-строки, WMI-таблицы и текущие
лимиты. Это RAM, не live256КиБ flash EC. Max использует общий30-секундный сборщик,
cleanup Default и одноразовый возврат подтверждённого режима. Новая команда,
питание/режим или чужое владение отменяют старый replay; CPU/батарея не сбрасываются.
BIOS/VBIOS используют существующие общие readers с проверками совместимости,
полноты и двух копий. Ссылки поддержки выбираются по82WK/82WQ.

Новый управляющий транспорт — Windows. Linux распознаёт профиль и схему, но
не заимствует Windows WMI/PawnIO writer. Kernel WMI/LenovoLegionLinux остаются
отдельными кандидатами. Протокол, сохранение, отказы и startup/resume проверяются
подставными данными; физическая работа на Lenovo ещё не подтверждена.

Исследования: research/it5507-legion-nmf081-20261101 и
research/legion-gamingfeature-full-20261101. Декомпил драйверного пакета и Intel
XTU SDK не объявляется декомпиляцией самого приложения Vantage/Legion Zone.

## Исправления по реальному логу0.1.435

WMI property names сопоставляются без учёта регистра. При отсутствии перенесённого
WmiDataId2 используется штатное поле Capability из проверенного по GUID класса;
значение не подставляется и readonly-флаги не превращаются в writable.
Factory admission сравнивает отдельные столбцы: E63C сначала очищает SRAM, затем
копирует только включённые fan/sensor columns. Отключённые столбцы обязаны быть
нулевыми. Реальная таблица descriptor6/count11/sensor-mask7 включена в offline
проверку без полного приватного RAM-снимка. Успешные портовые обмены Lenovo не
пишутся каждый отдельной парой событий; ошибки транспорта и resource results остаются.
