# MagicControl — спецификация интерфейса

Источник: скриншоты работающего C#-приложения `MECHREVO` (Fan_X15Pro), 5 экранов.
Назначение файла: техзадание на UI MagicControl. Всё, что помечено `[?]`, требует
уточнения по коду `Form1.Designer.cs` / `UiText.cs` — снимок не даёт точного значения.

Текущая база для Linux — Windows MagicControl. Общие вычисления геометрии находятся
в `src/gui/common/Geometry.h`, константы — в `Layout.h`, роли и размеры шрифтов —
в `Fonts.h`, цвета — в `Theme.h`. Обе GUI используют этот модуль при компиляции.
Семейства системные: Segoe UI в Windows, GtkSettings в Linux; высоты строк и
области текста согласованы с Windows. Полного совпадения формы букв это не даёт.
Расчёты выполняются с учётом DPI, GTK переводит их в логические координаты своих
штатных контролов. Отдельные значения из исторического описания ниже могут
отличаться от действующего общего модуля.

### Выпадающая панель `MECHREVO ▾`

Две секции.

**Язык** — плоские пункты, выбранный с галочкой:
`Автоматически · Русский` (показывает определённый язык), `Русский`, `English`, `简体中文`, `繁體中文`.
Раскладка — в две колонки, как в снимке: Русский | English, затем 简体中文 | 繁體中文.

**Ноутбук** — прокручиваемый список моделей:
- Обнаруженная модель сверху, обычным шрифтом, с галочкой (`WuJie 15X Pro`).
- Все остальные серые и **недоступны** — выбора и применения профиля нет. Это осознанное
  решение: неизвестной плате профиль не выдаётся.
- Список: CangLong 16 Pro, CangLong 16 Pro 2026, CangLong 16 Ultra, CangLong 16X Pro,
  CangLong 18 Pro, Code 01, Code 10, Code 10 AI, Code GG … (всего 178 моделей).
- Прокрутка: колесо над любой строкой, ползунок справа, клавиши ↑/↓, Page Up/Down, Home/End.
- Максимальная высота ~420 px при 100 % масштабе, с учётом DPI и свободного места.
- Escape и клик вне панели закрывают её; действия с ползунком панель не закрывают.
- Отрисовываются только видимые строки.

## 2. Вкладка FANs

Самая насыщенная. Сверху вниз.

### 2.1 Карточки CPU и GPU

Две карточки в ряд, равной ширины. Внутри — три колонки крупных значений и блок
мелких подписей под ними.

| | CPU | GPU |
|---|---|---|
| Заголовок | `CPU` | `GPU` |
| Крупное значение 1 | `914` — подпись `об/мин` | `932` — подпись `об/мин` |
| Крупное значение 2 | `10 %` — подпись `PWM` | `10 %` — подпись `PWM` |
| Крупное значение 3 | `35,1 °C` — подпись `Температура` / `PawnIO · Tctl/Tdie`; резерв `AMD ADL · CPU` | `35 °C` — подпись `Температура` / `AMD ADL · GFX` или `Edge` |
| Доп. ячейка | `SoC 36 °C`, подпись `AMD ADL · SoC` | `NPU 0 %`, частота и мощность, затем их источники |

Под каждым из трёх показателей отдельная строка источника. Для оборотов и PWM
в Windows это `UWACPIDriver.sys · EC`; для температуры — источник датчика.
Подписи, источники и строки нижнего блока используют одинаковый шрифт 8 pt.
Три колонки равной ширины: число с единицей, подпись и источник центрируются
в своей колонке. Основные цифры — 16 pt, SoC/NPU — 11 pt; группа SoC/NPU и её
строки источников центрируются в дополнительной ячейке.
Подписи SoC/NPU и единицы выровнены по базовой линии значения. Минимальная высота
карточки — 164 логических пикселя; при переносах нижнего текста высота увеличивается.
В строке загрузки, частоты и мощности значения с единицами белые; названия и
разделители сохраняют приглушённый цвет. При переносе значение остаётся со своей единицей.

Блок подписей под крупными значениями (мелкий шрифт, построчно):

CPU:
```
Загрузка 5,4% · 1 493 MHz · CPU 26,60 Вт
Загрузка: AMD ADLX · Частота: AMD ADL
Мощность: PawnIO / CPU core energy
```

В ячейке SoC показываются температура, общая мощность APU и оба источника:
```
SoC 35 °C
APU 32,70 Вт
AMD ADL · PawnIO
```
Подписи `APU` и `Вт` остаются на месте при пропуске чтения; пока нет первого
значения показывается прочерк, затем сохраняется последнее успешно прочитанное.

GPU:
```
Загрузка 99% · 2 898 MHz · GPU 28,50 Вт
Загрузка / частота: AMD ADL
Мощность: AMD ADL · GFX
```

Ключевая мысль: приложение **всегда печатает источник каждой цифры**. Это нужно
сохранить — при переносе на Linux подписи станут другими (`ec_sys`, `hwmon`,
`k10temp`, `amdgpu`), и пользователь должен видеть, откуда взято число.

### 2.2 Полоса мониторинга (5 карточек в ряд)

| Карточка | Содержимое | Пример |
|---|---|---|
| Батарея | процент, затем ток разрядки, затем источник | `71 %` / `Разрядка · 8,6 Вт` / `Windows · Battery IOCTL` |
| Память 1 | температура, `S/N`, источник | `39 °C` / `S/N: EAFFFBE7` / `PawnIO · SMBus 0x50` |
| Память 2 | то же | `39 °C` / `S/N: EAFFFBE2` / `PawnIO · SMBus 0x51` |
| Диск 1 | температура, модель, тип | `41 °C` / `RU-P538-1TB` / `Windows · NVMe` |
| Диск 2 | прочерк, если не установлен | `— °C` / `Не установлен` / `Windows · накопители` |

### 2.3 Графики кривых (две штуки, CPU и GPU)

- Заголовок: `CPU вентилятор` / `GPU вентилятор`.
- Ось Y слева — `PWM, %`, шкала 0…100, подпись сверху.
- Ось X — температура 20…100, подписи 20 / 40 / 60 / 80 / 100; `°C` справа от 100.
- Шапка графика уплотнена на 10 логических пикселей; поле графика ниже на 20%.
  Процент применяется после DPI-масштабирования с округлением до целого пикселя.
- Сетка — тонкие линии по каждому делению, 25 % по вертикали.
- Кривая — **ступенчатая** (не сглаженная): между точками значение держится, затем скачок.
- Маркер текущего состояния — белая точка на кривой + подпись под графиком:
  `— Кривая` (цвет линии) и `Факт: 35 °C · 10%`.

### 2.4 Таблица точек кривой

Две строки, 8 колонок на страницу, всего 16 точек.

```
       1    2    3    4    5    6    7    8
UpT   30   33   38   44   45   50   60   70     ← температура, °C
 %     7   10   20   30   40   50   70  100     ← PWM, %
```

- Каждая ячейка — поле с двумя стрелками (вверх/вниз) справа.
- Переключатель страниц: `<` `1–8 / 16` `>`.
- Числовые поля и стрелки страниц имеют одинаковую высоту 22 логических пикселя.
  При клике по графику или свободному месту фокус числового поля снимается.
- Подпись под таблицей: `Задано: 8 / 16`. Значение `255` в ячейке
  означает «точка не задана» — это нужно поддержать как отдельное состояние, а не как число.
- Подпись: `DownT  −3 °C` · `Применено · max(CPU, GPU)`.
- В нижней строке каждого редактора: `Default` / `Manual` / `Min` / `Max`, выбранная
  кнопка подсвечена. В Windows кнопки обновляют график и применяют режим EC.
- Min хранит базовую кривую; изменение числового поля сохраняется в Manual.
  Возврат к Min восстанавливает базовые точки, Manual запоминает последние правки.
  Max показывает постоянные 100%.
  Default хранит признак штатного режима по дампу после перезагрузки; RAM-таблицы
  в нём пусты, поэтому график показывает «управление прошивкой EC», а редактор
  точек отключён.

### 2.5 Кнопки действий

| Кнопка | Назначение |
|---|---|
| `Default` | вернуть оба вентилятора к штатному управлению прошивкой |
| `Manual / Min` | применить пользовательскую / базовую кривую |
| `Max` | включить Fan Boost для обоих вентиляторов |
| `CPU=GPU / CPU≠GPU` | связать/развязать редактирование кривых CPU/GPU |

Переключатель связи расположен справа в нижней строке карточки кривой GPU,
на одном уровне с Default / Manual / Min / Max; счётчик точек стоит справа от
него. Связанный режим подсвечен. OSD переключателя не показывается.
Нижние кнопки применения и штатного режима удалены, под карточками остаётся
компактная строка состояния, включая прогресс применения и подтверждение PWM/RPM.
В Linux аппаратное применение недоступно до подключения полного EC-транспорта.

Фактический `Режим EC: общий/раздельный` определяется чтением `0x7C5 bit 7`
и показывается отдельно от выбранной связи кривых.

Кнопки действий FANs, SETs, KEYs и BIOS используют общую высоту 30 логических
пикселей. Стрелки страниц относятся к числовому редактору и имеют высоту 22.
В SETs названия профилей производительности находятся внутри кнопок, мощности —
отдельными подписями под ними. Цветные кнопки палитры имеют общую высоту 30.

## 3. Вкладка SETs

Три группы, каждая — карточка на всю ширину.

### 3.1 Батарея · верхний предел зарядки

Сегментный переключатель из трёх: `100%` `95%` `85%` (выбран 95 %).
Пояснения мелким шрифтом:
```
Лимит: 95% · ограничение включено в ЕС.
Сейчас: 71% · Разрядка · 7,49 Вт
100% — полный заряд. 95% и 85% — выбранный верхний порог.
Сохранение в ЕС и активация ограничения показываются отдельно.
Показания сохраняются в журнал зарядки.
```
Важно: сохранение порога и его активация — **разные состояния**, показываются отдельно.

### 3.2 Производительность

Сегментный переключатель, три режима с лимитами:
| Режим | Длительно | Пик |
|---|---|---|
| Офисный | 45 Вт | 65 Вт |
| Сбалансированный | 54 Вт | 65 Вт |
| Турбо | 100 Вт | 105 Вт |

Значения таблицы выше — пример для этой модели. Подписи кнопок формируются из
прочитанных таблиц EC: Office `0x734..0x736`, Balanced `0x730..0x732`, Turbo
`0x7A7..0x7A9`. Активные ненулевые переопределения `0x783..0x785` показываются
в строке текущего профиля. Неполученное значение отображается как `—`.
Источник подписывается `EC`; это данные прошивки, а не обратное чтение лимитов SMU.

Операции FANs, SETs, KEYs и трея взаимно блокируются на время применения команды.
Первоначальное применение кривой блокирует переключения до подтверждения PWM/RPM.
Смена пресета у работающей Manual выполняется владельцем вентиляторов, сохраняет
логические кривые и обновляет ожидаемое состояние EC. Прямой сброс Manual из SETs
не допускается. При ошибке записи режима возвращаются собственные изменения
лимитов; внешние изменения не перезаписываются.

Пояснения:
```
Текущий режим: Офисный
Лимиты ЕС: длительно 45 Вт · буст 45 Вт · пик 65 Вт
Сейчас APU: 2,94 Вт · PawnIO
Один конфиг вентиляторов для всех режимов. Лимиты — верхний предел потребления.
```
Обратите внимание на расхождение: в кнопке `45 / 65`, а в строке лимитов
`длительно 45 · буст 45 · пик 65` — то есть буст показывается отдельно от пика.
Это надо привести к одному смыслу при переносе.

### 3.3 Подсветка клавиатуры

1. Режим: сегменты `Моно` `Пульсация` `Мульти` (выбран Моно).
2. Цвет: ряд из 8 образцов — белый, красный, оранжевый, жёлтый, зелёный, голубой, синий,
   фиолетовый, затем кнопка `Свой цвет…` (открывает выбор цвета).
3. Яркость: 5 кнопок — `Выкл.` `Яркость 1` `Яркость 2` `Яркость 3` `Яркость 4`
   (выбрана Яркость 1).
4. Подпись: `Текущая яркость: 1 / 4`.

Маппинг на регистры (из эталона):
- режим Моно → статический цвет `0x769/0x76A/0x76B`, радуга `0x767` бит 7 = 0
- Пульсация → `0x7C5` биты 2:0 = пресет, радуга = 0, цвет записан
- Мульти → радуга `0x767` бит 7 = 1
- яркость → `0x78C`: биты 7:5 = уровень 0…4, маска `0xE2`, обязательный строб `0x10`

## 4. Вкладка KEYs

Две группы переключателей. У каждого пункта: название, пояснение мелким шрифтом,
текущее состояние серым (`Вкл.` / `Выкл.`), справа пара кнопок `Выкл.` / `Вкл.`
(активная — фиолетовая).

### 4.1 Быстрое переключение

| Пункт | Пояснение | Начальное состояние |
|---|---|---|
| Блокировка клавиши Windows | Вкл. — клавиша Windows заблокирована. | Выкл. |
| Отключить экранное меню | Отключает наши экранные уведомления OSD. Действует сразу, выбор сохраняется. | Выкл. |
| Блокировка клавиши Fn | Меняет основное и дополнительное действие F1–F12. | **Вкл.** |
| Питание USB при выключении и гибернации | Настройка питания USB в ЕС. Фактическое питание проверяется при выключении ноутбука или в гибернации. | Выкл. |
| Автовключение при подаче питания | Запуск при подключении адаптера. После изменения нужна перезагрузка. | Выкл. |
| Блокировка клавиши Copilot | Блокировка действует, пока программа открыта; выбор сохраняется для следующего запуска. | Выкл. |

### 4.2 Устройства Windows

| Пункт | Пояснение | Состояние |
|---|---|---|
| Wi-Fi | Текущее состояние Windows. | Вкл. |
| Bluetooth | Текущее состояние Windows. | Вкл. |
| Веб-камера | `HD Webcam · IR Camera · Электронно отключена · подтверждено ЕС` | Выкл. |
| Touchpad | `HID-совместимая сенсорная панель` | Вкл. |

Подпись снизу: `Выберите «Вкл.» или «Выкл.». Состояния обновляются автоматически.`

Маппинг на регистры (из эталона):
- Windows-клавиша → `0x768` бит 0, запись через строб `0x767` бит 0 = 1
- Fn-Lock → `0x74E` бит 4
- USB-зарядка → `0x767` бит 4; поддержка `0x766` бит 1 **или** известная плата
- Автовключение → `0x726` бит 3
- Веб-камера → `0x727` маска `0x18`, вкл `0x18` / выкл `0x10`; наличие `0x727` бит 3
- OSD, Copilot, Wi-Fi, Bluetooth, Touchpad — не EC, а уровень ОС

## 6. Что переносим на Linux, а что нет

| Раздел | Windows | Linux |
|---|---|---|
| Обороты / PWM вентиляторов | `UWACPIDriver.sys · EC` | **проблема**: `ec_sys` даёт только 0x000..0x0FF, а наши регистры 0x43E..0xF5F. Нужен 16-битный путь доступа, см. `src/platform/linux/README.md` |
| Температура CPU | PawnIO Tctl/Tdie; резерв AMD ADL CPU | `k10temp` Tctl (`hwmon`) |
| Температура GPU | AMD ADL | `amdgpu` (`hwmon`) |
| Мощность APU | PawnIO / MSR | `ryzen_smu` или `k10temp` + RAPL |
| Батарея, ток | Windows · Battery IOCTL | `/sys/class/power_supply/BAT*/` |
| Память SPD (SMBus) | PawnIO · SMBus 0x50/0x51 | требует `i2c-dev` + прав root, может быть недоступно |
| Диски NVMe | Windows · NVMe | `/sys/class/nvme/` + `nvme smart-log`, либо `drivetemp` |
| BIOS / SMBIOS | реестр `HARDWARE\DESCRIPTION\System\BIOS` | `/sys/class/dmi/id/*`, `dmidecode` |
| EDID матрицы | Windows API | `/sys/class/drm/card*/card*-eDP-1/edid` |
| Wi-Fi / Bluetooth | Windows API | `rfkill` |
| Touchpad | Windows API | отдельный адаптер libinput/Wayland-композитора, пока не реализован |
| OSD, хоткеи Fn | хуки Win32 | evdev + слой уведомлений рабочего стола |
| Copilot | Windows | нет аналога |
| Liмит заряда | ACPI WMI адрес `0x7A6` | `uniwill-laptop`: `charge_control_end_threshold` |

Путь к EC на Linux требует прав root. Правило udev и каталог для него пока не
создавались; добавлять их следует вместе с проверенным Linux EC-транспортом.

## 7. Решения по реализации

| Вопрос | Решение | Почему |
|---|---|---|
| Интерфейс Windows | Win32 / GDI, C++20 | Нативные HWND для кнопок BIOS, собственная отрисовка карточек |
| BIOS | Отдельный `BiosPage` | Фоновый сбор Windows, измерение по ширине/DPI, рисование видимых строк |
| Тема | `Theme.h` | Цвета из эталона C#, тёмный заголовок MagicControl сохранён |
| Источники BIOS | SMBIOS, EDID, WMI, DisplayConfig, TBS, Battery Class IOCTL | Только чтение, без OEM DLL и опроса EC |
| Linux | GTK4 / Wayland | 4 вкладки собраны; BIOS читает DMI/sysfs. EC-запись отключена до реализации транспорта |
| Локализация | Запланирована | Сейчас интерфейс MagicControl на русском; 4 языка остаются целью |
