# Восстановление выбранного конфига

Основная схема ниже относится к Wujie/X5SP4NAG; границы других моделей указаны
отдельно. Уточнения19.10.2026 основаны на статических исправлениях из
`research/fixes/models-20261019/`, не на новой аппаратной проверке.
Wujie остаётся внешним эталоном общих карточек/вкладок/скролла для всех моделей;
различия restore задаются typed контроллером, а не самостоятельной страницей.

## Что исправлено

В запуске PID 3644 от 14.10.2026 в 05:45 по Москве файл выбирал Manual,
но EC оставался в штатном режиме (`0x7C6=0`). RAM-управление началось только
в 05:49:43 после ручной команды. Старый код загружал редактор и не применял
сохранённые профили. Теперь подсветка кнопки режима требует фактического
подтверждения, а не только совпадения с файлом.

## Состав конфигурации

- `app-settings.ini`: OSD, Copilot, встроенный шрифт, AllLogs.
- `device-settings.ini`: лимит заряда, профиль мощности, режим подсветки,
  цвет/пресет пульсации, яркость, Windows Lock, Fn Lock, USB-питание,
  автовключение от сети, Wi-Fi, Bluetooth, камера, тачпад.
- `fan-curves.csv`: выбранные профили CPU/GPU, связь CPU=GPU, логические точки.

Device-настройки сохраняются атомарно после подтверждённого действия пользователя.
Версия 2 хранит `PulseColor` как выбранный цвет: 0=белый, 1=красный,
2=зелёный, 3=синий. Код EC на этой плате равен `PulseColor + 1`.
Версия 1 с ошибочным порядком `Breathing` мигрирует по смыслу старой кнопки,
сохраняя намерение пользователя при исправлении карты цветов.
Фоновое чтение EC не заменяет сохранённый выбор. Изменение яркости клавишами
сохраняет значение в файл без повторной записи яркости в EC из пути уведомлений.
При миграции отсутствующие параметры один раз берутся из текущего состояния;
уже сохранённые значения сохраняют приоритет над сбросом прошивки.

## Когда и как применяется

События: запуск, Windows resume, выключенный → включённый/приглушённый экран,
фактическое изменение AC/DC. Дополнительно подтверждённый разрыв elapsed/unbiased
часов после Modern Standby отправляет восстановление в UI даже без power message.
Дублирующиеся уведомления объединяются в течение 750 мс. Постоянной перезаписи
конфигурации по таймеру нет.

Восстановитель ждёт окончания текущей EC-операции и проверки после сна,
затем применяет мощность, лимит заряда, подсветку и переключатели. Последними
одной командой передаются обе выбранные кривые вентиляторов. При CPU=GPU берётся
сохранённый CPU-профиль; неактивный независимый GPU-профиль не включает Max.
Для кривых контроллер ожидает свежие температуры до 30 секунд, сохраняет
существующие защиты и подтверждает фактические PWM/RPM. Default и Max используют
свои обычные аппаратные обработчики.

Общая блокировка DeviceOperation сериализует применение. Она освобождается
после записи EC, позволяя выбрать Default во время набора оборотов. Биты
подсветки и питания пишутся по маскам, сохраняя биты вентиляторов. Радиодоступ
начинается на GUI STA, завершается на рабочем потоке.

В логах: `configuration/RESTORE begin`, подтверждение/ошибка каждого раздела,
итог параметров; отдельно `CONFIG FAN requested/confirmed/failed`. Подтверждение
параметров и постановка кривых в очередь не выдаются за подтверждение оборотов.
Ошибка одного APU шага не отменяет независимые battery/FANs шаги. В legacy APU
step включены и предварительные чтения, чтобы их отказ не оборвал всю очередь.
FAN controller сохраняет собственные identity/mode/ownership guards, включая
Max/Default; общий итог restore остаётся incomplete при ошибке любого шага.
FANs не пишет APU, а SETs не вызывает комплексный OEM профиль ради FANs.

В обычном poll подтверждённая внешняя смена собственных FANs масок прекращает
управление без Default/rollback/rearm чужого состояния. Неизвестное чтение
приостанавливает writes до свежего результата; оно не превращается в совпадение
флагов на следующем тике. Lifecycle restore после подтверждённого сна и новое
явное действие пользователя рассматриваются отдельно от такого наблюдения.

Недоступные в интерфейсе настройки (таймер EC, «Батарея/Сеть») не получают
предполагаемых регистров записи. BIOS — информационная вкладка, её снимок
не используется как конфигурация для записи прошивки.

## Границы восстановления других моделей (19.10.2026)

- Honor HLYL-WXX9 не читает MECHREVO device-settings.ini ради startup/resume
  writes. Батарея/белая подсветка читаются через собственный HWMI/sysfs/I2EC;
  saved Wujie CSV не включает его fixed Manual. Watchdog/exit возвращает только
  собственный fixed request, с Applied/AlreadyAuto/OwnershipLost; чужой manual
  не сбрасывается. Явный Default — отдельный запрос пользователя.
- GM6 не восстанавливает FANs/CPU PL по общей схеме X5. SETs CPU-пресеты пишут
  только PL overrides и не переприменяют FANs. Manual PL draft хранит typed
  controller атомарно; его загрузка не означает фактического применения.
- GM6/HYDROC native BatteryProtection восстанавливается отдельно только при
  явно сохранённом ключе, в собственном model settings file. Retry ограничен
  пятью pre-write transient попытками/30с; identity/pin/OEM/INI/неопределённая
  запись прекращают очередь. Новый явный выбор отменяет старый pending restore.
  На выходе батарейная политика не сбрасывается. Процентные4/7 X5 не переносятся.
- Factory FAN mailbox GM6/HYDROC — явная активная диагностика, не restore,
  startup/poll или разрешение general FANs/Max/HID для HYDROC. ReadOnly RAM
  snapshot и изолируемая telemetry не должны создавать активного writer.

## Исторически проверенный запуск14.10.2026

14.10.2026, PID 6496, `MagicControl-1.jsonl`:

- 06:13:25 (Москва): программа запущена, плата `82/72/26` подтверждена.
- 06:13:26–27: лимит 85%, Офисный, Моно, яркость 4, RGB `50,40,40`,
  Windows Lock=0, Fn Lock=1, USB=0, автовключение от сети=0;
  Wi-Fi, Bluetooth, камера и тачпад включены — подтверждены все разделы.
- 06:13:27: автоматически поставлен Manual CPU=GPU из существующего CSV.
- 06:13:38: `CONFIG FAN confirmed`, CPU PWM 30% / 2782 RPM,
  GPU PWM 30% / 2793 RPM. До подтверждения GPU был на 29%, состояние корректно
  оставалось `confirmed=false`.
- Следующая выборка: `0x751=0xA0`, `0x7B9=85`, `0x741=0x81`,
  `0x7C5=0x88`, `0x7C6=0x04`; PWM обоих каналов 30%.

Ошибка восстановления в этом запуске не зарегистрирована. Хеши существующих
`app-settings.ini` и `fan-curves.csv` сохранены. Новая аппаратная конфигурация
мигрирована в `device-settings.ini`. Реальные сон/пробуждение и переподключение
зарядки на этой сборке ещё не проверялись.
