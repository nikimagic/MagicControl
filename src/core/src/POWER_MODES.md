# Режимы мощности APU и переопределения EC

## Intel: read-only диагностика PL при действии пользователя, 06.11.2026

Общий Windows collector для проверенных CPUID Raptor Lake B7/BA/BF дополняет
существующий короткий logging burst раздельными MSR610 и MMIO59A0/59A4, а
также raw MSR601 и PL4 current в амперах. Для Lenovo прежний фоновый режим и
имя его записи сохранены; для остальных источник называется
`intel_power_diagnostic`. Это не изменение PL, не физический watt readback и
не непрерывный новый poller. Таймштампы MSR и MMIO независимы. Подробнее:
docs/GM6-POWER-INVESTIGATION-20261106.md. Linux collector не добавлен.

## Отмена ожидания при сне, 04.11.2026

Windows ConfigurationRestore на системном событии сна отменяет ожидающую
операцию через поколение сна; прежний запрос не продолжает ожидание после
пробуждения. Ожидание учитывает время бодрствования Windows; при недоступности
счётчика используется прежний таймер. Новый запрос resume сохраняет общий resource entry и
проверки backend. При тайм-ауте фиксируются suspended/applying FAN и занятость
общего допуска. Это не подтверждение фактических лимитов SMU. Аппаратная
проверка перехода сна не выполнялась.

## Lenovo: диагностика класса адаптера

Для точного Lenovo KWCN backend при включённом журнале расширяет существующий
снимок `lenovo_power_diagnostic` сырыми I2EC-кандидатами класса адаптера и
ветки порогов. Каждый байт читается дважды; несовпадение записывается как null.
Снимок целиком не атомарен, единицы `C364/C365` не установлены. Аппаратный
`F01602.0` недоступен и остаётся null: статус AC Windows его не заменяет.
Записи, форсирования класса и новых циклов опроса это не добавляет. Сохранены
отдельные MSR/MMIO CPU-лимиты и знаковый ток батареи существующего журнала.
Успешное чтение или наличие класса 8 не доказывает фактические ватты БП,
устойчивость напряжения либо прекращение разряда. Требуется проверка на Lenovo.

## Custom Base, 02.11.2026

Выбор `00` / `10` — база мощности Custom; это не OEM-разгон CPU/GPU/RAM.
Независимая команда меняет только `751.B0`, с проверкой идентичности, владельца
и readback; ручные FAN-таблицы, Fan Boost и лимиты не переписываются. При FAN
Default прошивка вправе изменить штатные обороты в ответ на базовый профиль.
Настройка сохраняется в device-settings выбранной платы; старые файлы сохраняют
прежнюю базу (GM6 00, Wujie/GM5 10). GUI, запуск и возобновление используют
одних владельцев. Пока точный путь проверен статически только для Wujie,
GM5 и GM6; сходство Uniwill не разрешает запись на других платах. Реакция
железа, точность лимитов и поведение штатной кривой пока не проверены.

## База Custom: Wujie и GM5, 02.11.2026

По прямому выбору владельца Custom Wujie и GM5 использует CPU-базу Turbo
`0x751 & 0xB0 = 0x10`, независимо от предыдущей кнопки. Это политика
MagicControl: в разобранном OEM Wujie Custom выбирал00. Она не снимает
аппаратные ограничения питания и не гарантирует фактическую мощность.

Wujie меняет только маску B0 и свои три overrides в существующей транзакции,
с readback/откатом; Fan Boost и другие биты, таблицы и FAN gates не меняются.
GM5 для Custom проверяет `49F.1` (Turbo capability), устанавливает ту же
базу через существующий owner и обновляет FAN ownership, чтобы Manual online
не восстановил прежние CPU-биты. Custom-профиль/пресет сохраняет свой прежний
порядок FAN/PL; обычный Manual без запроса мощности не переводит базу в Turbo.
Первичная проверка Turbo предшествует изменениям; если возможность изменится
в ходе перехода, повторная проверка может отказать уже после штатного завершения
предыдущего Manual online, но до записи новой кривой.

GM6IR0C сохраняет родной составной Custom и его прежний путь. Lenovo сохраняет
штатный Custom WMI mode255. Эти изменения не распространяют Uniwill-регистры
на другие модели. Контролируемой аппаратной проверки новых переходов нет.

## Единственный вход CPU-команд,01.11.2026

SETs, CLI и внешний Wujie startup/resume используют executePowerResource:
Stock (native index0..2), Economy/Minimal, Automatic, Custom, CustomEditor и
Preset (slot0..2). Внешние CLI slots1/2/3 переводятся один раз на входе.
SettingsAction только декодирует кнопки и передаёт типизированный запрос.
Stock-only GUI guard больше не отбрасывает Minimal0 и Auto4; доступность
кнопки не заменяет повторные проверки конкретного backend.

StandardPowerModesWindows.h/.cpp и публичные applyStandardPowerProfile,
applySettingsPowerButton, applyStockPowerAndDeactivateCustom, applyCustomManual,
applyCustomPreset удалены. Wujie Allowed/Automatic/Stock helpers приватны у
общего входа; совместимый неиспользуемый Gm6Controller.setMode удалён.
Проверки редактора/чтения/индикации не являются аппаратными входами.

Штатный выбор снимает Custom intent после проверенного setter. GM делает это
в своём существующем controller writer; frontend не повторяет сохранение.
Honor/Wujie explicit используют один completion общего входа. Restore имеет
отдельный origin и не сохраняет восстановление как новый пользовательский выбор.
CustomEditor и Preset сохраняют прежний порядок FAN/CPU/readback/files и прежнее
сообщение частичного отказа; собственные кодеки/лимиты/откаты не заменяются.
CLI GM использует те же model-specific input bounds, что редактор, включая
HYDROC PL4 до510; окончательный допуск остаётся у устройства.

Внутренний GM replay остаётся у того же controller и вызывает его же проверенные
setters. Физическая OEM-кнопка — отдельная whole-profile команда с собственным
FAN/CPU/LED порядком; её нельзя подменять CPU-only Stock. Это не дополнительный
frontend writer. Linux и inventory-only профили без подключённого CPU backend
сохраняют явную недоступность; Windows maps/SMU не заимствуются. Windows HPBSD
с01.11 использует свой typed backend через тот же executePowerResource:
Balance/Performance из BIOS, Default FANs следуют B1/B2, а активные Manual/Min/Max
сохраняют точную таблицу. Custom использует общий редактор/пресеты/библиотеку,
общий диапазон запроса5..255W и exact MP1/PM guards, не старое ограничение тестилки65W.
Запрос не доказывает достижимую мощность; неподтверждённое применение откатывается.
Native8/3 FANs сохраняются блоком v3 общей библиотеки без преобразования чужих16
точек. Старые v1/v2 и v2-запись других моделей сохранены. CPU-only Custom и CPU
restore сохраняют FAN-policy; явные пресеты передают свои native curves через
тот же executeFanResource(Manual,Compound), сохраняя прежнее сообщение частичного
отказа и порядок выбора/сохранения после readback.

Проверки границ и автономные fixtures: tests/offline/power-runtime. Они проверяют
маршрут на fake LaptopControl, отказ/сохранение/origin/slot admission и finite
runtime. Они не подтверждают физические профили, частоты или FANs устройств.
Карта и сравнение исходников: research/power-single-path-20261101/REPORT.md.

## Wujie Custom: независимая базовая CPU-политика,29.10.2026

Условие зависимости появилось при разделении путей: с0.1.220 штатные кнопки
меняют751, а Custom оставался на writer трёх overrides. В0.1.389 изменился
источник видимых полей(SMU→EC), но не writer Custom и не SMU-reader.
Это сравнение исходников, не доказательство точной даты физической регрессии.
OEM RamFan1p5.SetFanMode(Custom3) выбирает базу751=00 перед AMD SPL/SPPT/FPPT.
Теперь общий Custom writer через существующий FanController отправляет одну
CPU-операцию:751.maskB0=0 и783/784/785, в одной транзакции с откатом всех
своих полей. Boost40,741,726,727,7C5/7C6, RAM-кривые и FAN ownership сохраняются.
Контроллер обновляет своё ожидаемое CPU-состояние; прямой записи751 из GUI нет.

GUI, пресеты, CLI и восстановление Custom используют executePowerResource.
В standalone CLI сохраняется прежний строгий отказ при чужом владельце,
оставленном Manual/Max: менять CPU-политику мимо владельца FANs нельзя.
На ошибке возвращаются точные исходные CPU-биты и overrides, а не preset recipe.
Запрос5..255 и сохранённые слоты не меняются принятыми значениями EC/SMU.
Raw applyManualPowerLimits для прежних фиксированных overrides/Auto не расширен.

Отдельно доказан DC-budget: внутренние872/87A/88A вычисляются EC из ROM-таблиц,
зависящих от751 и заряда батареи, затем ограничивают86B/86C/86E через minimum.
Эти внутренние поля/таблицы не записывать и не обнулять. После нормального
входа в Custom база одинакова независимо от предыдущей кнопки; аппаратный
потолок питания/батареи всё ещё может быть ниже запроса. Другие модели не меняются.

## Общий PCI mutex: права открытия,29.10.2026

Сохранять именно Global\Access_PCI для PawnIO/SMU и остальных мониторов.
Открывать через общий openSharedHardwareMutex: только SYNCHRONIZE и
MUTEX_MODIFY_STATE, без запроса MUTEX_ALL_ACCESS. На реальном объекте старый
CreateMutexW дал Win32=5, CreateMutexExW с минимальными правами открыл тот же
объект (ERROR_ALREADY_EXISTS). Никакого нового имени, изменения ACL или обхода
сериализации. Timeout означает занятость; ошибка открытия/ожидания содержит
свой Win32-код и не выдаётся за занятость либо нулевое показание.

## Wujie: показывать принятые лимиты EC,29.10.2026

Только exact WUJIE X5SP4NAG с проверкой82/72/26: readEcPerformance сохраняет
отдельно overrides783/784/785 и принятые после выбора политики46A/46B/46F
(STAPM/Slow/Fast). Основание: bank2AA8A..AADE встроенного EC-образа,
побайтно найденного в BIOS29.10, и пять совпавших сохранённых EC/SMU пар.
Это выбранный EC результат, не измерение потребления и не отдельный CPU ACK.
Карту НЕ переносить на GM6/Honor/HPBSD: уGM6 адрес46B — часть GPU tach.

Две согласованные тройки и свежая identity обязательны. Ноль/FF, изменяющаяся
тройка или ошибка чтения дают unavailable. Такая ошибка не теряет остальные
поля страницы, но не подменяется сохранённым запросом, preset/active или SMU.
Записей, ожидания равенства запросу, коррекции FANs или возврата «слишком
малого» результата нет. Более низкий результат допустим.

Windows-поля вне редактирования показывают accepted EC; во время Custom —
сохранённый пользовательский черновик. После успеха редактирование закрывается,
запрос/слоты не перезаписываются принятыми ваттами. PawnIO SMU остаётся отдельной
сверкой в подписи/журнале. CLI сохраняет старые поля overrides и добавляет
ec_power.accepted и smu_comparison. Нет нового writer или обхода диспетчера.
Другие устройства сохраняют прежние источники. Linux SETs без подключённого
EC writer/reader не получает фиктивные значения или новый аппаратный допуск.

## WUJIE Auto и нулевые overrides,27.10.2026

Подтверждённые783/784/785=0 теперь сохраняются в overrides как0, неnull.
В active нулевой override оставляет исходное поле native EC preset; это не0Вт.
При отсутствии явного Auto подсвечивается Office/Gaming/Turbo по751.mask90.
Отдельная пятая Auto повторяет контракт GM6: снять только783/784/785,
проверить0/0/0 и сохранить явный выбор ApuAutoPower=1. Ни751, ни FAN flags,
таблицы/ownership, режим вентиляторов или ручной черновик Auto не меняет.
Auto не зависит от AC/DC или масштаба PL4: нулевой override не имеет масштаба.
Прежние Custom5–255 и его727.7 guard остаются без изменения.

Новая UI позиция Custom5 не меняет старую запись ApuMode4=Custom. Auto имеет
отдельный необязательный boolean, добавленный в конец DeviceSetting; прежние
индексы и значения файлов сохранены. Native/Minimal/Custom снимают этот признак.
При startup/resume ApuAutoPower имеет приоритет над прежним ApuMode и вызывает
тот же guarded resetManualPowerLimits. Подсветка Auto требует явного intent и
полного fresh0/0/0. Неизвестное/частичное чтение не становится Auto.
CLI power auto использует этот же setter; как прежние Wujie CLI power setters,
он не заменяет GUI preferences. Linux показывает пятую кнопку через общий
каталог, аппаратные действия по-прежнему зависят от его реального backend.
GM6/GM5/L16/Honor/HPBSD writers и правила выбора не менялись.

## HPBSD: явная проверка SMU,27.10.2026

Отдельный applyHpbsdLimitsMilliwatts допускает только exact HPBSD/BIOS1.06/
AMD19h:75h/PM4C0009,5–65Вт,STAPM<=Slow<=Fast. Общий MP1 transport использует
response3B10578; Honor wrapper сохраняет3B10564 и все прежние условия.
HPBSD принимает точные милливатты1:1: проверены20/25/30 и8/10/12Вт, затем
возвращены54.4/60/65Вт; FAN policy не менялась. Нагрузка~14.8Вт при Slow10Вт
снизилась к~10Вт по SMU/RAPL. Длительные STAPM окна не проверялись.
Задание ограничено внутренней явной тестилкой, с сохранением baseline,
PCI mutex, повторным PM readback и проверяемым rollback. Обычный опрос,
восстановление,capabilities и кнопки SETs HPBSD новый setter не вызывают.
Никакой записи EC/вентиляторов/BIOS/thermal/voltage; коэффициенты Honor не
переносятся на HPBSD. Новые штатные тройки мощности не выдумываются.

## Штатные CPU-профили без переключения FANs,26.10.2026

Новое указание владельца заменяет прежний full-profile apply трёх стандартных
кнопок exact GM6: брать штатные лимиты, выбранный FANs сохранять. Изменение
реализовано в typed core/device paths, общих для GUI, CLI и восстановления.
Minimal, Custom, его значения и слоты этим изменением не переделываются.
Это относится именно к стандартным кнопкам; физический OEM цикл остаётся
отдельным whole-profile механизмом. Их побочные действия не взаимозаменяемы.

WUJIE Office/Gaming/Turbo используют существующий selectEcPerformance через
FanController.performance: очищают783/784/785, меняют только751.maskB0,
сохраняютBoost40, RAM gates, точки и lease FANs. Плата82/72/26 проверяется
до записи. Никакой общей фиксированной тройки ватт не применяется: реальную
политику AC/DC/зарядного устройства выбирает прошивка, SMU отображает результат.
NativeCpuPresets=1 сохраняется только после нового успешного выбора; старые
файлы без этого маркера сохраняют прежнюю семантику, Minimal/Custom — прежние
значения. Восстановление вызывает тот же core path.

GM6/GM5/L16/HYDROC читают собственные свежие таблицы734/730/7A7 и используют
свой codec PL4/FPPT, прежние диапазоны, AC admission и rollback. Стандартный
setCpuPreset пишет только783/784/785, не751/FAN/APP. GM6 EC1.12 исполняет
overrides при активных741.0 и727.6: если gate выключен, отказ до записи,
без скрытого включения FANs. Readback байтов не объявляется измерением CPU.
GM6 configuration v2 хранит отдельный stockCpu index; v1 читается совместимо,
старый FAN intent сохраняется отдельно, восстановление CPU читает defaults
заново. Физический native cycle не заменён этим CPU-only методом.

Honor имеет два штатных HWMI режима Balanced/Performance, а не три Uniwill
тройки. Typed LaptopControl.setStockCpuProfile повторно посылает нужную OEM
команду0F04 один раз, проверяет0E04, без промежуточного импульса и FAN-команд.
Чтение флага не доказывает фактические лимиты SMU после прежнего Custom.
Linux без подтверждённого writer остаётся недоступным; GUI показывает честный
состав режимов. Для inventory-only моделей управление не добавляется.

Источники и границы: research/native-cpu-profiles-20261026/REPORT.txt.
Новых аппаратных запусков и тестов при этой правке нет.

## Custom WUJIE без DC-срезания,25.10.2026

Уточнение владельца после0.1.204: ручной Custom5–255Вт независимо от AC/DC.
Прежняя ветка kApuBatteryMaximum40/40/45 не должна менять ни редактор, ни
его сохранённые слоты, ни CLI custom, ни восстановление Manual/Mode4.
Все эти пути используют общий Custom dispatcher;29.10 добавлена его собственная
CPU-база перед прежней записью overrides с той же валидацией.
Отключение БП не переписывает draft. Factory presets по-прежнему идут через
applyApuAllowedLimits и сохраняют свои DC-пределы/Turbo admission. Это не
универсальная политика для GM6/HYDROC/L16/Honor: их кодеки и границы прежние.
Guard прямого PL4/ownership/rollback и предел byte255 сохранены. Фактическое
принятие высокой мощности остаётся отдельным SMU readback, не обещанием UI.

## Custom WUJIE до255Вт и Esc,25.10.2026

По указанию владельца прежний программный AC предел100Вт поднят до255Вт.
OEM MyFanManager.SetPL пишет1923/1924/1925 как(byte)PL, поэтому500 не кодируется
этим путём и не допускается. Shared kApuManualMaximum=255; validator, сохранение
ManualStapm/Slow/Fast, Custom slots и редактор используют одинаковый предел.
Readback EC допускает201–255;0 остаётся отсутствием override. Принятый byte
не доказывает лимит SMU или фактическую мощность. Guard прямого PL4, ownership,
rollback сохранены; DC40/40/45 относятся к factory presets, не Custom. Honor, GM6 и другие model-specific
диапазоны этим изменением не расширяются. Linux writer не добавлен.

Esc во время редактирования Custom восстанавливает предшествующий локальный
набор и закрывает редактор. Нет save/apply/EC/SMU записи. Во время уже начатого
аппаратного применения Esc не объявляет операцию отменённой и не меняет её.

## GM6 Custom1/2/3 и завершение программных команд,22.10.2026

Ряд редактора общий для Windows/Linux: [Custom] [1] [2] [3]. Полные пресеты
подключены к exact GM6 Windows; остальные существующие writers не расширены,
на Linux кнопки имеют прежнюю недоступность аппаратного Custom. Размеры трёх
кнопок задаёт общий DIP layout, используется встроенный шрифт и прежние контролы.
Подписи числовых полей по-прежнему измеряются реальным шрифтом/языком/DPI.

Первый клик по пустому слоту сохраняет Custom без EC-записей: редактируемые PL,
либо собственный Custom intent/draft (при отсутствии — прежние fresh Gaming
defaults для Custom); обе16-точечные UpT/DownT/PWM кривые и Respective.
Следующие клики применяют сохранённый слот через тот же applyNativeProfile.
Заполненный слот обычным кликом не перезаписывается. Поля файла проверяются
до аппаратного apply: версия, exact профиль,3 слота, размер, число точек,
границы/порядок PL и кривых. Ошибка не очищает файл и не включает профиль.

только актуального GM6. В чистые release-пакеты личные слоты не включаются.

Программные команды GM6 профиля/Custom/слотов завершают readback своего профиля
без ожидания несвязанного Battery Class/RAPL/power-policy опроса. Старые значения
датчиков сохраняют прежние timestamps; normal passive poll обновляет их отдельно.
При интерактивной команде ожидающий GM6 passive read пропускает оставшиеся

software_command_timing разделяет apply_ms и profile_refresh_ms с monitoring=deferred.

или контроллер не создаётся, остальные модели сохраняют прежнюю последовательность.

## Независимость от FANs

SETs управляет мощностью APU, FANs — вентиляторами. Смена мощности не должна
вызывать Default/Max/Manual, восстановление вентиляторов или перезапись их таблиц.
Изменение температуры и оборотов вследствие изменения мощности нормально;
это не повод считать вентиляторный режим потерянным.

Не писать из управления мощностью `0x726`, `0x727`, `0x741`, `0x7C5`, `0x7C6`,
PWM или RAM-таблицы. Общий регистр `0x751` менять **только маской `0xB0`**,
сохраняя Fan Boost `0x40` и все остальные биты.

## Office / Balanced / Turbo

| Профиль | Записываемые биты `0x751 & 0xB0` |
|---|---:|
| Office | `0xA0` |
| Balanced | `0x00` |
| Turbo | `0x10` |

Декодирование группы профиля использует `0x90`; бит 5 (`0x20`) присутствует
в нашей записи Office. Его самостоятельный эффект не установлен. Не придумывать
отдельный переключатель на основании этого бита.

`selectEcPerformance` читает исходные режим и три override, возвращает ненулевые
`0x783–0x785` к нулю, записывает изменившийся профиль маской, проверяет чтением.
Ноль в override означает возврат к штатной политике, **не ограничение до 0 Вт**.
При ошибке откатывать только собственные изменения, сверяя ожидаемое состояние;
не затирать внешнее изменение старым полным снимком EC.

Фабричные тройки EC читаются из Office `0x734–0x736`, Balanced `0x730–0x732`,
Turbo `0x7A7–0x7A9`. Это данные OEM, а не гарантированные текущие лимиты SMU.
Например, таблица Turbo 100/100/105 не доказывает, что APU разрешено 100 Вт.
Источник питания и политика прошивки могут влиять на фактические лимиты.
Не выдавать числа таблицы или выбранный профиль за измеренную мощность.

## Проверенная связь override → SMU

Пробы 16.10.2026, 16:49–16:50 Москва: Turbo `0x751=0x10`, источник EC USB-C 2,
65 Вт, `0x727=0x40`. MagicControl закрыт, нагрузка не запускалась.
Исходные SMU **STAPM/Fast/Slow = 35/40/35 Вт**.

| Регистр EC | Историческое OEM/API имя | Фактически изменившийся лимит | Проба |
|---|---|---|---|
| `0x783` | PL1 / sustained | **STAPM** | raw 25 → 25/40/35 |
| `0x784` | PL2 / shortBoost | **Slow** | raw 26 → 35/40/26 |
| `0x785` | PL4 / peak | **Fast** | raw 15 → 35/15/35 |

**Порядок EC-регистров — STAPM, Slow, Fast, а не STAPM, Fast, Slow.**
По запросу пользователя вся карточка APU и Tab-навигация показывают
**Fast → Slow → STAPM**. Внутренний массив/запись EC остаются STAPM/Slow/Fast;
GUI меняет размещение, не соответствие регистров. Ключи файла не меняются.
Каждый регистр менялся отдельно. Остальные два лимита сохранялись.
Возврат каждого override к нулю возвращал SMU к **35/40/35**.
Первое изменение наблюдалось в следующем секундном опросе; это разрешение
измерения, а не доказательство фиксированной задержки ровно 1 секунда.

`EcPowerLimits::sustained/shortBoost/peak` сохраняют исторические имена OEM.
Не связывать `shortBoost` автоматически с SMU Fast. `readEcPerformance` возвращает
EC-представление, а не снимок SMU; их состояния получать и подписывать отдельно.

## Особенность `0x785` / PL4

OEM читает **бит 7 регистра `0x727`**: если он установлен, `SetPL4Value`
записывает половину значения (`value >> 1`); иначе пишет значение напрямую.
В нашей пробе бит был **сброшен**, raw 15 соответствовал SMU Fast 15 Вт.

Случай установленного бита на нашем устройстве **не проверен**. Не включать
удвоение по предположению и не переключать `0x727.7` ради нужного масштаба:
этот байт также содержит вентиляторный gate `0x40` и команду камеры `0x18`.
Для неизвестного масштаба будущий ручной интерфейс должен сообщать ограничение
поддержки, а не экспериментировать незаметно.

## Телеметрия SMU

24.10.2026: временный отказ `ioctl_update_pm_table` теперь получает прежние
ограниченные повторы10/100мс не только на HLYL/Renoir, но и на уже допущенном
Wujie/PM5D0009. Повторяются только HRESULT INTERNAL_ERROR/BUSY и только перенос
телеметрии, максимум3попытки. Остальные ошибки сразу возвращают прежний stale;
после исчерпания попыток сохраняются reset модуля и backoff30с. Старые данные
не объявляются свежими. Отдельный `smu_telemetry` журнал различает retry/recovered.
Версии/identity/PCI mutex/декодер, SMU setters и startup/resume EC restore не менялись.
Наличие кода повтора не является аппаратным подтверждением восстановления после сна.

Для PM `0x5D0009` используются float-индексы:

- 0 — STAPM limit;
- 2 — Fast limit;
- 3 — мощность APU в окне Fast;
- 4 — Slow limit.

Версию проверять до декодирования. `ioctl_update_pm_table` переносит телеметрию;
в текущем reader нет SMU setters. Не добавлять их в мониторинг.
Мощность APU включает встроенную графику: не прибавлять GPU повторно к APU.
Текущая мощность может быть значительно ниже лимита без нагрузки.

## Кнопки SETs: фиксированные лимиты (16.10.2026)

Четыре кнопки в одном ряду задают **Fast / Slow / STAPM**:

| Кнопка | Fast | Slow | STAPM |
|---|---:|---:|---:|
| Экономичный | 15 | 10 | 10 |
| Офисный | 30 | 25 | 25 |
| Сбалансированный | 45 | 40 | 40 |
| Турбо | 70 | 65 | 65 |

От батареи Turbo отключён в SETs и трее, обработчик также запрещает применение.
Manual: максимумы Fast 45 / Slow 40 / STAPM 40 Вт; от сети — 100 Вт на поле.
Источник определяется через Windows GetSystemPowerStatus, не по статусу зарядки
батареи или предполагаемому EC priority. Неизвестный источник ограничивается как
батарея, Turbo требует подтверждённую сеть. Диапазоны меняются при уведомлении
питания и опросе. Пустой/промежуточный ввод разрешён, ограничение — при завершении.
Перед применением и восстановлением Windows ApuPowerPolicyWindows.h повторно
проверяет источник и ограничивает тройку. Сохранённый Turbo на старте от батареи
восстанавливается не выше 45/40/40, но файл выбора не переписывается пассивно.
При отключении кабеля редактор ограничивается; это не запускает новую запись EC
или восстановление FANs. Balanced задаёт 45/40/40 и от сети, и от батареи.

Это пресеты конкретных override, а не старый OEM-переключатель 751.
Все четыре кнопки и Manual вызывают `applyManualPowerLimits`: только отличающиеся
783/784/785 с проверкой и откатом собственных изменений. Не менять 751, 7C3,
High Power, Overboost, батарею или FANs при выборе этих кнопок. Пресеты определены
один раз в `kApuPowerPresets`, внутренний порядок STAPM/Slow/Fast.

Manual и три поля Fast / Slow / STAPM расположены в одном ряду с мощностью APU.
Контролы по умолчанию недоступны, цифры приглушённые: показывают реальные лимиты
SMU при каждом опросе (3 секунды), включая состояние после применения Manual.
Первое нажатие Manual только открывает редактор: цифры белые, загружается ранее
сохранённый ручной пресет. EC и файл при открытии не меняются. Ввод/стрелки/потеря
фокуса меняют только черновик; опрос не перезаписывает его, включая пустое поле.
Второе нажатие Manual применяет и сохраняет значения. При успехе редактор закрыт,
цифры снова приглушены и отображают SMU; при ошибке черновик остаётся доступным.
Новый первый клик снова загружает сохранённый Manual. Пресетная кнопка закрывает
редактирование и применяет собственную тройку, не затирая сохранённый Manual.
Состояние редактора не выводить из факта ненулевых override или ApuMode=4:
выбранный ручной режим и временное редактирование — разные состояния.
Ограничения ввода: батарея Fast45/Slow40/STAPM40, сеть 100 Вт на поле, минимум5.

`device-settings.ini`: `ApuMode=0..3` — четыре пресета по порядку, `4` — Manual.
`ManualStapm/ManualSlow/ManualFast` сохраняют ручную тройку отдельно. Совпадение
ручной тройки с пресетом не превращает выбранный Manual в пресет.
Запуск/возобновление восстанавливает новый режим через тот же API override.
Старые файлы без ApuMode сохраняют прежний OEM-путь восстановления; новая схема
сохраняется после явного нажатия кнопки. Не переосмысливать старый Performance=0..2
как новые индексы. Старый `selectEcPerformance` остаётся отдельным OEM API.

Сборка подтверждает компиляцию, не физическое соблюдение всех новых пресетов
под нагрузкой или их восстановление после сна. Диапазон редактора не является
доказанным диапазоном аппаратных возможностей.

Подтверждены изменение читаемых SMU-лимитов и возврат нулём в указанной
конфигурации. Не подтверждены физическое соблюдение под нагрузкой, другие
профили/зарядки, совместная запись всех трёх override, максимальный допустимый
диапазон, сохранение после сна/гибернации и масштаб при `0x727.7=1`.

Режим Manual обязан различать запрошенное, записанное EC и принятое SMU.
Сохранять исходные значения до записи, менять только нужные override, проверять
SMU и предусмотреть возврат. Не вести постоянную борьбу с прошивкой и не
переприменять FANs. Не добавлять периодическую запись лимитов при простом
опросе или открытии вкладки. Сохранение после сна проверять отдельно.

Исследовательский `probe.py` выполняет аппаратные записи: запускать только по
явному запросу пользователя. Для текущего запроса на документацию не запускать
тесты, приложение или аппаратные пробы. При новых результатах обновлять эту
инструкцию и комментарии, сохраняя границу между доказательствами и гипотезами.

## Цвет фактической мощности APU

Число мощности SMU Fast: до 20 Вт включительно — синий, 20 < P ≤ 30 — зелёный,
30 < P ≤ 45 — жёлтый, выше 45 Вт — красный. Дробные значения сравниваются
без округления; неизвестное значение имеет нейтральный цвет.

## Недоступное управление APU в Default FANs (17.10.2026)

По наблюдению пользователя прошивка в Default FANs не принимает ручное
управление APU. Интерфейс отражает эту фактическую недоступность, чтобы не
предлагать неработающие действия: пресеты мощности APU, Manual и его редакторы
недоступны в подтверждённом Default. Переключатель платформы Limiter EC/Turbo EC
ОСТАЁТСЯ ДОСТУПЕН, включая трей: это отдельная политика EC, не ручные ватт-лимиты.
Подсвечен только Balanced как индикатор Default; это НЕ запускает запись его
45/40/40 в EC и не меняет сохранённый ApuMode. SMU продолжает опрашиваться.
При выходе из Default управление снова доступно; сохранённые лимиты не переприменяются
ради подсветки. Запрет есть в трее и обработчиках, включая отложенное применение.
Default определять по подтверждённому FanControlStatus, не по RPM/PWM или ошибке.
Батарейные 100/95/85% и подсветка клавиатуры остаются независимыми.

Подписи контролов APU по запросу пользователя: «Пик, Вт» / «Средняя, Вт» /
«Длительно, Вт» в визуальном порядке Fast/Slow/STAPM. Ширины подписей измерять
реальным шрифтом, сохранять один пробел после Вт и одинаковые межгрупповые отступы.
Это только отображение: внутренние имена, регистры, порядок записи и ключи файла
остаются прежними; не менять соответствие лимитов ради русского названия.

Локализация контролов: powerFieldLabels() — единый источник подписей и для
измерения, и для рисования. При добавлении языков подставлять переведённые строки
в эту точку и заново вызывать layout. Ширины вычисляются GetTextExtentPoint32W
текущим шрифтом при текущем DPI; не задавать фиксированные ширины/отступы для
каждого языка. Между группами остаётся единый визуальный интервал.

## Подтверждение Default при запуске/гибернации (19.10.2026)

должны быть сняты; смешанный набор флагов не считается Default.
