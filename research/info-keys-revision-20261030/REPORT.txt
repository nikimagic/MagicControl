Second INFO/KEYs architecture audit,30.10.2026, baseline 0bbbed37

Found/fixed active residue:
1. CLI inventory still collected then saved InventoryCache itself (old path since
   e01208f4/77502e33). Previous collect-only documentation was inaccurate. It now
   uses executeInfoInventoryResource, as GUI refresh already does, preserving JSON
   output and successful persistence while refusing to save a cancelled snapshot.
2. KEYs had two explicit-worker creation/publication blocks, for read and command.
   They now share startWorker and publish/failure. The pre-existing KeysLifecycle
   worker remains an intentionally separate restore/observe policy.
3. Windows GUI Row.available and unused KeyId/include residue removed. Permission
   remains in the common coordinator; GUI still owns only presentation state.
4. External changes to another KEYs row during a command could be overwritten by
   its old baseline. They are now overlaid as during refresh. The command's own
   row remains a fresh hardware confirmation; local OSD is authoritative after
   all overlays. These are source-inferred failure cases, not observed new logs.
5. INFO could accept duplicate/late installer completion or overwrite it through
   an exception after synchronous completion. A single guarded publish makes the
   terminal result immutable. Raw callback outcomes remain audited separately.
   This is defensive lifetime correctness, not a claimed reproduced hardware bug.
6. PowerInput had a distinct declared resource key but was routed through EC's
   conditional handler. It now has its own binding to the SAME existing collector.

No old parallel GUI executors remain. Legitimate roles retained: Win32/GTK event
adapters, GUI asynchronous vs CLI synchronous coordination, separate actual OS
backends, collect-only API (not the CLI inventory command), restoration policy,
cache reads, explicit APP/Copilot teardown, and per-window scroll positions.
No new architecture files or hardware protocol/reader changes introduced.
Static audit and final shared build evidence follows. No tests or app/hardware run.
