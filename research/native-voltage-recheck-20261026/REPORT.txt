2. Mode and voltage are different state

7A6.mask30:00=Full Capacity/Performance,10=Balanced,20=Healthy.
741.0 absent makes the firmware clear this mode field. APP is already set in
the observed WUJIE logs; no experiment to raise it was performed.

The firmware chooses the FIRST applicable reduction tier, per cell:
250mV: history H>15840 OR cycles>=550 OR calendar age>=25months
200mV: history H>11520 OR cycles>=450 OR age>=19 OR Healthy
150mV: history H>8640  OR cycles>=350 OR age>=13
100mV: history H>6480  OR cycles>=250 OR age>=10 OR Balanced
 50mV: history H>4320  OR cycles>=150 OR age>=7
  0mV: none of the above.
For an invalid tiny BMS voltage input(<500mV), a separate guard leaves delta0.
H is a firmware high-voltage/temperature exposure counter; this report does
not assert a wall-clock unit or identify arbitrary host-mapped bytes as its
actual current internal value.

WUJIE direct proof: C6CB=250,C703=200,C736=150,C76D=100,C790=50;
DD16 supplies low-byte E0/carry for the highest H threshold3DE0; D71A compares
age25, C6F0 age19, C72E age13, C75A age10, D881 age7.
GM6 raw table is independently preserved in its two image windows and the
earlier ec-audit/HEALTHY.md, not inferred solely from the WUJIE function.

Full Capacity removes only the USER minimum. It does not disable aging.
Balanced ensures at least100mV/cell; Healthy at least200mV/cell. Aging may
select a stronger tier in any mode. The UI must not promise different CV
values for every button or promise100% of an unaged cell's nominal energy.

3. Calendar age, actual WUJIE saved data

WUJIE bank1 E7C6..E9A5 calculates age; bank0 trampoline1CA8 dispatches there.
The function uses the preferred valid date7F2/7F3 or otherwise manufacture
date0314/0315. Current year/month are72D/72E (BCD). It calculates whole calendar
months, publishes/cache036C, validates input and can fall back to saved036C.
Maintenance flags726 and override036D can alter this path; they are not normal
UI settings and were not changed.

In dump-20261025-142546-0/ec.bin (and prior saved24/25October dumps):
0314/0315=5A52;72D/72E=26/10;7F2/7F3=0000;036C=14hex=20;
036D=00;726=00. Corresponding ec-valid.bin marks these byte reads valid.
SBS packed manufacture date5A52:
year=1980+(word>>9)=2025,month=(word>>5)&15=2,day=word&31=18.
Thus the battery-reported manufacture date is18February2025, and the EC's
October2026 calculation is(2026-2025)*12+(10-2)=20months.
This is an EC copy of battery metadata, not a new direct BMS read in this
analysis. It is neither purchase date nor a measured wear percentage, and
does not prove the pack's physical birth date if BMS metadata was rewritten.

4. Voltage formula and charger handoff

Cells:491&C0==C0 ->4;==80 ->3;otherwise2 in the reviewed functions.
Base:030E/030F BE16 BMS charging-voltage request.
Target:0522/0523 LE16 = base - cell_count*selected_reduction.
WUJIE C792..C7C8 performs this multiply/subtract; command handoff:
0522/23 ->0836/37 ->pending0832.1 ->bank0 D5BD ->ChargingVoltage command15.
GM6:0522/23 ->0836/37 ->DE6B pending0832.1 ->common1C06 ->bank0 C929
->ChargingVoltage15. Earlier byte-linked handoff evidence remains in:
research/battery-logger-comparison-20261026/CURATED-WINDOWS.asm and
research/devices/gm6ir0c/battery-all-modes-20261021/ec-handoff-audit/REPORT.md.
Prepared voltage requests do not prove SMBus ACK or measured charger output.
With AC absent this function need not update the target: it can remain saved.
Measured pack voltage0438 is a separate signal.

6. Result / boundaries

The displayed WUJIE Full Capacity plus0.80V reduction is consistent with the
reviewed firmware; it does not by itself indicate a failed button or a UI bug.
The earlier statement that switching a mode must change displayed voltage was
too strong: it changes the mode field, while stronger aging can dominate CV.
These modes are voltage/aging profiles, not95/90% charge hysteresis. The separate
percentage limiter and its lower restart semantics are not changed by this audit.
No product source, settings, platform/ROM identity, firmware or EC was changed.

7. Coverage: manufacture date is not a universal EC address

Confirmed here: WUJIE and GM6's reviewed images/EC layouts have the date and
calendar-age chain described above. Other supported models are not confirmed
by this audit. In particular0314/0315 must not be read/decode-assumed universally
for HYDROC, GM5, L16, Honor or unknown laptops merely by family resemblance.
Honor uses a separate vendor interface, not this Uniwill map.
Windows BatteryManufactureDate is a DIFFERENT interface, already queried by
MonitoringWindows.cpp and BatteryInterfacesWindows.h. If its battery driver
does not return it, INFO may show unknown even though a reviewed EC image has
its own copy. Calendar age and date are not guaranteed on every laptop.
