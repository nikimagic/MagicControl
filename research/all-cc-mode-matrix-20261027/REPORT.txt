Это обычная RamFan1.5-ветка. AppType, CustomizeTarget и BIOS-family могут

В старом legacy MyFanManager индексы ДРУГИЕ: 0 Gaming, 1 Office, 2 Turbo.
Универсального Custom 3 там не показано. Общими должны быть названия и смысл,
а не одинаковый числовой аргумент для разных менеджеров.

Stock 0/0/0 означает возврат к firmware budget, не 0 Вт.
Fan Boost 751.6 не равен Turbo 751.4. Custom 726.7, индикатор 727.6,
APP 741.0 и RAM commit 7C6.2 — отдельные поля.

Общие Default-файлы GM5/HYDROC/L16 и сохранённого WUJIE совпадают:

Gaming — 90% при UpT 83; Turbo — 100% при UpT 83.
Это совпадение шаблонов пакетов, не доказательство одинаковой EC-политики.
Резервная Office из FanCurve-Backups отличается и не считается заводской.

Реальная цепочка RamFan1.5:
FAN.TableName -> MyFanTableCtrl.SetFanTable -> очередь:
7C6.2 off -> split/common 7C5.7 -> запись CPU F00/F10/F20 и GPU F30/F40/F50
-> commit on, только если CPU F00/F01 не оба нулевые.
Up сдвинут на одну точку, Down[0] пропущен, Duty кодируется *2.
При начале CPU 0/0 commit остаётся 0. Поэтому stock-режим НЕ означает
безусловно commit=1, но и наша Default с отключением RAM НЕ эквивалентна
загрузке валидной заводской RAM-кривой.

При FanSafetyProtect 7A5.3 сервис подставляет DefaultFanTable соответствующего
режима; для Custom — Gaming. При подключении LC обычная отправка таблицы
может блокироваться или заменяться; при отключении возвращается её имя.

Точный WUJIE 5.57 содержит RefreshDefaultFanTableAll:
снимает APP -> firmware mailbox Gaming=2 / Office=3 / Turbo=1 -> читает RAM
-> сохраняет Default -> копирует в M1..M4 -> возвращает APP.
Команды F5F/F5D/F5E и ACK FD/C9 подтверждены в коде CC.
Это активные EC-записи; здесь они НЕ выполнялись. Наличие CC-обработчика
не доказывает успешный ответ конкретной установленной EC-прошивки.
Нулевой сохранённый M1 сам по себе не доказывает успешный factory export.

5. РЕЖИМЫ ПРИ РАБОТЕ ОТ БАТАРЕИ И СЕТИ

Источник | Как определяется доступность | Реакция
GM5/GM6 старые | Windows Online плюс 7CC & 0x36; 0x12/0x24 трактуются как DC | PowerStatusChange -> Init(false) -> повтор текущего профиля
HYDROC 5.23.51.56 | RoundSocket 7CC.0 и APVersionCheck | PowerStatusChange пустой; SwitchModePowerChange синхронизирует EC mode
CC 5.56 exact 7578 | Для AP>=24 учитывает RoundSocket 7CC.0, NVIDIA и UMA различаются | PowerStatusChange пустой; отдельный SwitchModePowerChange читает mode и снимает Boost/GPU offset в соответствующей ветке
WUJIE 5.57 exact | Для BIOS IDG/IDI/IDL публикует IsAC=true в FAN/Tray status | Отдельные SwitchModePowerChange, Resume и WMI 171/199; IsAC не является физической AC-телеметрией
L16 exact 5.60 | Видны isAc и SwitchModePowerChange | Нужное тело защищено; соседний алгоритм не приписан

Главное для WUJIE: его BIOS-family IDG входит в явное исключение.
CC сообщает интерфейсу IsAC=true даже при физической батарее.
Поэтому общий запрет кнопок по одному Windows DC не повторяет OEM WUJIE.
В точном 5.57 IsUMA() также явно признаёт IDG/IDL/IDI; в других сервисах
эта функция проверяет GetNvGpu()==0. Нельзя смешивать эти реализации.

Turbo capability обычно читается из 49F.1; CustomizeTarget 42 может обнулить.
В новой NVIDIA-ветке физический цикл при AP>=24 и RoundSocket!=1
направляет Gaming -> Office, пропуская Turbo.
Это условие физической кнопки, не доказанный общий запрет любого вызова UI.
В UMA-ветке физический цикл обычно Office -> Gaming -> [Turbo] -> Office;
Custom выбирается интерфейсом отдельно. Четыре общих названия не требуют
навязывать одинаковый аппаратный цикл каждой модели.

В рассмотренном CPU SetUserProfile нет универсального отказа Custom при DC.
Но наличие setter не доказывает доступность кнопки клиента или исполнение
лимита прошивкой. Наш AC-only guard нельзя ни называть точным OEM правилом,
ни снимать без проверки всей конкретной цепочки.
Stock оставляет AC/DC бюджеты прошивке; фиксированная общая тройка Вт
из JSON не является полным описанием режима.

8. ЗАРЯДКА ОТДЕЛЬНО ОТ ПИТАНИЯ CPU

BatteryProtection2 задаёт 7A6[5:4]: Full Capacity/Performance=00,
Balanced=01, Healthy=10. Это не Office/Gaming/Turbo и не флаг IsAC.
В рассмотренной CPU-цепочке не найден автоматический вызов смены зарядки,
Platform7C3 или ROM770. Literal scan точного 5.57 также не нашёл 1987/1904,
но это не исключает вычисляемые адреса, другие DLL или firmware.
По ответу владельца будущая CPU/FAN-адаптация зарядку и ID не меняет.
