Общая перекрёстная ревизия, 19.10.2026, MagicControl0.1.75
Родительский агент: независимая проверка конкретных веток после5 модельных аудитов.
Только статический просмотр кода и сохранённых данных. Новых аппаратных проб,
тестов, сборок и изменений src/gui/ядра/настроек не выполнялось.

X1 [P2] Выбор CPU-пресета GM6 в SETs переприменяет управление FANs.
Путь: src/gui/windows/SettingsPage.cpp:1357–1358 вызывает Gm6Controller::setMode.
Реализация: src/devices/mechrevo/gm6ir0c/ControlWindows.cpp:281–290:
stopOnline(), putTables(factoryCurves,false), custom/light=0,
751 native mode, PL overrides=0, RAM commit7C6.2=1.
Таким образом выбор в карточке «Производительность Intel CPU» останавливает
Manual online и заменяет активную фан-кривую встроенной OEM reference.
Это не гипотеза по совпадению адресов — прямой путь вызова и набор записей.
Точное совпадение с родным OEM whole-system profile подтверждено GM6 агентом;
оно не означает соответствия независимому управлению мощностью из SETs.
Общий AGENTS.md запрещает запись FAN-таблиц из SETs; эталон Wujie сохраняет
вентиляторы при выборе мощности (FAN_MODES.md:22–23).
Нельзя безоговорочно переносить только аппаратные регистры Wujie на GM6.
Предложение: отделить typed CPU-only настройку от штатного комплексного OEM
профиля, сохранить FANs/online и actual-state. Если независимый native preset
не подтверждён, не выдавать комплексное изменение за CPU-only. Решение должно
сохранять внешний вид карточек Wujie; физический API проверять отдельно.
Это дополнение к gm6ir0c.txt, который верно описывает текущее OEM-поведение,
но не классифицировал его связь с общим пользовательским контрактом.

Перекрёстно подтверждены также:
- unknown U1: Windows Radeon fallback подавляется глобальным hasIdentity,
  поэтому частичный ответ provider скрывает второй OS-visible адаптер.
- unknown U2: baseline promise.get()/fast.join() не прерывают зависший
  синхронный vendor/Storage вызов; реальное зависание не воспроизводилось.
- unknown U3: bool online не выражает unknown; подтверждённая ёмкость/процент
  при неизвестном AC приводят к ложной подписи «от батареи»/online=false в JSON.
- unknown U6 / HYD-04 / GM6-03: диагностический primary disk value может остаться
  от Storage property, но source изменяется на SMART. Отдельные raw rows верны.
  У обычной UI-карточки с успешной property-temperature этот SMART путь пропущен.
- HYD-01: settings export не включает hydroc16g2-device-settings.ini.
- HYD-03: HYDROC counts0→0 фиксированы, а report452 называет их общими EC counts
  с учётом независимого online. Read-only snapshot действительно не пишет;
  отсутствие любых других записей приложения этими константами не измерено.
- GM6-01: settled означает стабильность положительных RPM после30с,
  но Gm6Controller превращает его в fanResponseConfirmed. Это не доказательство
  исполнения Max; рост RPM не обязателен, если исходное состояние уже Max.
