# Числовой ввод GM6/общий Windows-контрол

По дополнительным скриншотам пользователь не может набрать100, хотя стрелки
устанавливают100. Причина в общем createNumericFieldWindows: однострочный EDIT
без ES_AUTOHSCROLL ограничивает ручной ввод видимой шириной. Добавлен стиль,
сохранены границы, шрифт, отступы и спин-кнопки. Исправление распространяется
на всех потребителей общего numeric factory, в том числе CPU PL.

FANs больше не коммитит промежуточный текст активного EDIT на каждый EN_CHANGE
для температуры/обычного Manual: ранее исключение было только для EC Manual PWM.
Commit/save остаётся на потере фокуса, стрелках, колесе и явных действиях FANs.
Значения не применяются к EC самим фактом ввода цифры.

Пульсация GM6: текущий подтверждённый OEM интерфейс — четыре индекса1–4,
а не произвольный RGB. KeyboardPulsePalette намеренно не присваивает этим
индексам выдуманные физические цвета. «Свой цвет» применяется к Mono; hardware
палитра пульсации требует подтверждения соответствия четырёх цветов. Запрошено
у владельца. Эта сборка не объявляет произвольный RGB в GM6 Pulse поддержанным.

Новых аппаратных запусков, UI/EC тестов нет. Проверка — сборка обеих ОС,
обновление portable и SHA256. Прокрутка/геометрия не менялись.

Документация Microsoft подтверждает ограничение видимой шириной для single-line EDIT без ES_AUTOHSCROLL: https://learn.microsoft.com/en-us/windows/win32/controls/about-edit-controls#scrolling-styles
