# Поиск независимого автоотключения подсветки — 13.10.2026

## Интерфейс

В общий макет Windows/Linux добавлена строка `Погаснуть [галка] [поле ↕] сек`.
Галка и поле неактивны, пока не установлен аппаратный способ управления.
Они не меняют `0x741`, не выдают неподтверждённое значение за текущую настройку
и не сохраняют фиктивный параметр в конфигурацию.

## OEM SingleZone: подтверждённая цепочка

Исходники: `C:/Users/admin/Documents/mechrevo/Decompiled/DefaultTool/`.

- `LightingModel/LM_EC_RGB.cs:43`: `0x766 & 0x04` выбирает `SingleZone`.
- `MyControlCenter/KeyboardCloseTimer.cs:109`: число секунд сохраняется
  в `_Seconds`, затем `EnableCloseTimer()` задаёт `_TimersTimer.Interval = _Seconds * 1000`.
  Это `System.Timers.Timer` процесса, а не запись времени в EC.
- `MyControlCenter.MyRgbKeyboard/SingleZone.cs:117`: событие таймера вызывает
  `SetPowerDisable_EC(true)`; обратное событие включает питание подсветки.
- `SingleZone.cs:367`: `SetPowerDisable_EC()` читает адрес 1932 (`0x78C`),
  меняет только бит 1 и записывает результат обратно. Яркость 5–7 сохраняется.
  Это команда немедленного выключения/включения, а не уставка простоя.

## Аппаратный таймер ITE/HID: другая ветка

`LightingModel/LM_ITE_RGB.cs:1098`, `HID_Set_TimeOut_1AH()` отправляет через
`m_HIDManager.WriteFeature()` пакет:

```text
00 1A control enable time 00 00 00 save
```

Здесь есть параметры `enable`, `time`, `save`, но единицы `time` по одному
этому методу не установлены. Команда не является записью в RAM EC.
`LM_Manager.cs` выбирает ITE/HID и EC как разные реализации.
В текущем PnP-инвентаре отсутствует устройство с `VID_048D`; перечислены
HID-коллекции `UNIW0001` на I2C. Применимость пакета 1A к нашей SingleZone
не подтверждена. Пакет не отправлялся.

## Linux и ACPI

- [Текущий uniwill-acpi.c](https://raw.githubusercontent.com/torvalds/linux/master/drivers/platform/x86/uniwill/uniwill-acpi.c):
  `uniwill_ec_init()` устанавливает `ENABLE_MANUAL_CTRL` в `0x741`,
  а `uniwill_disable_manual_control()` снимает его при освобождении драйвера.
  Это подтверждает общий срок владения приложением/драйвером, а не независимую
  настройку автоматического гашения.
- [Текущий TUXEDO uniwill_keyboard.h](https://raw.githubusercontent.com/tuxedocomputers/tuxedo-drivers/main/src/uniwill_keyboard.h):
  включение/выключение подсветки меняет бит 1 регистра её состояния;
  при инициализации/удалении меняется также `0x741`. Отдельная уставка
  клавиатурного timeout в просмотренном файле не найдена.
- Сохранённая `out/test_util/analysis/EC_20261012_073054/acpi/DSDT.dsl`
  предоставляет `ECRR/ECRW` для окна `0xFED50000/4096`. В объявлении полей
  не указаны адреса `0x741` и `0x78C` и не обнаружена именованная уставка
  времени клавиатуры. Наличие универсального доступа само по себе не раскрывает
  назначение остальных байтов.

## Вывод и дальнейший путь

Найдена поддерживаемая OEM команда немедленного гашения через `0x78C.1`.
Подтверждённый регулируемый таймер для SingleZone живёт в программе.
Отдельный аппаратный флаг автоотключения и числовая уставка времени для
этой платы пока не установлены. Полный перебор 0x741 при `.0=1` уже показал,
что `.2` возвращается в 0, а `.7` — в 1; он не открыл независимую настройку.

Для дальнейшего аппаратного поиска нужен код EC этой платы либо документированная
команда её прошивки. Исследованный `Research/BIOS_OTA_Full` содержит разбор
загрузчика/обновлятора BIOS, а не найденный образ EC N.1.20MRO15.
Наличие штатного таймера ~31 с не доказывает наличие доступной для записи
уставки: интервал может быть константой кода прошивки.

В этом проходе выполнены статический поиск, чтение PnP-инвентаря и сборка UI.
Новых аппаратных записей и повторного перебора EC не было.

## Уточнение по питанию AC/DC

Пользователь сообщил: сейчас от сети свет не гаснет, от батареи гаснет.
Это физическое наблюдение требует различать простой клавиатуры и фактическое
выключение светодиодов; прежний вывод о безусловном гашении при `.0=0` был неполным.

В новом журнале `MagicControl-2.jsonl`, начатом 13.10.2026 в 15:36:34 МСК,
бит `0x741.0` равен 0 при обоих источниках питания. При AC встречаются
`0x741=0x80` и `0x84`. Следовательно, если видимое свечение при AC сохраняется,
самого `0x741.2=1` недостаточно для вывода о физическом гашении.

Повторное сравнение ранее сохранённой полной серии из 301 кадра (41 кадр AC,
230 кадров DC после исключения переходных участков) сохранено в
`ac-dc-native-comparison.json`. В ней:

| Регистр | AC | DC |
|---|---|---|
| 0x741 | 0x84 | 0x80, 0x84 |
| 0x78C | 0x80 | 0x80 |
| 0x767 | 0x80 | 0x80 |
| 0x7CC | 0xA4 | 0x80 |

У `0x7CC` меняются признаки подключённого порта, но бит 7 остаётся 1.
Кнопки «Батарея/Сеть» в текущем UI отключены и лишь показывают интерпретацию
этого бита. Они не переключали наблюдаемое поведение.
[В ядре Linux](https://raw.githubusercontent.com/torvalds/linux/master/drivers/platform/x86/uniwill/uniwill-acpi.c)
бит 7 определён как `USB_C_POWER_PRIORITY`, значения названы `charging` и
`performance`. Это не подтверждение переключателя общего энергосбережения
на X5SP4NAG; OEM `GetTypeCAdaptorPrioritySupport()` возвращает false.

Гипотеза о штатном гашении только при DC согласуется с новым наблюдением,
но другие функции экономии и отдельный управляющий флаг пока не установлены.
Наблюдаемые различия AC/DC сами по себе не дают оснований записывать в
кандидатные регистры: среди них находятся текущие состояния питания и батареи.
