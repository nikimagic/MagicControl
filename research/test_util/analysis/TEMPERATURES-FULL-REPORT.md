# Полный разбор: температуры CPU, GPU, памяти, диска и NPU

Источники: 11 дампов из `out/test_util/logs` (5 запусков Windows с 4-КБ снимками
EC, 6 запусков Linux), ACPI-таблицы DSDT/SSDT из `technical.json`, прошлые разборы
в `firmware_temperatures/` и `temperature_review/`. Только чтение сохранённых
логов, обращений к железу нет.

## Итоговая таблица

| Узел | Где читается | Адрес / канал | Значения в логах | Готово к показу |
|---|---|---|---|---:|

## Память: две планки, два независимых датчика

Модули DDR5 содержат SPD Hub с датчиком температуры по стандарту JEDEC. Читается
через SMBus: адреса `0x50` и `0x51`, регистр `0x31`, формат — 16-битное слово,
старшие 4 бита которого несут знак и признак диапазона, остальное — значение в
шаге 0,25 °C. Сырые слова из логов: `624` → 39,00 °C и `596` → 37,25 °C.

- `0x50`: 37,25–61,25 °C, среднее 45,75 °C
- `0x51`: 35,75–61,25 °C, среднее 45,06 °C

Значения совпали лишь в 14 случаях из 110, разница доходит до 1,75 °C. Значит это
**два отдельных физических датчика**, по одному на планку, а не один, прочитанный
дважды. У машины два слота SODIMM, и лог `technical.json` подтверждает две планки.
В телеметрии UI уже есть строка `DDR5=44,5/44,5C`.

## Диск: два канала, второй требует оговорки

NVMe-накопитель отдаёт три индекса температуры. Сырые значения приходят в
кельвинах: `314` → 40,85 °C, `304` → 30,85 °C.

| Индекс | Значение | Уникальных значений | Замечание |
|---|---:|---:|---|
| 0 | 41 °C | 2 | основной; то же, что composite |
| 1 | 41 °C | 2 | **побитовая копия индекса 0** во всех 110 снимках |
| 2 | 29–36 °C | 8 | отдельный, живой канал |

Индекс 1 повторяет индекс 0 **в каждой точке**, поэтому это одно показание, а не
второй датчик: показывать оба нельзя. Индекс 2 меняется независимо и, судя по
адресу, относится к памяти накопителя, но **какому именно узлу он соответствует,
спецификация NVMe не фиксирует** — порядок сенсоров задаёт производитель. Поэтому
подпись должна быть нейтральной («датчик 2»), а не «NAND» или «контроллер».

Контроллер сообщает температуру с шагом 1 °C (8 уникальных значений в узком
диапазоне), поэтому 0,85 в дробной части — следствие пересчёта из кельвинов, а не
точность измерения.

## Прошивка: температур памяти и диска в EC нет

Проверено прямым поиском, а не по смыслу. Каждый из 4096 байт EC имеет собственное
время съёмки, поэтому многосекундный снимок не считался мгновенным: опорный канал
интерполировался на время каждого байта, затем считалась корреляция. Условия
отбора: не меньше 6 кадров, корреляция ≥ 0,98, наклон 0,9–1,1, диапазон 20–80 °C.

| Опорный канал | Адрес EC | Что это |
|---|---|---|
| CPU Tctl/Tdie | `0x43E` | подтверждено |
| CPU ADL | `0x43E` | тот же регистр |
| GPU GFX | `0x43E` | тот же регистр кристалла, **отдельного датчика GPU нет** |
| DDR5 0x50 | — | совпадений нет |
| DDR5 0x51 | — | совпадений нет |
| SSD индекс 0 | — | совпадений нет |
| SSD индекс 2 | — | совпадений нет |

То есть `0x43E` — это единственный температурный регистр EC, и он относится к
кристаллу CPU. Совпадение с GPU объясняется тем, что Radeon 880M находится на том
же кристалле и греется вместе с процессором; считать `0x43E` датчиком GPU нельзя.

Это согласуется с прошлым разбором ACPI: поле `VGAT` (`0x44F`) существует, но во
всех 110 снимках равно нулю, а `SOCT`, `SOCE`, `VDDT`, `VDDE` нулевые и не имеют
кода перевода в градусы. Память и диск управляются вне EC — память через SMBus
напрямую, диск через свой контроллер.

## NPU: температуры нет

Ни один источник её не публикует:

- в AMD PMLog температурные каналы NPU неподдерживаемы либо отсутствуют, а
  неизвестных поддерживаемых слотов в собранном PMLog нет;
- в уникальных DSDT/SSDT есть устройство `IPU`, но ни одна таблица не публикует его
  температуру;
- отчёты AMD XRT содержат версию драйвера и устройства, но не термальный параметр.

Что есть по NPU: загрузка `NPU_BUSY_AVG`, слот 72 — **0 % во всех 110 снимках**;
частота `CLK_NPUCLK` / `NPUFrequency` — 0–800 МГц. Подменять температуру загрузкой
или температурой SoC нельзя. Чтобы проверить существование скрытого датчика, нужен
отдельный сбор **под нагрузкой именно на NPU** с одновременной записью EC, ADL,
ADLX и XRT: под нагрузкой датчик может появиться в списке поддерживаемых.

## Linux

В Linux-логах температурных каналов нет вообще: собраны только `Linux proc`,
`Linux power_supply` и `Linux hwmon / BAT1` (напряжение и мощность батареи). Это
чистый WSL без доступа к железу. Для Linux-версии все пять узлов придётся
реализовывать заново: CPU — `k10temp`, память — драйвер `spd5118` (даёт
`temp1_input`), диск — `nvme` (`/sys/class/nvme/nvme0/device/hwmon*/temp*_input`),
GPU — `amdgpu` (`hwmon`), NPU — отдельного канала нет.

## Что можно показывать в UI

**Показывать:** CPU (Tctl/Tdie), GPU (GFX), память — два значения по плашкам,
диск — индекс 0 и индекс 2 с нейтральными подписями.

**Не показывать:** индекс 1 диска (копия индекса 0); температуру NPU (её нет);
`0x43E` как отдельный датчик GPU (это кристалл CPU).

**Подписи источников:** «PawnIO · Tctl/Tdie», «AMD ADL · GFX»,
«SMBus 0x50 · SPD» и «SMBus 0x51 · SPD», «NVMe · composite» и «NVMe · датчик 2».
