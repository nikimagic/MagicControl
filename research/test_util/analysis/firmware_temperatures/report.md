# CPU, GPU, SoC и NPU: разбор дампов

Источник: 110 снимков Windows из пяти запусков переносимой Test_util,
включая по 4096 байт EC в каждом снимке, прямые каналы AMD ADL/ADLX, PawnIO,
WMI ACPI thermal zone и сохранённые отчёты AMD XRT. Сенсорные чтения сопоставлены
внутри запуска по UTC; EC сканируется по времени каждого байта, без выдуманного
предположения, что многосекундный снимок атомарный.

| Узел | Подтверждённый канал | Значения в логах | Вывод |
|---|---|---:|---|
| CPU | PawnIO / AMD SMN `0x59800` (Tctl/Tdie) | 31,75–56,875 °C | Прямое CPU-значение; коррелирует с ACPI CPU thermal zone и EC `CPTM` |
| CPU, резерв | AMD ADL PMLog `TEMPERATURE_CPU`, 32 | 30–53 °C | Во всех 110 снимках ниже Tctl/Tdie: средняя разница 2,809 °C, максимум 6,875 °C |
| GPU | AMD ADL PMLog `TEMPERATURE_GFX`, 28 | 30–56 °C | Поддерживаемое значение; согласуется с AMD ADLX |
| GPU, сверка | AMD ADLX `GPUTemperature` | 30–55 °C | Разница ADLX−GFX: −4…+1 °C; 109 из 110 снимков в пределах 1 °C; систематического занижения GPU нет |
| SoC | AMD ADL PMLog `TEMPERATURE_SOC`, 29 | 31–54 °C | Поддерживаемый отдельный канал температуры SoC |
| NPU | ADL `NPU_BUSY_AVG`, 72; ADLX `NPUActivityLevel` / `NPUFrequency` | загрузка 0%; частота 0–800 МГц | Температуры NPU эти снимки не содержат; XRT-отчёты не содержат строки датчика температуры |

## Что показала прошивка

В реестре Windows сохранились оригинальные ACPI AML-таблицы из `technical.json`.
Уникальные DSDT и две SSDT сохранены в этой папке с SHA-256 в `manifest.json`;
30 одинаковых копий SSDT удалены только из аналитической подборки. Таблицы
дизассемблированы Intel ACPICA `iasl`. Поиск строк и методов находится в
`acpi-temperature-references.txt`; полный числовой перебор в EC выполняет
`scan_thermal_channels.py`.

- **`CPTM` → EC/ACPI `0x43E`**: DSDT объявляет поле как CPU thermal-control
  temperature. Значения регистра 32–56 °C в точности совпадают с известной
  CPU-температурой EC и находятся в среднем в 0,431 °C от Tctl/Tdie по 105
  временно согласованным снимкам (корреляция 0,9984). Это CPU-показание, не
  отдельный датчик GPU, SoC или NPU.
- **`VGAT` → `0x44F`**: поле присутствует, но все 110 значений равны нулю.
  Это не пригодная текущая температура. Отдельный GPU GFX уже читается из ADL.
- DSDT объявляет **`XHPP` `0x3E`**, **`VDDT` `0x77`**, **`VDDE` `0x78`**,
  **`SOCT` `0x79`** и **`SOCE` `0x7A`** в пространстве ACPI `EmbeddedControl`.
  Их нельзя путать с теми же низкими смещениями в `SystemMemory`/MMRB.
  Сохранённый 4-КБ дамп считывает MMRB (`0xFED50000`), а не весь диапазон
  `EmbeddedControl`; поэтому нулевые MMRB-байты около `0x477–0x47A` ничего не
  говорят о значениях этих полей EC. DSDT не задаёт им градусы или масштаб и не
  использует `SOCT/SOCE/VDDT/VDDE` как возвращаемые температуры. Их точное
  назначение по одним именам не подтверждено.
- ACPI `ECTZ._TMP` вычисляет термальную зону из поля `XHPP`; WMI сообщает
  `ECTZ_0` в диапазоне 32,05–57,05 °C. В 105 совпавших кадрах она отличается от
  CPU Tctl/Tdie в среднем на 0,775 °C и коррелирует с ним (`r=0,9859`). `TZ01_0`
  повторяет те же WMI-значения с расхождением не больше 0,0011 °C; оснований
  считать её вторым физическим датчиком нет. Её `_TMP` найден в доступном DSDT
  не был, поэтому имя WMI само по себе не идентифицирует отдельный компонент.
- **NPU**: уникальные DSDT/SSDT содержат устройство `IPU`, но ни один из них не
  публикует его температуру. В AMD PMLog все названные температурные каналы
  NPU неподдерживаемы либо отсутствуют; неизвестных поддерживаемых слотов в
  собранном PMLog нет. В XRT-отчётах есть версия NPU-драйвера и устройства, но
  нет термального параметра. Все 110 кадров NPU простаивает (`0%`), поэтому
  по этим данным нельзя исключить скрытый датчик, который проявляется только
  под нагрузкой.

## Поиск по всем числовым форматам EC

Скрипт читает все 110 сохранённых 4-КБ снимков, перебирает выравнивания и окна
по 1/2/4/8 байт, знаковые и беззнаковые little/big-endian int, float и double.
Для целых проверяются масштабы `1`, `1/2`, `1/10`, `1/100`, `1/256`.
`ec_temperature_sparse_candidates.csv` содержит все динамические адреса,
которые попали в 30–70 °C как минимум в 6 снимках и изменились не менее чем на 1 °C, с количеством кадров, диапазоном
и лучшим совпадением. `thermal_channels.json` включает частоту случайных
попаданий по каждой интерпретации, лучшие сопоставления и состояния каналов.

Самое сильное совпадение во всех форматах — адрес **`0x43E` / DSDT `CPTM`**:
105 временно сопоставленных снимков, MAE 0,431 °C к прямому PawnIO Tctl/Tdie,
`r=0,9984`. Некоторые многобайтные варианты начинаются с `0x43D`, но этот адрес
не самостоятельный датчик: окно перекрывает следующий байт `CPTM` `0x43E`.
Остальные числовые кандидаты не имеют подписанного поля датчика и не достигают
этой точности; совпадения температуры по одному диапазону не объявляются
датчиками. Динамических float/double-каналов в диапазоне 30–70 °C не найдено.

Полный список **533 объявленных полей и зарезервированных участков** DSDT,
включая размеры и адресные пространства, находится в
[`dsdt-fields.md`](dsdt-fields.md); CSV содержит все записи, в том числе
смещения битов, динамические контексты и строки исходного ASL. OperationRegion
вынесены в `dsdt-regions.csv`.

Для повтора из корня репозитория:

```text
python research/test_util/analysis/scan_thermal_channels.py
```

## Полный перечень полей DSDT

В DSDT объявлены 469 именованных полей, 58 зарезервированных областей и шесть
IndexField без фиксированного адреса. [Полный список полей](dsdt-fields.md) показывает
регионы, address space, bit offsets и адреса, которые можно вычислить; [CSV](dsdt-fields.csv)
содержит те же данные в машиночитаемом виде. `ECMG` (SystemMemory от `0xFED50000`)
и `ECXP`/`ECMP` (EmbeddedControl от нуля) перечислены отдельно. Запись ASL сама
по себе не гарантирует, что поле физически отвечает в каждом режиме.

## Что можно показывать в UI

CPU — PawnIO Tctl/Tdie; SoC — AMD `TEMPERATURE_SOC`, 29; GPU — AMD
`TEMPERATURE_GFX`, 28. EC `0x43E` можно оставить отдельной проверочной метрикой
CPU. `VGAT` пока показывать нельзя: он равен нулю. Для NPU температура в этих
логах не обнаружена; её нельзя заменять температурой SoC или числом загрузки.
Чтобы проверить канал NPU, нужен следующий сбор с включённой именно NPU-нагрузкой
и одновременными ADL/ADLX/XRT/EC снимками.
