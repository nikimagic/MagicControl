# Контракт общего BIOS/SPI collector по итогам исследования

Это спецификация, не внесённая в production реализация.25.10.2026.
Новых аппаратных обращений/билдов нет. Действующая версия portable0.1.189.

## Одна реализация сбора, несколько транспортов

`BiosCaptureService` отвечает за identity, каталог результата, два прохода,
журнал, размер/coverage, сравнение и manifest. `BiosCaptureBackend` отвечает
за конкретный доступ: существующий AFU, Intel FPT, разрешённый native Intel
SPI, AMD ROM2/ROM3, Linux MTD, отдельный EFI/внешний путь. Название модели
задаёт подтверждённые данные/возможности, не копию collector.

Выбор опирается на фактические CPU/PCH/PCI/BIOS identity и поддержанные
возможности, не на выбранную preview-модель и не только на строкуAMI.
Никаких запусков по кругу старых драйверов в надежде, что один сработает.

## Минимальные типы результата

- `spi_full`: установлена область всего целевого flash/компонентов и успешное
  чтение её диапазонов. Запрошенный размер не является достаточным критерием.
- `bios_region`: полезное чтение BIOS-региона при неизвестной/недоступной
  остальной SPI. Сохраняется успешно как регион, full SPI не объявляется.
- `rom_window`: конкретное адресное окно с известной базой/размером; отдельные
  доказательства нужны для соответствия целому flash.
- `firmware_volumes`: набор FV через протокол; отдельно от physical SPI.
- `update_package`: файл производителя/распакованные компоненты, не live dump.
- `partial` и `unsupported`: байты/журнал сохраняются, полнота не подменяется.

## Метаданные

В manifest нужны независимо:

- фактическая identity, версия приложения, UTC/местное время;
- backend/tool/module/driver версии, происхождение, SHA и signature result;
- запрошенная операция и фактическая командная строка/транспорт;
- chip count/ID/capacity, источник определения размера и уверенность;
- адресное пространство и base/length каждого компонента/региона;
- read permissions, успешные/непрочитанные/неизвестные диапазоны;
- raw status/error/output, offsets и timestamps, без скрытого усечения;
- каждый pass file/bytes/SHA, карта различий и итог проверки;
- `capture_saved`, `capture_complete`, `two_passes_equal` отдельно;
- отдельно `ec_ram_captured`/`live_ec_flash_captured` и наличие embedded update
  payload, чтобы main SPI не подменял дамп постоянной памяти отдельного EC.

Размер: JEDEC/SFDP или иное независимое hardware evidence предпочтительны;
Descriptor/straps/протокол/SMBIOS/файловый анализ сохраняются с указанием
источника. Повторяющееся содержимое ROM3 и SMBIOS не выдаются за новый JEDEC
опрос. Допускается подтверждённое окно/корроборированный ожидаемый размер
без опасного дополнительного probing только ради более сильного ярлыка.

## Чтение и ошибки

Для каждого блока сохранять исходный offset/length/result. Нельзя сдвигать
следующие успешные байты к предыдущим при ошибке, как это возможно при простом
append, и нельзя заменять их прошлым чтением из display continuity cache.
Телеметрийный cache не участвует в дампе.

Верхний слой должен понимать, когда vendor file содержит заполнение/пропуск
или когда coverage неизвестен. Не превращать FF/00-подстановку в измеренные
байты. Сохранить исходный vendor file и отдельную validity map/диагностику.
Не достраивать полный live SPI из старого Descriptor/ME и свежего BIOS-region.

Два прохода нужны для сравнения. Одинаковый SHA не доказывает полноту;
различающийся SHA не всегда доказывает повреждение, поскольку NVAR/ME data
могут изменяться. Сохранять оба образа, сравнивать диапазоны, структуры и
стабильные участки. Подтверждать ровно то, что измерено.

## Разделить read cycle и изменение политики

SPI read требует временных записей адреса/opcode/count/start в контроллер.
Это отличается от erase/program, изменения BIOSWE/BLE/protection/clock,
ROM-ID, EC flags или persistent firmware writes. Read-only API допускает
только необходимые проверенные read cycles, а не общий programmer init,
пытающийся открыть запись. Прочитанный rflasher constructor и flashprog
init нельзя автоматически считать допустимыми для этого контракта.

На Windows отсутствие kernel admission остаётся отказом. Никакого автоматического
TESTSIGNING, отключения SecureBoot/HVCI, перехода на unrestricted PawnIO,
перезапуска/замены чужого WNPDriver или OEM-защит. Эти действия не выполнялись.

## Процесс и интерфейс

Рабочий AFU/backend сохраняется. Общая кнопка INFO получает результат общего
сервиса. Геометрия карточек, header, scroll, preview остаются по существующему
контракту; backend не имеет собственного окна/контролов.

Progress считает фактические байты/проходы, не рисует процент по неподтверждённому
SMBIOS. stdout/stderr читаются так, чтобы pipe не тормозил vendor process;
сохраняются полностью с отдельным журналом событий. Отмена/ошибка сохраняют
уже собранные данные. Завершение процесса/драйвера должно соблюдать владение,
а не убивать чужие программы или оставлять неподтверждённое состояние.

Результат доступен для проверки до дальнейших разрешений на оборудование.
Текущий документ не разрешает новый live-run и не является его выполнением.
