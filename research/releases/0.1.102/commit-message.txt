MagicControl 0.1.102: проверенные архивы Windows/Linux без публикации

По отдельному поручению пользователя подготовлены локальные ZIP/TAR.GZ и
распакованные каталоги0.1.102 в GitHub_Releases. Публикация, push и создание
GitHub release не выполнялись. Публичная версия остаётся0.1.90; локальный
README явно отделяет подготовленные пакеты от опубликованного выпуска.

Стандартный Tools/Package-Releases.py упаковал точную исходную ревизию
d7f2354863d52e75f8a700145af01b6f05ec78dc. Оба build-info указывают чистые
входы приложения, фактическую версию и исходный SHA256 GUI. Рабочие portable
не изменялись упаковкой; Linux GUI strip выполнен только внутри пакета.

Обновлены канонические README обеих ОС: пять профилей, INFO, четыре языка,
Noto Sans SC/TC, действующие правила обычного и трёхэтапного read-only дампа,
выбор GPU по маршруту дисплея и аппаратные ограничения. Убраны исторические
противоречия старых описаний0.1.69. Дополнены TC notices и канонический Linux
THIRD-PARTY-NOTICES. Правило -text сохраняет байты подготовленных пакетов,
INF/манифестов и других файлов0.1.102 при работе Git.

Release notes описывают накопленные изменения после0.1.90 и прямо фиксируют
неудачу GM6: readback85/80 удерживался, но при86–87% шла зарядка18–21Вт.
Новая версия не объявляет отсечку исправленной. HYDROC, другие пороги,
возобновление и единицы температуры требуют дополнительных данных.
Новые SOC/Turbo политики Wujie не включены.

Сохранено дополнительное исследование родных Wujie power/Overboost цепочек:
7A5.7/7A5.4 и инверсный7A6.1, различия RAM1.5 и старой Intel-ветки,
отсутствие установленного точного порога SOC и длительности Turbo. Отрицательный
поиск в host C# не опровергает работу политики внутри EC-прошивки.

PawnIO/Uniwill, лицензии, отсутствие CLI/личных настроек/логов/дампов/исходников,
