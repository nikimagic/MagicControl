HPBSD BIOS 1.06: режимы и переключение — продолжение, 28.10.2026

Только статическое исследование сохранённого BIOS, EC-кандидата и ранее
полученных отчётов. На мини-ПК, EC и SMU ничего не запускалось и не писалось.

1. РЕЗУЛЬТАТ

Штатные лимиты STAPM / Slow PPT / Fast PPT для Balance и Performance пока
не установлены. Найдена более полная статическая цепочка выбора двух FAN
таблиц и сохранения/синхронизации режима. Перенос этого пути в продукт без
подтверждения действующего EC и сохранения состояния был бы преждевременным.

2. ЦЕПОЧКА BIOS -> EC-КАНДИДАТ

IFR exact HPBSD BIOS: Setup переменная EC87D643-EBA4-4BB5-A1E5-3F3E36B20DA9,
поле +0x2D, 1 = Balance, 2 = Performance. Suppress/grayout — условия форм,
а не подтверждение доступности или недоступности в действующем UI.

OemPei.te.asm:
- EBP-0xD8 — буфер Setup; чтение EBP-0xAB соответствует +0x2D.
- BIOS проверяет CMOS index 0x63 (порты 0x70/0x71). Значения A0/A1/A2
  попадают в отдельную ветку и дают команду B0/B1/B2 на порт 0x66;
  иначе 0/1/2 в Setup ведут к соответствующим B0/B1/B2.
- OemDxe.pe.asm синхронизирует эту CMOS-пару с Setup+0x2D; полный жизненный
  цикл и актуальная сторона истины в работающей ОС не подтверждены.
- Значит, одна разовая EC-команда не доказывает сохранение выбранного режима
  в BIOS/CMOS и поведение после перезагрузки.

В извлечённом 128-КиБ EC-кандидате SHA256
15fb6994c9c5292df51441cf49b876070785f95314efe02a03fea3c55065a994:
- helper 0x5019 выбирает запись из таблицы по байту R7. У 0xD7A3 сохранены
  тройки D8 10 B1 и D8 17 B2: B1 -> 0xD810, B2 -> 0xD817.
- 0xD810/0xD817 записывают B1/B2 в XDATA 0x832F, затем вызывают 0x9DF7,
  где для этих значений выбираются разные таблицы CPU FAN.
- Оба обработчика затем переходят к 0x9FAF. Он перезаписывает системную
  FAN-таблицу XDATA 0x8330..0x8338 и вспомогательные поля 0x88C0..0x88C2.
  Значения включают 0/25/0, 15/83/25, 40/100/83. Это сырые поля таблицы,
  не измерение PWM. Выбор режима затрагивает ОБА FAN-направления.
- Внешний порт 0x66 прослежен в OemPei, а входной байт R7 — в EC dispatcher;
  полную аппаратную доставку между ними на действующем устройстве не измеряли.
  XDATA и Windows I2EC имеют разные адресные представления.

3. ПОИСК ЧИСЕЛ МОЩНОСТИ

В 10 уже извлечённых исполняемых секциях BIOS выполнен поиск 32-битных
little-endian литералов 35000, 45000, 54400, 60000, 65000. Результаты
и SHA источников — EVIDENCE.json. 54400 не найден; отсутствие литерала
не исключает вычисление, другие кодировки или другие модули.

В AmdNbioPei около 0x9AC8430 и 0x9AC8484 обнаружены последовательности
60000 / 45000 / 35000, передаваемые с токенами 0x250 / 0x251 / 0x252.
Значения видны в двух соседних условных ветках. Значение токенов и их
привязка к Setup+0x2D/SMU не установлены. Нельзя объявлять эти числа
ваттами или считать их профилями Balance/Performance по совпадению порядка.
Найденное в секции другое совпадение 65000 также не атрибутировано профилю.

Ранее наблюдавшиеся 54.4 / 60 / 65 Вт — STAPM / Slow / Fast одной сессии.
Ранее проверенные 20 / 25 / 30 и 8 / 10 / 12 Вт — пользовательские ручные
установки. Ни одна тройка не доказана как конкретный штатный профиль.
Windows в сохранённой проверке не прочитала Setup с Win32 error 203.
Несколько копий этой переменной в образе имеют значения 0/1; по одному
порядку вывода нельзя установить активную или заводскую копию.

4. ЧТО НУЖНО ДЛЯ ПРАВИЛЬНОГО ПЕРЕКЛЮЧЕНИЯ

Уже установлены названия BIOS и статические FAN-ветви. Для настройки ядра
необходимо определить отдельно:
- фактический действующий режим и переход на аппаратуре данной BIOS/EC;
- STAPM, Slow, Fast и поведение под нагрузкой для каждого штатного режима;
- влияние на CPU/system FAN, защитную ступень, активный Manual и ownership;
- синхронизацию Setup и CMOS и сохранение после reboot/resume;
- поведение при потере владения и невыполненном readback/rollback.

Доступное сейчас безопасное направление — сравнить сохранённые пользователем
логи разных BIOS-состояний или, при отдельном решении владельца, собрать A/B
read-only снимки после ручного выбора каждого режима в BIOS. Не утверждать
штатные значения по другой модели; не автоматически отправлять B1/B2,
не записывать Setup/CMOS и не подменять подтверждённые ручные лимиты.
