3. Цепочка доступа EC
GCUService / DefaultTool -> MyECIO.MyEcCtrl -> MyECIO.AcpiCtrl ->
Windows DeviceIoControl -> \\.\ACPIDriver -> UWACPIDriver.sys -> ACPI/EC.

Сверено тремя независимыми частями пакета:
- DefaultTool: читаемые C# методы Read/Write/ReadACPI/WriteACPI;
- native ACPIDriverDll.dll: дизассемблированные экспорты ReadEC / WriteEC;
- native SYS: dispatcher сравнивает эти же IOCTL.
EC read:  0x9C40A488.
EC write: 0x9C40A48C.
DefaultTool byte reader: вход DWORD address (4 байта), ответ DWORD (4 байта),
берётся младший байт; writer: два DWORD address/value (8 байт), ответ4 байта.
Native DLL использует огромные общие буферы по0x400000; это особенность wrapper,
не требование читать4МиБ EC. В драйвере есть и дополнительные CM/MMIO/PCI/IO,
SmartAPC/custom команды. Их наличие не означает универсальный безопасный доступ.
Доказательства: ACPIDriverDll-ioctl.asm, UWACPIDriver-ioctl.asm и
 decompiled-interfaces/MyECIO.AcpiCtrl.cs.

7. Кандидаты чтения identity и функций
Из читаемого DefaultTool:
- Project ID: EC0x740;
- BIOS project ID: EC0x74C, маска4/6бит зависит от признака поддержки;
- RamFan1.5 support:0x78E.bit6;
- LC fan table support:0x7C8.bit5;
- keyboard type дополнительно зависит от EC0x73C и firmware ITE.
ECSpec содержит tach Main0x464/0x465, Second0x46C/0x46B,
Duty L/R0x75B/0x75C. Реальные роли каналов и масштаб PWM HYDROC не измерены.
register-candidates.json содержит249 констант с источниками и строками;
все помечены confirmed_on_hydroc=false.

Пакет поддерживает RamFan1, RamFan1.5, RamFan2 и LC-ветви.
RamFan2 имеет карты для трёх физических fan tables с отдельными CPU/GPU
температурными кривыми и duty: это не побайтовая карта двух каналов GM6.
Из защищённого GCUService пока не доказано, какую ветвь выбирает HYDROC.
JSON UserFanTables содержит разные семейства и общие DefaultFanTable:
они не объявляются считанной заводской таблицей этого HYDROC.

8. Подсветка
DefaultTool содержит нормальный исходный путь ITE HID:
HIDManager -> штатные hid.dll / SetupAPI -> VID048D, Usage1.
Keyboard PID candidates: CE00,6000,6001,6002,6003,6004,6006,6007,600A,600B.
Lightbar PID candidates:7001,7000,6005,6008,6010.
Тип выбирается по UsagePage FF12/FF02/FF03, firmware revision и EC subtype.
Есть firmware version getter и HID feature reports; данные выбираются до setter.
Перечень эффектов включает static, breathing, rainbow, ripple, raindrop,
aurora, neon, music, custom и другие. Наличие эффекта в общем коде не
подтверждает поддержку любой конкретной HID firmware HYDROC.
Свойства HID устройства данного ноутбука пока не предоставлены.

9. Графика и MUX
GPUInfoDLL.dll экспортирует GetNVTemperature / GetNVGpuInfo / GetNVPState,
SetNVGpuCoolerLevels / SetNVGpuFanPolicyControl, а также OC/Whisper/thermal APIs.
Нативный GetNVTemperature использует NVAPI thermal settings version2.
Наличие setters не доказывает возможность управления вентилятором RTX5090:
нужны реальные ответы getters, поддержка policy и возможность возврата.

DGgpuDirectConnectionMode содержит Intel iGPU_only=1, dGPU_only=2, Dynamic=4.
В структуре NVRAM есть OemDisplayMode. UEFI_Firmware.dll импортирует
GetFirmwareEnvironmentVariableW / SetFirmwareEnvironmentVariableW.
В бинарнике найдены OemMagicVariable / UniWillVariable / OemMagicDoor и GUID
{9f33f85c-13ca-4fd1-9c4a-96217722c593}.
Это путь к политике UEFI, а не доказанный Runtime D3 или мгновенное переключение.
DefaultTool декларирует также некоторые P/Invoke, которых нет в экспортах
соответствующей DLL: декларацию саму по себе нельзя считать рабочим API.

10. CPU, батарея и связь служб
IntelOverclockingSDK — .NET клиент, а не SYS драйвер.
Мониторинг через net.pipe://localhost/ExtremeTuningUtility/Monitoring;
есть отдельные Event и ServiceInfo endpoint, поле IocbiosDriverVersion.
Файла IOCBIOS/XTU SYS в распакованном комплекте не найдено.
Это не означает, что такой драйвер отсутствует в уже установленной системе.

В ECSpec есть ecBt1Temperature=0x4A2. Это конкретный кандидат для батареи,
но ширина, единицы, valid flags и применимость к HYDROC ещё не доказаны:
читаемого действующего getter в этом наборе пока не получено.
Батарейные System Battery Class wrappers также есть; Windows Win32=1 в
пользовательском дампе не исправляется одним фактом наличия константы.

GCUBridge содержит MQTT bridge, TCP port13688. Это программный посредник,
не kernel driver. Работа через bridge требует установленной родной службы;
его наличие в пакете не доказывает, что она запущена на ноутбуке.

11. Итог для следующего шага
Родной драйвер и транспорт EC найдены и проверены статически.
Можно проектировать отдельный read-only HYDROC adapter с точным SMBIOS match,
проверкой PnP ACPI\INOU0000 и фактических ProjectID/capability bytes.
Управление FANs/лимитами/подсветкой включается после определения конкретной
ветви и аппаратной проверки. Разбор архива сам по себе не разрешает перенос
проверенных на GM6/X5 битовых масок на HYDROC.
