19.10.2026

Результат
=========
Из точного GCUService.exe пакета ControlCenter_5.23.51.56_Eluktronics_V4
расшифрованы ВСЕ5512 записи таблицы JIT-защиты. Для каждого тела проверен
контрольный хвост VBPD. Дополнительно раскрыты все6 обнаруженных обёрток
DynamicIL, в том числе настоящий App.Main и декодер строк.

1424 верхнеуровневых типа и два метода модуля выгружены в C#.
Ошибок экспорта:0. Диагностик Error near IL_:0.
13223 вызова декодера константных строк заменены их результатом в читаемой копии.
16604 обращения к прокси снабжены именами целей из ТОЧНОЙ таблицы724 импортов.
Удалено7960 только явно недостижимых if(false)/if(1==0) с пустыми присваиваниями.

Все операции — чтение PE/метаданных, преобразования байтов и декомпиляция.
OEM-сервис, его .cctor, DLL, драйверы, EC и UEFI не запускались.
Исходный OEM-файл не изменён. Файлы *.analysis-only.dll находятся в build/.
Эта папка содержит исследовательский результат, а не готовый проект для сборки
или замены Control Center. Исходная и читаемая версии сохранены раздельно.

В исходных метаданных5513 метода ссылались на общее тело-заглушку.

Пустые тела и чужие реализации вместо него не подставлялись.

Как восстановлена защита
========================
В DLL-плагине защитного загрузчика найден JIT-hook FUN_180001b50.
Библиотека извлечена без LoadLibrary: RC4 внешнего контейнера, затем RC4 каждой
секции компактного PE. Статический образ исследован Ghidra; native-код не исполнялся.

В FUN_180001b50 находятся четыре DWORD ключа RC4:
  1AB1215F 2317DBEA 1C9F87B5 9BFC772D
Байты ключа берутся в little endian, как в самой функции.
Таблица FWSN: файловое смещение00822048,5512 элемента по24 байта.
Смещение шифрованного тела вычисляется из его собственной записи; одновременно
проверяется соответствие RVA/файлового смещения. Проверены CLI-заголовки,
длины IL, диапазоны LocalSignature и VBPD в КАЖДОЙ записи.

Второй слой извлечён из аргументов шести настоящих DynamicIL-обёрток.
Ключ16 байт раскрывается штатным32-байтным преобразованием загрузчика; затем
RC4 расшифровывает соответствующий CLI body. Аргументы и SHA сохранены в proof/.
Тело декодера строк подтвердило формулу для UTF-16 code units:
  key = byte(length ^ 0x58)
  result[i] = char((cipher[i] + 10 + i) ^ key)
Приведение key к byte обязательно, в том числе для строк длиннее255 символов.

Ранние попытки сопоставления с GM6 и линейного обхода сохранённых тел находились
в build/research-hydroc16g2/battery-recovery. Они были исследовательскими
кандидатами с неоднозначными ссылками. Они НЕ являются входом данного результата.
Все публикуемые здесь тела извлечены по native-ключу и собственным дескрипторам.
Ни один адрес тела, импорт или метод в этой выгрузке не подставлен из GM6.

Что подтвердилось по HYDROC
==========================
1. App действительно вызывает BatteryProtection2.EnableByService, Receive,
   Resume, Disable и Uninstall.
2. Рабочие профили PERFORMANCEDMODE/BALANCEDMODE/HEALTHYMODE меняют7A6.4–5
   на00/10/20 с сохранением остальных битов. Сохранение — HealthProtectionStatus
   в OEM\GamingCenter2\BatteryProtection2. Resume повторяет профиль.
3. Для CustomizeTarget17 И56 значение по умолчанию — BALANCEDMODE, для остальных
   PERFORMANCEDMODE. Это отличие от исследованного активного GM6-кода.
4. Восстановленный Receive обрабатывает три профиля, RECOVERY и GET.
   Прямых вызовов private SetBatteryChargingLimit_Up/Down и
   LoadBatteryLimitationDefault во всём IL не обнаружено; подробности в audit.json.
5. Восстановленный сервисный NvramVariable.SetFwVars(string,byte), как и
   DefaultTool, не содержит обработки трёх батарейных ключей. Одни поля
   BatteryLimitation/ChargeMaximumLimit/ChargeMinimumLimit не задают активацию.
6. MyFanCtrl выбирает базовый менеджер или семейство RamFan1p5 по capability/
   Commercial/CustomizeTarget. В его конструкторе нет выбора RamFan2.
   Наличие других классов внутри EXE не означает их использование на этой плате.

Эти результаты подтверждают команды OEM-кода. Проценты остановки зарядки для
трёх именованных профилей и физический зарядный ток этим статическим разбором
не измерены. Возможности записи HYDROC в MagicControl здесь не расширялись.

Воспроизведение
===============
1. Нужны исходный GCUService.exe с указанным SHA, Python3 и metadata-only
   Decompile.exe, собранный из recovery-tools/Decompiler с локальной библиотекой
   ICSharpCode.Decompiler.dll11.1. Метод target assembly никогда не вызывается.
   Проект принимает путь к библиотеке через -p:DecompilerAssembly=полный_путь.
2. Extract-Native.py --input GCUService.exe --output КАТАЛОГ
   сохраняет статический native image и его хэш. Он нужен для анализа источника ключа.
3. Decrypt-Jit.py --input GCUService.exe --output КАТАЛОГ
   извлекает5512 проверенных тел и сохраняет manifest.
4. Decrypt-Inner.py --directory КАТАЛОГ --decompiler Decompile.exe
   раскрывает6 внутренних обёрток из их собственных аргументов.
5. Export-Readable.py --input GCUService.exe --directory КАТАЛОГ
      --decompiler Decompile.exe --destination КАТАЛОГ_ИСХОДНИКОВ
   выгружает raw/readable C#, таблицу импортов и хэши.
   Параметр --reuse-raw пропускает только уже выполненный экспорт C#.

Сохранённые скрипты повторно создали те же SHA256 JIT image, all-layers image
и native image. Сборка metadata-only инструмента завершилась без ошибок.
