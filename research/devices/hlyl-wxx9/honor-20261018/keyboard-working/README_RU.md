# Рабочая подсветка клавиатуры — HUAWEI HLYL-WXX9

Это отдельный проверенный комплект для ноутбука:

- модель: `HUAWEI HLYL-WXX9`, плата `HLYL-WXX9-PCB`, версия платы `M1010`;
- BIOS: `HUAWEI 1.09` от `18.05.2022`;
- embedded controller: ITE `IT8987`, прошивка EC `1.9`;
- сборка программы: runtime-only, self-contained `.NET 10`, `win-x64`.

Комплект управляет подсветкой через работающий runtime-интерфейс I2EC контроллера.
Он **не прошивает BIOS**, **не записывает EC flash** и не использует старую
нерабочую WMI/ACPI-службу.

EXE принимает только четыре I2EC-режима: read-only, однократный HIGH, тест
трёх уровней и системный автозапуск. Старые экспериментальные команды WMI/ACPI,
secondary-EC и remap из этой сборки удалены; неизвестный аргумент возвращает
код `64` без обращения к аппаратным портам.

Версия `1.0.1` учитывает подтверждённое состояние после выхода из сна:
`level=0x00`, `shadow=0x80`, `PWM=0x00`. Оно разрешается только в однократном
пути HIGH и только после прохождения всех остальных проверок контроллера,
питания, guard, PWM-конфигурации и двух одинаковых снимков. Другие
рассогласования по-прежнему блокируются.

Исправление проверено на фактическом состоянии после сна: запуск от `SYSTEM`
завершился с первой попытки и кодом `0`, после чего read-only снимок подтвердил
`level=0x02`, `shadow=0x80`, `PWM=0x64`. Подробности:
`verified-results\resume-fix-2026-08-29.txt`.

## Что уже проверено

Физически проверен полный цикл `OFF -> LOW -> HIGH` три раза, с паузой в одну
секунду. Все три уровня реально меняли яркость, итоговое состояние было HIGH.
Копия журнала лежит в `verified-results\three-level-cycle-confirmed.txt`.
Установка защищённой задачи и её реальный запуск от `SYSTEM` также завершились
с кодом `0`; результат сохранён в
`verified-results\autostart-protected-verification.txt`.
Отдельная проверка чистого CLI и отказа старому ключу `--service` сохранена в
`verified-results\runtime-only-cli-verification.txt`.

Проверенные runtime-значения:

| Уровень | XRAM `0x02F4` | XRAM `0x03FC` | PWM2 duty `0x1804` |
|---|---:|---:|---:|
| OFF | `0x00` | `0x00` | `0x00` |
| LOW | `0x01` | `0x40` | `0x32` |
| HIGH | `0x02` | `0x80` | `0x64` |

Программа перед записью проверяет модель контроллера, доступность I2EC в режиме
read-write, текущие EC guard/power-state, конфигурацию PWM2 и строго разрешает
запись только в три адреса выше. После записи выполняется read-back.

## Быстрое включение HIGH

Откройте PowerShell в этой папке и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Turn-On-HIGH.ps1
```

Скрипт сам запросит UAC. Результат сохранится в `Turn-On-HIGH-Result.txt`.

## Проверка трёх уровней

Три раза переключает `OFF -> LOW -> HIGH`, по одной секунде на состояние, и
оставляет HIGH:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-OFF-LOW-HIGH.ps1
```

Результат: `Test-OFF-LOW-HIGH-Result.txt`.

## Read-only проверка состояния EC

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Read-EC-State.ps1
```

Результат: `Read-EC-State-Result.txt`. Этот режим не пишет целевые EC-данные.

## Автоматическое включение для всех пользователей

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Autostart.ps1
```

Установщик создаёт или обновляет задачу `\HuaweiKeyboardLightRuntime`. Она
работает от `SYSTEM` с максимальными правами и включает HIGH:

- через 30 секунд после загрузки Windows;
- через 10 секунд после входа любого пользователя;
- через 3 секунды после разблокировки;
- через 5 секунд после выхода из сна.

Перед созданием задачи установщик проверяет SHA-256 и копирует рабочий EXE,
закреплённую библиотеку PawnIO и подписанный модуль в защищённую системную папку:

```text
C:\Program Files\HuaweiKeyboardLightRuntime
```

Именно эту защищённую копию запускает задача `SYSTEM`. Сам комплект можно
хранить в `Documents`, но постоянная системная задача намеренно не указывает на
изменяемый пользователем EXE — это исключает опасную подмену файла с последующим
запуском от `SYSTEM`.

При раннем запуске программа запускает установленный demand-driver PawnIO и
делает до трёх попыток. Журнал автоматических запусков:

```text
C:\ProgramData\HuaweiKeyboardLightRuntime\autostart.log
```

Удалить только задачу автозапуска:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall-Autostart.ps1
```

Скрипт удаления не удаляет PawnIO, файлы комплекта или данные BIOS/EC.

## Важные условия

- Системный драйвер PawnIO должен быть установлен. Его установщика в этом
  комплекте нет; на данном ноутбуке PawnIO уже установлен как `DEMAND_START`.
  Библиотека `PawnIOLib.dll` версии 2.2.0 и подписанный модуль `LpcIO.bin`
  включены и закреплены по SHA-256.
- При ручном запуске из `Documents` программа намеренно загружает закреплённую
  библиотеку только из защищённой стандартной папки установленного PawnIO.
  Локальная копия из комплекта начинает использоваться лишь после переноса в
  защищённую `C:\Program Files\HuaweiKeyboardLightRuntime`; это блокирует DLL-
  подмену из изменяемой пользовательской папки.
- Старая служба `HuaweiKeyboardLight` больше не требуется. Установщик оставляет
  её строго `STOPPED/DISABLED`; чистая runtime-only сборка также корректно
  работает, если этой службы вообще нет.
- Перед ручным тестом закройте HWiNFO, RWEverything, superiotool и другие
  программы, которые одновременно обращаются к EC/Super-I/O.
- Галку PC Manager, запрещающую автоматическое выключение подсветки, можно
  оставить включённой. Поэтому постоянный опрос EC не используется: HIGH
  применяется только на системных событиях.
- Файлы BIOS в этот комплект не входят, и ни один скрипт прошивальщик не
  запускает.

## Контроль целостности

Критические SHA-256 записаны в `SHA256.txt`. Скрипты ручного запуска и
установщик автозагрузки дополнительно проверяют все три хеша перед работой.

Проверить вручную:

```powershell
Get-FileHash -Algorithm SHA256 .\HuaweiKeyboardLight.exe
Get-FileHash -Algorithm SHA256 .\PawnIOLib.dll
Get-FileHash -Algorithm SHA256 .\pawnio-modules-0.2.10\LpcIO.bin
```

## Исходники и пересборка

Проверенные исходники находятся в `source`. Пересобрать отдельную копию:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build.ps1
```

Новый результат появится в `rebuilt`. Проверенный EXE в корне пакета не
перезаписывается автоматически. Для пересборки нужен установленный `.NET 10 SDK`;
первое восстановление NuGet-пакета `System.ServiceProcess.ServiceController`
может потребовать интернет или уже заполненный локальный кэш.

`Build.ps1` проверен: свежая пересборка дала байт-в-байт тот же SHA-256, что и
EXE в корне. Результат записан в
`verified-results\build-reproducibility.txt`.

## Состав папки

- `HuaweiKeyboardLight.exe` — проверенный рабочий EXE;
- `PawnIOLib.dll` — подписанная и закреплённая библиотека PawnIO 2.2.0;
- `pawnio-modules-0.2.10\LpcIO.bin` — подписанный модуль доступа к I/O;
- `Turn-On-HIGH.ps1` — однократное включение HIGH;
- `Test-OFF-LOW-HIGH.ps1` — наглядный тест всех уровней;
- `Read-EC-State.ps1` — read-only диагностика;
- `Install-Autostart.ps1` / `Uninstall-Autostart.ps1` — автозапуск SYSTEM;
- `verified-results` — копии уже успешных проверок;
- `source` — исходники `.NET 10`;
- `SHA256.txt` — контрольные суммы критических файлов.
