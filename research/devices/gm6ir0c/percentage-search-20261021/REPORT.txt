GM6IR0C: как реализован процентный предел в проверенных исходниках
21.10.2026. Агент «Поиск». Только статический разбор.

ИТОГ
Полный применимый механизм физических100/95/85% для точного GM6IR0C
N.1.05MRO09 / Project25 не найден. Найдено несколько РАЗНЫХ host-интерфейсов,
и у каждого установлена граница применимости. Наличие числа7B9 или слова
Uniwill в проекте не доказывает наличие одинакового firmware consumer.
Производственная батарея, EC, GUI, INI, portable и build inputs не менялись.
Аппаратных вызовов, запуска OEM/исследуемой DLL, тестов или сборок не было.

Что новое относительно прежнего INDEX
1. Реально разобрана NUCtoolV2.dll из текущего Reference_Projects: найден
   WCF контракт IUniwillService с отдельными percentage/mode/rate API.
2. Сопоставлены его явно заявленные NUC-модели с теми DMI, где Linux
   действительно включает percentage feature. GM6 этой цепочкой не покрыт.
3. В exact OEM дополнительно проверен feature gate отдельной QC-ветки
   и отсутствие выбора этой ветки в текущем MyFanCtrl.
4. Прочитан сырой threshold60-stopped.json HydroControl: остановка есть,
   но Reached и Enabled не установлены. Это уточняет прежний текстовый lead.
5. Свежая загрузка pinned upstream Linux совпала побайтно с нашим14.10
   snapshot. Отдельного нового GM6 gate в ней не появилось.

3. EXACT GM6 OEM: проверен дополнительный QC gate

Активная сборка GCUService1.0.2.70, SHA указан в соседнем Healthy report.
MyFanManager_QC.SetBatteryChargingLimit(:1808) действительно пишет7B9.low7,
100 кодирует0. Receive/UserSet(:548) допускает60/70/80/90/100 лишь при
SMBIOSINFO.m_bSupportBatteryLifeExtension. Нижнего порога/7C3/87F setter
в этом методе нет. Сохранение/CheckFirstTime(:867) повторяет только upper.

CustomizeCtrl.cs:259–316 вычисляет m_bSupportBatteryLifeExtension только
после IsQCRefreshBIOS. Проверяются структура Win32_BIOS.BIOSVersion и
реверсированная OEM SMBIOS string(type11,string18), index4. Пустая строка
в этой отдельной QC-ветке включает feature по default. Это BIOS feature
metadata другой платформы, не register gate742/741 для нашего GM6.

Критично: по полному all-active поиск MyFanManager_QC дал только объявление
класса. MyFanCtrl.cs:27–72 выбирает RamFan1p5 по IsSuportRamFan1p5 и
commercial ProjectID; на exact GM6 это MyFanManager_RamFan1p5. В его
dispatcher нет нового QC percentage command. Наличие QC-класса внутри DLL
не означает, что GM6 является выбранной/поддержанной QC-моделью.

BatteryProtection2 private SetBatteryChargingLimit_Up/Down остаются без
caller в полном all-active; CHARGING_UP_LIMIT enum не создаёт dispatch.
Native Healthy chain, default100/95 полей и UEFI cached writer уже разобраны
соседним battery-healthy-20261021; сейчас проверены снова по файлам.
Ни SettingName, ни registry/cache не заменяют missing consumer.

6. ЧТО МОЖНО СЧИТАТЬ ПРАВИЛЬНОЙ АРХИТЕКТУРОЙ ДЛЯ GM6

Только после получения применимого consumer:
- Exact identity/capability отдельно от transport availability.
- Upper requested, configured/readback, enabled и physical stopped — разные поля.
- Healthy7A6 сохраняется отдельным native API, не переименовывается в85/95.
- Shared transactional transport с fresh masked RMW и owned rollback.
- Restart/persistence/resume определяются доказанным GM6 consumer, не именем
  OEM private Down и не совпадением с Wujie80 или NUC100raw.
- Для пробы нужны нативный SOC/remaining/full, ток/напряжение, источник AC,
  firmware gate/reached и контекст до/после; OS SOC может быть remapped.

Сейчас недостаёт exact EC/BIOS/SMM кода, который потребляет7B9 и задаёт
chargeIC stop/restart. Драйвер и AML дают дверцу чтения/записи; они не содержат
этого алгоритма. Существующая пара85/80 уже держалась при положительном токе.
Объявлять её рабочей или добавлять неподтверждённый platform4/ROMID/stored
writer по совпадению адресов оснований нет.

Интернет21.10: primary Linux дополнительно закреплён commit/SHA. Exact
GM6IR0C+charge/7B9/JiguangX запросы не дали нового технического первичного
consumer; сторонние driver-scan страницы не использованы как алгоритм.
CAPTCHA/HTML от OEM BIOS не повторно выдавалась за firmware, доступ не обходился.
