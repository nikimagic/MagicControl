# AFU на Intel: /O, /0 и /ALL

25.10.2026. Проверены комплектные readme/User Guide именно AFU5.17.00.0153,
байты Windows EXE, руководство AMI для Intel M10JNP2SB и веб-поиск. На железе
никакая команда, включая помощь /?, не запускалась.

**Для сохранения: `AFUWINx64.exe backup.rom /O`. Латинская O, не цифра0.**
Это описано в [руководстве AMI для Intel Server Board M10JNP2SB](https://winraid.level1techs.com/uploads/short-url/1RMQ6auqWcD24gsVay6dsYGS1nn.pdf),
страницы11/17. Это AMI-authored документ, доступная копия на стороннем хосте.
Он подтверждает синтаксис AFU на Intel; не аттестует чтение всех регионов GM6.

В нашей комплектной инструкции
research/windows-full-spi-20261024/ami-original/AMI_Aptio_5.x_AFU_User_Guide_NDA.extracted.txt:

- Раздел2.2/3.3 описывает/O как операцию сохранения. Command/O нельзя смешивать
  с обычными flash options произвольным образом.
- **Раздел10.4 — BIOS Guard. `/ALL` означает запись всех секций** входного
  BIOS Guard образа. Рядом/BIOSALL и/MEALL для записи соответствующих секций.
  Тот же смысл прямо присутствует в бинарнике AFU поfile-offsetECFD0.
- /FDR,/MER,/GBER — программирование Descriptor/ME/GbE, а не переключатели
  областей для чтения. Добавлять их к/O для «полного бэкапа» не обосновано.
- /HOLEOUT сохраняет конкретный ROM Hole поGUID, не обещает весь SPI.
  /BCPALL сохраняет значения настроек перед обновлением, не полный flash.
- /CMD и/OEMCMD — OEM-зависимые команды. Для GM6 нужного безопасного read
  extension не найдено; неизвестные значения не подбирались и не запускались.
