MagicControl 0.1.110 — две вложенные карточки внутри батареи

EC слева: время до разряда, до100% и до порога, полная/заводская ёмкость,
здоровье по EC. Windows справа: полная/проектная ёмкость и здоровье ОС,
название базовой схемы, лимит частотыCPU иEPP. В Linux правый заголовок
отражает реальный OS-источник; Windows policy там недоступна и не выдумывается.

Два видимых прямоугольника на прежней kFanNestedSurface с заголовками.
В каждой строке подпись слева, значение справа, с переносом при необходимости.
Ширины значений измеряются текущим native шрифтом; одна общая geometry helper
задаёт столбцы обеим ОС. Высота строк учитывает две строки текста иDPI.
Совпадающий с заголовком источник на каждой строке повторно не печатается.

Цвета времени сохранены: разряд красный, заряд зелёный, прочерки нейтральные.
Отступ от строки порта16DIP, между вложенными карточками12DIP, padding общий.
Windows обновляет полные вложенные карточки через существующий buffered paint,
чтобы изменения текста/ширины не оставляли старые фрагменты; кнопки и scroll
не инвалидируются. Linux использует прежний canvas redraw.

Другие карточки, шрифты, палитра, scrollbar mechanics, журналы, формулы,
источники данных, политики и аппаратные команды не менялись. Диагностическая
карточка сохраняет BatteryLog gate. Новый renderer или транспорт не добавлен.

Поставка: общий Release0.1.110, рабочие portable Windows/Linux, версии иSHA256
четырёх GUI/CLI,450 исходных входов,9 защищённых UI/палитра sources,
6 личных файлов,11 архивных логов. См. фактический verification JSON.
Тесты,GUI,драйверы и аппаратные пробы не запускались. Визуальный прогон
в работающем приложении не выполнялся; проверена компиляция/статические файлы.

Дополнение: в обе вложенные карточки добавлены текущие показания как в
эталонном компактном блоке: SOC, мощность, циклы, температура, напряжение,
ток. Слева EcBatteryReading.battery, справа чистый readOsBatteryOnly.
Windows ток вычислен по W/V, процент по ёмкостям; отсутствующие данные
драйвера не заменяются EC. Отдельного батарейного PawnIO источника нет.
Прежний paint компактной диагностической карточки извлечён в один helper
в каждом native адаптере и вызывается в трёх местах, без новых копий renderer.
Используются прежние batteryCard/batteryCardGeometry и палитра. Добавление
сводок не добавляет аппаратных чтений: paint использует принятый sample.
