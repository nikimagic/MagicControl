R2. Явные Wujie CLI power/limit/static keyboard после записи собирают
новый SettingsSnapshot и вызывают тот же rememberSettingsChoice, что GUI.
Используются прежние rememberObservedBattery/Power/LightingChoice и атомарный
DevicePreferences writer. Второго INI writer в CLI нет. При отказе свежего
чтения или сохранения команда возвращает ошибку, не обещает сохранение.

foreground-операцией. Восстановление и временная индикация не записывают

applyApuAutomaticLimits/applyApuStockProfile/applyApuAllowedLimits/
applyKeyboardBacklight. Использует executePowerResource,
applyStandardPowerProfile и applyLighting, как явные входы.
Сохранены KeyboardLightingPause, expected snapshots, masking, readback,
FAN-preserving arguments, transaction и прежние lifecycle retry/step policies.
Штатный профиль восстанавливается через общий native entry без действия
GUI, которое дополнительно меняло бы файл Custom selection.

R4. ОТКРЫТО. GPU GUI admission/private worker и direct CLI provider path не
исправлены этим коммитом. Нельзя считать весь проект переведённым на один
command lifecycle. NVIDIA/Update/OSD/screen-flip GUI thread debt остаётся.

R5. Linux primary GTK и записывающий CLI используют один OS flock lease до
создания аппаратных контроллеров. Файл /tmp/magiccontrol.application-control.v1.lock
не удаляется: иначе две стороны могли бы заблокировать разные inode.
FD закрывается RAII, lease освобождается при завершении процесса, перед exec
не наследуется. Symlink/nonregular/multilink отбрасываются; lock-busy отдельно
от прочих ошибок ОС. Read-only CLI остаётся доступен. Без IPC/handoff/daemon.
Область гарантии: новые сотрудничающие процессы0.1.403+ в одном host/tmp
namespace. Старый GUI, сторонний CC и другой namespace не участвуют.
Это application ownership, не гарантия физической атомарности firmware.

R6. Capture использует общую BatteryUiPolicy: текущие100/95/85/60, raw0->100,
плюс старый10 для чтения прежних настроек. Пользовательские файлы не мигрируют
насильно и диапазон реально поддерживаемых записей не расширяется.
