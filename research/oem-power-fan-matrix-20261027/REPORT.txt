ТОЧНОЕ Type-C ПРАВИЛО GM5/GM6:
GetTypeCsatusFromEC читает7CC и возвращает raw &0x36.
Если Windows Offline -> g_ACLineStatus=0.
Если Windows Online и masked value==18 decimal(0x12) ИЛИ36 decimal(0x24)
-> g_ACLineStatus=0. В остальных Online случаях ->1.
18 и36 здесь НЕ ватты и НЕ проценты батареи. Смысл конкретной мощности
адаптера эти две проверки сами по себе не устанавливают.
R PowerModeEvent читает тот же Type-C status, но проверяет только Windows
Online/Offline. Перенос этого различия на exact5.57 без тела метода запрещён.

КРИТИЧЕСКОЕ ОТЛИЧИЕ ОТ MagicControl Default:
Родной DefaultFanTable_* означает заводскую КРИВУЮ, которую CC загружает
в RAM и активирует. Это не эквивалент нашей команде Default с отключением
RAM/custom/override gates. Штатный CPU профиль нельзя автоматически
приравнять к7C6.bit2=0. И наоборот, RAM active не означает только Custom.
SetFanTable асинхронен: queue disable/write/enable; SetUserProfile продолжает
остальные настройки. Здесь не доказана общая атомарная транзакция OEM.
UpdateStatusToTray вызывается рано, до завершения queued FAN write;
это не аппаратный readback и не образец для подтверждения успеха у нас.

6. ЗАРЯДКА — ОТДЕЛЬНАЯ ПОДСИСТЕМА
BatteryProtection2 SetHealthProtectionHigh/Middle/Low используют маску7A6[5:4]:
Performance/FullCapacity=00, Balanced=01(bit4), Healthy=10(bit5).
Это не CPU Office/Gaming/Turbo. Из рассмотренной цепочки CPU профиля
не следует автоматическая смена battery mode, Platform ID или ROM ID.
В найденных CPU methods не вызывается BatteryProtection2.
7A6 имеет другие соседние биты; перенос названия одного бита на весь байт
или на другую модель недопустим. Наше согласованное задание не меняет зарядку/ID.
