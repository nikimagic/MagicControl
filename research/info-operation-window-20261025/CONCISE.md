# Исправление избыточного текста окна INFO

По скриншоту владельца0.1.203: технические UI snapshots/JSON/precheck/vendor
metadata непригодны для пользовательского окна. Требование: начало сбора,
важные редкие события/инструкции, ошибки красным, успех зелёным.

Изменения:

- OperationMessages хранит типизированные пользовательские записи с Tone.
- В publish действует явный allowlist каналов/событий. UI/action snapshots,
  поля инвентаризации, адресные чтения EC, vendor banners/проценты и служебные
  параметры в окно не поступают. Полные дисковые JSONL/stdout/stderr сохраняются.
- BIOS/VBIOS failed/capture_failed извлекают details.error; vendor вывод даёт
  только строки Error/ERROR/Warning. Важные power-input prompts выводятся явно.
- Имена файлов/partial directory не дублируются в пользовательской причине
  ошибки. Одинаковая причина с точкой/без точки выводится один раз.
- Старт: «Сбор данных начался.». Успех: «Сбор данных завершён успешно.» зелёным.
  При ошибке — красная причина и «Сбор данных не завершён.», без зелёного текста.
  Отмена имеет отдельный итог. Сохранение inventory проверяется как часть успеха;
  hardwareWarning не приравнивается к успешному сбору.
- Win32: RichEdit character format по каждой записи, фон и цвета из общей темы.
  GTK: теги text buffer той же темы. Используется прежняя общая прокрутка.

Ожидаемый вывод для показанного случая без внешнего питания:

1. Сбор данных начался.
2. Для чтения BIOS подключите внешнее питание. (красным)
3. Сбор данных не завершён. (красным)

Аппаратные операции и приложение агентом не запускаются. Проверка — компиляция
обеих ОС, static review всех finish-call sites и версии/SHA portable.
