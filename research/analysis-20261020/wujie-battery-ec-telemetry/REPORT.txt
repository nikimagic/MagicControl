Wujie X5SP4NAG: процент и мощность батареи из EC
Проверено20.10.2026. Только сохранённые файлы; записи/чтения оборудования не выполнялись.

ВЫВОД
На точном Wujie82/72/26 можно получать оба показания из read-only EC telemetry:
- готовый целый SOC: byte4AB;
- проверка процента:100 * word436 / word404;
- мощность: word434[mA] * word438[mV] / 1 000 000;
- направление: word432 & 3:1=разряд,2=заряд,0=покой,3=недопустимая комбинация.
Отдельный достоверный регистр готовых ватт не установлен: ватты рассчитываются.
Положительное значение434 само по себе не означает зарядку: ток без знака.
Это карта только данной платы, не GM6/HYDROC/Honor.

  design6400mAh, поэтому Windows health100% не заменяет фактический full.
Байт4AB не объявлен здесь как отдельное ACPI поле; его SOC-семантика ниже
подтверждается точными дампами. Исполняемый EC consumer SOC не восстановлен.

Прикладной GCUService_Reference_w568w — НЕ точная версия нашего runtime.
MyControlCenter/BatteryInfo.cs:11–13,98 читает процент через
SystemInformation.PowerStatus.BatteryLifePercent. BatteryModel/BatteryInfo.cs:
62–64 получает CurrentCapacity/Voltage/DischargeRate через Windows Battery IOCTL.
В GCUService_Current/GCUService.decompiled.cs:31200+ нужные методы по-прежнему
Runtime exception stubs. Их наличие не выдаётся за восстановленное тело.
Решающее точное OEM-доказательство здесь — DSDT самого ноутбука.

ПРОВЕРКА ДАМПОВ
analyze.py проверил identity82/72/26 и validity каждого используемого байта.
36 различных RAM снимков:21 разряд,11 заряд,4 покой. SOC от8 до86%.
Во ВСЕХ36 byte4AB точно совпал с100*word436/word404; максимальное расхождение0.
Это согласованность представлений одной оценки BMS, не два независимых датчика
и не доказательство точности/дробного разрешения. Для99–100% в этой выборке нет
raw RAM кадров; скриншот не подменяет их проверку.

Примеры EC, без смешения с более поздним battery.json:

  voltage14682mV,state1 => разряд9.998442W;
-20.10,100812, initial: SOC76,remaining4408/full5800; current2006mA,
  voltage16771mV,state2 => заряд33.642626W;
-20.10,113108, initial: SOC85,remaining4930/full5800; current0,state0 =>0W.
4A4 совпадает с434 в35/36 кадрах, но это не оправдывает замену XST1 чужим
зеркалом. Полные4KiB собираются неатомарно, адреса могут отражать разное время.

В fast sensors позднего дампа69 пар Windows Rate / EC-supplemented U,I:
медиана абсолютного расхождения0.000176W, максимум2.299864W.
Это только проверка согласованности: журнал не отмечает успешное EC-чтение
каждого поля отдельно, а fallback I=Windows W/V может совпасть по построению.
Чтения также последовательны; нельзя считать такие пары независимой
лабораторной проверкой точности или сравнивать ec.bin с поздним battery.json
как одновременные измерения.

ГРАНИЦЫ БУДУЩЕГО ПОДКЛЮЧЕНИЯ
Использовать существующий read-only EcAccess только после точной identity,
валидировать присутствие/готовность, целостность слов, допустимые значения и
состояние. Читать короткий согласованный набор, проверять повтором, не смешивать
старый ток с новым напряжением и не угадывать направление по одному current.
Если набор недостоверен, возвращать недоступность/fallback Windows с явным
источником. SOC4AB разумно сверять с436/404; нулевой full не делить.
Никаких SMBus команд, сброса BMS, смены лимита/напряжения или EC firmware не нужно.
Производственный код/карточки/portable в этой задаче не менялись и не запускались.

Первичный стандарт единиц и состояния (не источник адресов данной платы):
https://uefi.org/specs/ACPI/6.5/10_Power_Source_and_Power_Meter_Devices.html
Разделы10.2.2.1 _BIF и10.2.2.11 _BST: Power Unit1=mAh/mA, Present Voltage=mV,
state bit0=discharging,bit1=charging; обе установки одновременно недопустимы.
Подробные адреса, valid masks, пути и SHA256 каждого кадра — evidence.json.
