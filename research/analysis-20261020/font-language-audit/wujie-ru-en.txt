MagicControl — Wujie / common RU-EN font and translation audit
Date:2026-10-20. Static audit only. No production/UI/config edits, GUI,
hardware/EC access, tests, application/helper builds or commits in this task.
Wujie remains the visual reference: no proposed card/scrollbar redesign.

Scope and evidence
Read AGENTS.md, docs/LINUX-UI-PARITY.md, Wujie README, all entries of the
shared four-column translation catalog, Windows localization adapters and
common cards/OSD plus Windows/Linux SETs/BIOS/updates/font consumers.
Only RU and EN linguistic correctness is assessed here. SC/TC column presence
is counted, not a review of Chinese wording/glyph quality (other agents own it).
Source revision and hashes are recorded at the end. No external web claim needed.

Summary
NoP1 established. Main confirmed P2 defects: untranslated/mixed safety/status
messages; language-independent decimal comma; unit fragments; unmapped update
window status/title; misleading Firmware mode label for Wujie lighting preset.
The current catalog has no empty RU/EN fields and its existing entries are
reviewed individually in the complete ledger below; that is NOT full UI coverage.
Unknown strings are explicitly preserved by translate(), so extra Russian text
does not become English merely because both languages can render its glyphs.

P2-1 — Safety/ownership/battery statuses lack English messages (both OSs)
Mechanism: src/gui/common/Localization.h:219–235 matches only the enumerated
Russian fragments and preserves the rest; it has no typed status/error keys.
Exact examples:
 src/gui/common/MonitoringCards.h:65 "Батарея не установлена" ->
  "Battery не установлена"; suggested EN "Battery not installed".
 :67 "Питание: источник неизвестен" -> "Power source: источник неизвестен";
  suggested "Power source unknown".
 :68 lowercase "заряд" is absent while catalog has uppercase "Заряд";
  suggested complete template "Charge: {value} %".
 :70 "последние показания" absent; suggested "last available readings".
 :74/77 "Нет батареи", "Источник неизвестен", "Нет показаний" absent;
  suggested "No battery", "Source unknown", "No readings".
 :100/108 source-unavailable/data-missing strings absent; suggested
  "No data" / "Source unavailable".
 src/devices/mechrevo/x5sp4nag/windows/FanControlWindows.cpp:392
  "Нет свежих температур CPU/GPU; управление возвращено EC." is not a full
  catalog key; suggested "No fresh CPU/GPU temperatures; firmware control restored."
 :435 "Флаги управления вентиляторами EC изменились." -> incomplete English;
  suggested "EC fan-control flags changed.".
 :547 "RAM-таблица изменена другим владельцем; восстановление отменено.";
  suggested "RAM fan table changed by another controller; restore cancelled."
 These are our own statuses, not untranslated third-party vendor error payloads.
 src/gui/windows/FansPage.cpp:1025/1080–1094 forwards controller.message to the
 operation status. Changing a language does not supply missing templates.
 src/gui/linux/SettingsPage.cpp:31/135/137 similarly retains Linux transport/
 unsupported backlight reasons in Russian; suggested complete messages
 "Linux EC/SMU transport is not connected. Hardware control unavailable."
 and "Linux keyboard-backlight driver is not connected yet."
RU converse: src/devices/mechrevo/x5sp4nag/windows/BatteryChargeWindows.cpp:125,
152/225 emits own English exceptions ("stored charge limit readback mismatch",
"Unsupported charge limit", "EC battery platform readback mismatch"). RU UI
returns input unchanged (Localization.h:220); suggested RU "Сохранённый предел
заряда не подтверждён чтением", "Неподдерживаемый предел заряда", "Режим
батареи не подтверждён чтением EC". Keep raw vendor/API error codes alongside.
Fix proposal: shared stable message IDs/parameters + complete four-language UI
messages for our own states. Preserve raw driver/API diagnostic payload separately.
No fan/EC mechanism or UI geometry change is needed to localize messages.

P2-2 — EN numbers use Russian comma; RU/GPU formatting inconsistent
 src/gui/common/MonitoringCards.h:15–21 replaces every decimal point with comma
 regardless of active language; applies CPU/GPU/RAM/battery/card readouts on
 Windows and Linux. EN can show "43,0 °C", "12,41 V".
 src/gui/windows/SettingsPage.cpp:782–786 and873–874 repeats forced comma for
 APU watts and battery health; Linux SETs uses monitoringNumber as well.
 src/gui/common/DiscreteGpuCard.h:31–32/42/49 uses std::format with default dot,
 so in RU separate GPU card can show dot beside comma in FANs.
Suggested shared display formatter: RU comma, EN dot; one grouping/unit policy
across cards; keep logs/JSON/CSV machine formats invariant. Do not change telemetry
values or introduce language-dependent parsing into saved fan/power settings.

P2-3 — Unit fragments remain mixed (BIOS/inventory and common readouts)
 Catalog Localization.h:104–108 covers MHz/GiB/MiB/mA/W but not Гц, Вт·ч, В/ГБ.
 src/platform/windows/BatteryInterfacesWindows.h:72 formats "{:.2f} Вт·ч";
 greedy fragment matching yields "W·ч", not Wh, in English (Вт matches but ч
 has no entry). Suggested exact whole-unit EN "Wh" (RU "Вт·ч").
 src/platform/windows/InventoryDetailsWindows.cpp:136 and
 src/platform/windows/InventoryWindows.cpp:457/489 output Гц; EN should be Hz.
 src/gui/common/MonitoringCards.h:82/110 hardcodes V/MHz even for RU while
 other strings use МГц; not a sensor error, but typography/locale inconsistency.
Suggested atomic unit tokens/full-value formatters instead of fragment replacement.
Keep degree-Celsius, SI scales and binary GiB/MiB correct; no GB/GiB substitution.

P2-4 — Updates window status/title bypass localization
Windows src/gui/windows/UpdateWindow.cpp:53/66 creates and updates raw STATIC;
no applyWindowLanguage or localized() call exists there. Ownerdraw buttons use
localizedDrawText(:75), so buttons translate but status remains Russian.
Window title :84 also raw "MagicControl — Обновления".
Linux src/gui/linux/UpdateWindow.cpp:31/36–37/45 creates raw title/status without
applyWidgetLanguage; actionButton for controls is localized via Ui.cpp:304–306.
Own asynchronous messages :20/24 remain unmapped in catalog even if routed.
Suggested EN title "MagicControl — Updates"; "Click Check.";
"Checking GitHub Releases…"; "Preparing update…";
"Version {version} is available. Click Update. Settings and curves are preserved.";
"Version {version} is up to date."; "Package verified. Restarting…".
Use shared label/status adapter and message templates; root separately documents
hardcoded Segoe UI/DPI issues at Windows UpdateWindow.cpp:51. Do not duplicate
font helpers or change Wujie card geometry to fix this secondary dialog.
Startup dialogs: src/gui/windows/main.cpp:82–84 (already running) and94–97
(failed to create window) use raw Russian Unicode escapes in MessageBoxW before
MainWindow loads saved language. Suggested EN “MagicControl is already running.”
and “Could not create the window.”; root owns startup language/font solution.

P2-5 — "Firmware mode" incorrectly describes Wujie keyboard action
 Localization.h:51 maps "Штатный режим" -> "Firmware mode".
 src/gui/windows/SettingsPage.cpp:1470–1472 stops host cycle, sets level4,
 effect0 and Wujie colorValues()[5] (cyan). This is an application lighting
 preset; it does not relinquish control to a firmware keyboard policy.
Related statuses :1343/1669 say "Штатная подсветка"/"Восстанавливаю штатную
подсветку…", neither has a complete EN key.
Suggested terminology decision (without altering card placement): EN
"Default preset" / "Applying default lighting preset…"; RU "Штатная
предустановка" / "Применяю предустановку подсветки…" if owner approves wording.
Do not silently change the hardware action to make the existing English true.
"Штатное управление EC" -> "Firmware EC control" (catalog:65) is separately
appropriate for FANs Default and should not be globally replaced.

P2-6 — OSD and KEYs success/error coverage incomplete
 src/gui/common/OsdMessages.h:8–9/16–20/26–28/33–38/42–43 own messages
 "Подсветка выключена", "Громкость", "Звук выключен", "Микрофон включён",
 "Клавиатура", "Текущее состояние", "Состояние клавиши" lack full EN keys.
Even common adjective forms differ: dictionary "Выключен" does not match
lowercase "выключен" appended to Caps Lock. Suggested complete message IDs:
"Keyboard backlight off", "Volume {value}%", "Muted", "Microphone on/off",
"Touchpad on/off", "Camera on/off", "Key state", "Checking device state…".
 src/gui/windows/KeysPage.cpp:235–244/265/320/322 similarly includes own
 unmapped states, selected-vs-confirmed messages and caveats. Suggested
 "Setting applied and saved to app-settings.ini.", "Change confirmed.",
 "Command completed, but the device state is unconfirmed.".
 Translate pending/confirmed/unknown distinctly; do not collapse readback into
 proof of physical effect. Retain CPU/GPU/EC/SMU/PWM and technical API names.

Fonts, measurement, truncation — confirmed structure, not visual pass
 Common Fonts.h:25–35 shares role sizes/weights; :76–83 Windows maps Segoe UI
 families; windows/Layout.h:35–39 substitutes private Noto Sans SC only when
 enabled and excludes symbol role. Windows MainWindow.cpp:223–228 and Linux
 main.cpp:17–39/74–77 register/fallback and log font availability. Font absence
 is not proof of missing letters; system substitution/fallback remains OS-owned.
 No RU/EN-specific font-family divergence is established by these source paths.
 Linux Ui.cpp:62–82 shapes/measures translated text with Pango; :151–177 clips
 within reference line boxes and uses shared fixed ascent/lineheight from
 Fonts.h:48–61, not the active font's ink extents. This is a static clipping risk
 for substituted fonts/combining marks, NOT confirmed visible clipping.
 Windows BiosPage.cpp:46–49/273–278 measures localized text before row heights;
 Linux BiosPage.cpp:59–62 does the same via textHeight; keep this good behavior.
 Windows ControlTheme.h:43 uses DT_END_ELLIPSIS and Linux Ui.cpp:315 sets
 label ellipsis: avoids overflow but does not prove full EN captions fit.
 SettingsPage.cpp:866/878/904 single-line diagnostics use ellipsis; longer
 translated safety reasons need accessible full text/tooltip, not wider cards.
 Static audit cannot establish which installed fallback face actually renders,
 optical glyph quality, DPI100/125/150/200% fit, missing-glyph boxes or screenshot
 parity. No GUI/font rendering/test was run. Record these as unverified, never
 present source review as a visual pass. Do not modify scroll geometry.
