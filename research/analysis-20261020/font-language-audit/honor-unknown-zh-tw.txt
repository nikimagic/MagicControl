TW-01 [P2] Неполные фразы и перевод фрагментов дают русско-китайскую смесь
Источник механизма: src/gui/common/Localization.h:219-235.
Отдельный ключ «Нет» имеет значение «否» (Localization.h:177), но функция
заменяет его и в начале неизвестных фраз. Вывод из чтения алгоритма и
входных литералов (не результат запуска приложения):
  «Нет показаний» -> «否 показаний»;
  «Нет батареи» -> «否 батареи»;
  «Просмотр профиля» -> «預覽 профиля»;
  «Не установлена» и «Разрядка» остаются русскими целиком.
Источники видимого текста:
  src/gui/common/MonitoringCards.h:27-32, :70-80;
  src/gui/windows/SettingsPage.cpp:763, :797;
  src/gui/common/Localization.h:76, :140, :177.
Доступны «Не установлен», «Разряд», «Просмотр», но не нужные здесь полные
фразы/словоформы. Дефект общий для Windows/Linux и всех моделей; Unknown
чаще попадает в состояния без данных, поэтому заметнее остальных.
Точные предлагаемые TW-строки:
  Нет показаний -> 無法取得讀值
  Нет батареи -> 未安裝電池
  Батарея не установлена -> 未安裝電池
  Не установлена -> 未安裝
  Разрядка -> 放電
  Просмотр профиля -> 設定檔預覽
  Питание неизвестно -> 電源來源不明
  Источник неизвестен -> 來源不明
  Источник не подключён -> 尚未連接資料來源
  Источник недоступен -> 無法取得資料來源
Рекомендуется полный message-ID/шаблон для предложения, а не наращивание
эвристического пословного перевода. Не менять тексты сырых диагностик в файлах.

TW-02 [P2] Состояния Honor, включая подтверждение и потерю владения, не переведены
Windows источники:
  src/gui/windows/SettingsPage.cpp:797, :803-807, :1083;
  src/devices/huawei/hlyl-wxx9/FanControlWindows.cpp:30-34, :77-82, :111;
  src/devices/huawei/hlyl-wxx9/ControlWindows.cpp:101, :135-136.
Linux источники:
  src/gui/linux/SettingsPage.cpp:70-72, :137, :232-233.
Пример штатной строки Windows:
  «Huawei · белая подсветка · Выкл./Низкая/Высокая»
  -> «Huawei · белая подсветка · 關閉/低/高».
Строка «Honor: ручной PWM подтверждён; контроль температуры активен»
вообще не имеет подходящего ключа. Пользователь TW не получает понятной
разницы между selected policy, временным гашением, аппаратным readback,
возвратом Auto и неподтверждённым rollback. Это ошибка полноты, а не повод
подменять состояние успехом. Бэкенд не должен терять исходную диагностику.
Предложения TW для полных пользовательских сообщений:
  Huawei · белая подсветка · Выкл./Низкая/Высокая
    -> Huawei · 白色背光 · 關閉／低／高
  Huawei · белая подсветка · временно погашена таймером
    -> Huawei · 白色背光 · 已由計時器暫時關閉
  Huawei · белая подсветка · плавное гашение по таймеру
    -> Huawei · 白色背光 · 正依計時器設定漸暗
  Huawei · белая подсветка · выключена после сна
    -> Huawei · 白色背光 · 從睡眠喚醒後仍為關閉狀態
  ручной PWM подтверждён; контроль температуры активен
    -> 已確認手動 PWM；溫度監控已啟用
  владение потеряно; чужой ручной режим не изменён, возврат Auto не подтверждён
    -> 已失去控制權；未變更其他程式的手動設定，尚未確認恢復自動模式
  откат не подтверждён; состояние неизвестно
    -> 尚未確認回復成功；目前狀態不明
  Батарея: системные показания. Управление ограничением зарядки для этой модели не подключено.
    -> 電池：系統讀值。此型號尚未提供充電上限控制。
В последующей реализации связывать перевод с кодом состояния/параметрами;
не разбирать аппаратные коды строковыми заменами.

TW-03 [P2] Linux tooltip, подписи доступности и заголовок выбора цвета обходят перевод
src/gui/linux/Ui.cpp:99-113 обрабатывает только GTK_IS_LABEL и дочерние виджеты.
Не локализует свойства tooltip-text, accessible label, GtkColorDialog title.
Конкретные потребители:
  src/gui/linux/SettingsPage.cpp:159 — русские имена цветов в tooltips;
  :178 — gtk_color_dialog_set_title(dialog,"Выберите цвет");
  :218 — «Выбрать цвет для предпросмотра»;
  :223, :225, :230, :232-233 — таймер, включая специфичные Honor инструкции;
  src/gui/linux/MainWindow.cpp:260 — «Проверить обновления MagicControl».
Даже полное добавление этих фраз в каталог недостаточно без перевода свойств.
Предложения:
  Выберите цвет -> 選擇色彩
  Выбрать цвет для предпросмотра -> 選擇預覽色彩
  Белый/Красный/Оранжевый/Жёлтый/Зелёный/Голубой/Синий/Фиолетовый
    -> 白色／紅色／橙色／黃色／綠色／青色／藍色／紫色
  Здесь «Голубой» — cyan RGB(0,255,255), а не light blue:
  src/gui/windows/SettingsPage.cpp:75-76 и src/gui/linux/SettingsPage.cpp:40.
  Поэтому точная подпись TW — 青色 (допустимо 藍綠色), не 淺藍色.
  Включить/отключить штатный таймаут Huawei
    -> 啟用／停用 Huawei 原廠背光逾時計時器
  Huawei: 0–3600 секунд. 0 — без автоотключения. Изменение применяется при выходе из поля.
    -> Huawei：0–3600 秒。0 表示不自動關閉。離開輸入欄位時套用變更。
Общий адаптер локализации должен хранить исходник каждого свойства и применять
его также при смене языка. Системный нативный диалог может иметь ОС-язык;
его собственные кнопки этим аудитом не объявляются переводимыми приложением.

TW-04 [P2] Неверное название физической величины: W подписаны «耗電量»
src/gui/common/Localization.h:59:
  RU «Потребление» / EN «Power usage» / SC «功耗» / TW «耗電量».
src/gui/common/DiscreteGpuCard.h:35 использует эту подпись для GPU мощности;
src/gui/linux/MainWindow.cpp:250 также собирает строку «Потребление: — Вт».
耗電量 — количество потреблённой электроэнергии, тогда как W измеряет мощность.
Точное исправление TW: «耗電功率» (или единообразно «功率» с соседними полями).
Значение и единицы W не изменять; никаких конверсий мВт/Вт здесь не требуется.

TW-05 [P2] Десятичная запятая навязана всем локалям
src/gui/common/MonitoringCards.h:15-20 принудительно меняет '.' на ','.
Для zh-TW (как и EN/SC) это даёт «23,89 GiB» вместо «23.89 GiB» и аналогично
для мощности/температур/напряжения. Группировка RPM пробелами задана отдельно
(:51-56) и не должна случайно менять хранимые данные или числовой ввод.
Предложение: общий formatter по выбранному UI-языку, RU запятая,
EN/zh-CN/zh-TW точка; хранение CSV/INI/JSON и протоколы оставить независимыми
от UI locale. Сейчас это статический факт функции, не визуальная проверка.

TW-06 [P2] SC-начертания Han используются также для zh-TW
src/gui/common/Fonts.h:15-16 закрепляет Noto Sans SC без привязки к языку.
src/gui/windows/Layout.h:35-38 выбирает его для всех текстовых ролей.
src/gui/linux/Ui.cpp:51-76 выбирает ту же семью; язык Pango не выставляется.
languageTag(TraditionalChinese) -> zh-TW (Fonts.h:91), но в просмотренном
font pipeline этот тег не участвует в выборе региональных форм глифов.
Подтверждённые root-агентом данные ресурса, также прочитанные в этом аудите:
  research/analysis-20261020/font-language-audit/font-metadata.json
  cmap 30890; все символы 201 Entry × 4 языков присутствуют;
  GSUB содержит ZHS, отдельного ZHT нет; семейство Noto Sans SC.
Следствие: отсутствующих кодовых точек словаря в cmap не найдено; поведение
рендерера и отсутствие квадратов в окне этим не проверены. Корректные
тайваньские региональные формы не гарантированы. Это не
«упрощённый перевод»: текстовые кодовые точки TW сами по себе традиционные.
Предложение: языковой выбор TC-совместимой семьи/ресурса или CJK-шрифта
с доказанной ZHT поддержкой; выбрать Pango language/context по UI-языку.
Отдельно измерить роль/строку на обеих ОС, сохранив эталон карточек Wujie.
Не предлагать механическую глобальную замену шрифта ради одной локали.

TW-07 [P2] Фразы новых режимов/цикла и OSD остаются русскими
src/gui/windows/SettingsPage.cpp:800:
  «Цикл 6 · цвет 2 / 6 · каждые 5 сек»
  -> «六色循環 · цвет 2 / 6 · каждые 5 秒».
Словарь знает «Цвет» и «Каждые» с заглавной, но не строчные формы этой фразы.
Предложение полного TW-шаблона: «六色循環 · 色彩 {index} / 6 · 每隔 {seconds} 秒».
src/gui/common/OsdMessages.h:8, :15-35 содержит «Подсветка выключена»,
«Громкость», «Микрофон», «Клавиатура», «Тачпад включён» и др., которых нет
полными сообщениями в каталоге. Это общие события для обеих ОС/всех профилей.
Примеры: 背光已關閉, 音量 {percent}%, 麥克風已關閉, 觸控板已啟用.
Сохранять параметры и событие, локализовать только представление.

TW-08 [P3] Английские имена пользовательских режимов не локализуются
Localization.h:220 сразу возвращает строку без кириллицы. Windows
FansPage.cpp:303-312 и Linux FansPage.cpp:394 задают Default/Manual/Max/
Manual\nonline. Аналогично «Unknown» в DeviceHeader.h:19 сохраняется как есть.
Названия моделей, идентификаторы, бренд и короткие подписи вкладок FANs/SETs
не объявляются ошибкой только из-за латиницы: они часть утверждённого дизайна.
Для собственно режимов предлагается согласованный словарь с пояснениями
«韌體自動», «手動», «最大轉速», «即時手動控制»; либо явно зафиксировать
Default/Manual/Max как неизменяемые термины продукта и локализовать описание.
Unknown как имя профиля можно оставить; не менять внутренний id noname.
Не менять размеры/разбивку кнопок без отдельной задачи и измерений.

СМЫСЛОВО ПРОВЕРЕННЫЕ ТЕРМИНЫ БЕЗ НАЙДЕННОЙ ОШИБКИ

韌體 (firmware), 驅動 (driver; расширенное 驅動程式 допустимо), 主機板,
記憶體, 顯示記憶體, 時脈, 唯讀, 遲滯, 電池充電上限, 循環次數,
健康度, 外接電源, 已套用/未套用/未確認 сохраняют нужное различие.
Моно/單色, Пульсация/呼吸燈, Мульти/多色 адекватны текущим общим эффектам;
не утверждают RGB на монохромном Honor. W/GiB/MiB/mA/MHz/°C и проценты
в каталоге не искажены. Три батарейные подписи 100%/95%/85% общие и в
переводных состояниях не должны заменяться OEM названиями режимов.

ФОРМАТ И ПОЛНОТА ПАРАМЕТРОВ

В 201 Entry нет printf/{name} шаблонов с переносом аргументов между языками;
пустых TW-строк нет. Основной риск — конкатенация переведённого существительного
с непереведённым окончанием и русским порядком слов, а не потерянный %d.
Числа/порог/температура должны оставаться параметрами цельной фразы.
Не менять payload команд, raw code, units, пути и аппаратные имена при переводе.

ОГРАНИЧЕНИЯ

Это не визуальное подтверждение fitting/ellipsis, не проверка reader/screen
reader и не аппаратное измерение. Длинные строки и запас по вертикали требуют
впоследствии отдельной согласованной визуальной проверки RU/EN/SC/TC на обеих
ОС при нескольких DPI. У Honor/Unknown не найдена отдельная font policy:
они используют общий renderer и общий дефект локализации/региональных форм.
Для исправления этих пунктов не требуется новая архитектура вкладок или
изменение карточек/скроллбара. Билд и portable в этой ревизии не обновлялись.
