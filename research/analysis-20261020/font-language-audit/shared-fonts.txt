MagicControl: ревизия общей типографики, 20.10.2026
Объект: текущие исходники и working portable Windows/Linux 0.1.90.
Охват: Wujie, GM6IR0C, Honor HLYL-WXX9, HYDROC-16 G2, Unknown;
RU, EN, zh-CN, zh-TW; встроенный шрифт и системный fallback.
Метод: чтение исходников, разбор бинарных таблиц sfnt, SHA256 комплекта.
GUI, EC, тесты, сборки и установка шрифтов не запускались.

ПОДТВЕРЖДЕНО

1. Все пять моделей используют общий FontRole и один набор размеров/весов.
   src/gui/common/Fonts.h:9-35; windows/Layout.h:30-42; linux/Ui.cpp:62-75.
   Отдельных семейств или размеров для карточек каждой модели не обнаружено.
   Модель меняет данные/доступность через общие страницы. Это сохраняется.

2. Комплект содержит NotoSansSC.ttf, variable wght 100..900.
   Фактически запрашиваемые роли имеют веса400,600,700; default оси100
   сам по себе не доказывает неверную толщину: адаптеры передают вес явно.
   Семейство Noto Sans SC. cmap содержит30890 кодовых точек.
   Все уникальные символы всех201 записей словаря, включая четыре колонки,
   присутствуют в cmap. Это не проверка контента вне словаря или shaping.
   Метаданные: font-metadata.json.

3. SHA256 шрифта в исходниках, двух рабочих portable и двух подготовленных
   каталогах GitHub_Releases/0.1.90 совпадает:
   a3041811a78c361b1de50f953c805e0244951c21c5bd412f7232ef0d899af0da
   Размер17772300 байт. OFL и NOTICE находятся рядом в assets/fonts.
   Оба working portable build-version.txt:0.1.90.

4. Загрузка приватная: Windows AddFontResourceExW(FR_PRIVATE),
   MainWindow.cpp:224-228; Linux FcConfigAppFontAddFile,
   main.cpp:17-44. Шрифт не устанавливается системно. При неудаче есть fallback
   и startup log. При embeddedFont=false Windows выбирает Segoe по роли,
   Linux семейство gtk-font-name; пиксельное совпадение системного режима
   между разными ОС/окружениями не гарантируется.

ПОДТВЕРЖДЁННЫЕ ЗАМЕЧАНИЯ

F01 [P2] Нет выбора региональной формы традиционного китайского.
   Fonts.h:15-16 выбирает Noto Sans SC независимо от languageIndex.
   В TTF GSUB LangSys есть ZHS, но нет ZHT. В Linux createText не задаёт язык
   PangoContext, а смена языка MainWindow.cpp:315 меняет только перевод строк.
   Поэтому традиционные кодовые точки есть, но корректный набор региональных
   форм Тайваня выбранным языком приложения не обеспечен. Квадраты этим
   анализом не обнаружены и не утверждаются.
   Направление исправления: общий выбор шрифта/shaping по языку с отдельным
   проверенным TC-ресурсом либо подтверждённым региональным набором; один
   контракт для обеих ОС и для measure/paint. Размеры, роли и карточки сохранять.

F02 [P2] Windows UpdateWindow обходит общую типографику и смену DPI.
   src/gui/windows/UpdateWindow.cpp:51 создаёт Segoe UI напрямую высотой13px
   при96DPI вместо createUiFont. Это игнорирует embeddedFont и отличается
   от Body12px/ClassicBody12px, тогда как GTK наследует общий Body.
   В procedure нет WM_DPICHANGED: DPI сохраняется из owner при открытии.
   Направление: общий FontRole и жизненный цикл DPI, без изменения размеров
   карточек приложения. Это отдельное окно обновления, не карточка SETs.

РИСКИ, НУЖНА ОТДЕЛЬНАЯ ВИЗУАЛЬНАЯ ПРОВЕРКА

F03 [P3] Linux line boxes/ascent взяты из Segoe, а фактический шрифт Noto.
   Fonts.h:45-61; linux/Ui.cpp:156-174: baseline ставится по фиксированной
   таблице, затем применяется clip. Фактические ink extents не используются
   для доказательства вмещения глифов. Наличие дефекта обрезания именно
   китайских/кириллических глифов статически НЕ подтверждено.
   Проверять строки с Ё/й/диакритикой и сложными Han при96/120/144/192DPI.
   Не увеличивать карточки или менять scrollbar на основании этой гипотезы.

F04 [P3] GTK CSS вычисляется по начальному displayScale без widget.
   linux/Ui.cpp:348-355,439-443; MainWindow.cpp:198 вызывает один раз.
   Canvas получает текущий scale своего surface. После переезда между
   мониторами дробные округления Caption/KeyDetail в CSS и canvas могут
   различаться: Caption11px@96 против10.5 logicalpx@192.
   Факт расхождения формул подтверждён; заметность/обрезание не измерены.
   Проверять также изменение системного font-name при embeddedFont=false.
