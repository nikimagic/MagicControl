4. Реальные пробелы и границы нынешнего обещания

WBT1 [P2, представление]: BatteryChargeWindows.cpp:229–231 пишет в результате
restart_below=80%, хотя код только записал и прочитал80. Exact boundary и работа
нижнего компаратора не установлены. Для общего API нужны раздельные состояния:
requestedRestart80 / configuredRestart80 / restartExecutionVerified=unknown.
Слово below в format string не является доказательством EC алгоритма.

WBT2 [P2, preflight/rollback]: строка179 читает storedBefore без проверки диапазона,
а203 специально допускает FF. Старый C# BatteryChargeLimiter.cs:125–127 отвергал
low7>100 как недостоверный baseline. При частичной ошибке текущий rollback274
может вернуть low7=127 из FF или иной invalid value, отсутствующий в supported API.
Нужно либо отказывать до записи при неизвестном baseline, либо отдельно оформлять
инициализацию неизвестного состояния; не обещать безопасное восстановление
невалидного threshold. В этой работе исходники не менялись.

WBT3 [P2, полнота подтверждения]:225 проверяет EC upper/lower/gate, но не свежий
WMI87F в трёх финальных readback. stored=verified означает предыдущий readback
или только начальное совпадение. Если OEM изменит WMI во время ожидания, итоговая
фраза может устареть при ещё совпадающем live upper. Для строгого результата
нужно поле lastStoredReadAt/value или конечное ограниченное перечитывание WMI.
Это статический сценарий, не новая воспроизведённая аппаратная неисправность.

WBT4 [граница100]: raw0 по OEM и старому C# отключает процентное ограничение.
Current100/platform4 отличается от старого100/platform7, поэтому старый A/B
не подтверждает current combination4+upper0+lower80. Обычный полный заряд через
BMS не доказывает заданный программой80–100 гистерезис. Поддержка restart80
при100 не следует из одного readback7D0.

WBT5 [политика питания]:7C3 меняет не только зарядку. Измерено на DC и AC100W:
  tests/test_util/analysis/battery-platform-smu-20261016/ALL-MODES.md:7–24;
  tests/test_util/analysis/charger-rating-smu-20261016/REPORT.md:7–28.
На DC platform4 сводит native APU режимы к Fast/Slow/STAPM45/40/40; при7 они
различаются. В проверенном наборе AC65W эффект отсутствовал, AC100W — был.
Нельзя переносить4/7 на другую плату как универсальный battery-enable.
Current API правильно не компенсирует эту политику скрытыми APU/FAN записями.
Дополнительный voltage cap7A6 также может ограничивать эффективный upper:
старый C#155–157 снимал его для изолированной пробы, current API его осознанно
не трогает. Preserve/OEM policy и конкретный percentage preset — разные функции.

5. Перенос общего пользовательского контракта
Можно унифицировать карточку, логическую цель и typed pair restart80,
stop{100,95,85}. Нельзя переносить Wujie7B9/7D0/WMI87F/platform4 на Honor/GM6/
HYDROC/Unknown только ради одинаковой семантики. Нужны независимые capability,
точные setter/readback активации, valid range и OEM policy. Native7A6 профили
нельзя переименовать в100/95/85 без подтверждённой процентной функции.
Для Wujie upper85/95 выше порога физически подтверждены; current lower80 —
configured/readback. Контракт владельца сохраняется, executionVerified — unknown.

6. Минимальный будущий эксперимент restart — только описание
В этой работе не выполняется. На exact Wujie с устойчивым AC/температурой и без
OEM перехвата зафиксировать config80/85, platform4,ROMFF,gate и Battery Class
поток; получить исходную подтверждённую остановку около85.
1) Отключить AC, разрядить до81, подключить тот же адаптер. Без нового setter
   записать реальный ток/мощность, SOC gauge4AB и capacity ratio, upper/lower,
   platform/gate/reached. Старт при81 опровергнет правило «не раньше80» для
   повторного подключения, даже при7D0=80.
2) Если81 не запускает заряд, отдельно повторить на80 и79 с устойчивыми отсчётами
   после перехода. Различать continuous-AC recharge и adapter-reconnect:
   подключение адаптера может иметь отдельную политику, один опыт не покрывает оба.
3) Для100/95 повторить как отдельные пары, не экстраполировать85. Чтобы установить
   строго <80 или <=80, нужны SOC квантование/внутренняя шкала либо exact EC
   компаратор; целого Windows процента и mWh ratio мало для точной границы.
Сохранение после sleep/reboot — отдельная серия: раньше измерено хранение WMI
числа при потере platform/gate. Записи статуса742.2,ROMID, неизвестных битов
или firmware для такого наблюдения не нужны. Новые пробы не запускались.
