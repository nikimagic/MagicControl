4. Наш core, цикл, lifecycle, locks
KeyboardBacklight.cpp:68–100: общий EcAccess transaction; свежие masked RMW,
readback RGB/effect/brightness, соседние fan/USB/lightbar поля сохраняются.
Cycle expected73–74 охватывает RGB/breathing/Rainbow, намеренно не Fn brightness.
Journal27–38 записывает попытки изменений, перед откатом сравнивает own masks;
неподтверждённый rollback пока только журналируется — см.K3.

KeyboardColorCycle112–130: первый цвет сразу; далее wait interval, затем общий
DeviceOperationKind::Background. Он не публикует interactive begin/end, поэтому
старое мигание доступности кнопок при каждом цвете в этом коде не воспроизводится
по прежней причине. Интервал отсчитывается после EC операции: период немного
длиннее заданного, это видно и в старых логах, не потеря шага.
Смена RGB/effect извне останавливает cycle; stop/exit оставляет последний цвет.
Startup autoplay отсутствует. Сам цикл не хранится как desired effect в INI;
старый Mono цвет сохранён отдельно. Скрытие вкладки не уничтожает реальные страницы.

ConfigurationRestoreWindows.cpp:239–257 сравнивает saved с current наstartup/
resume и восстанавливает эффект/RGB/яркость;110–140 делает adapter flash1с.
Эти записи пользуются общим operation gate, но не имеют session с cycle:
они могут сделать его expected устаревшим и остановить cycle при следующем шаге.
MainWindow.cpp:447–452 при suspend/resume уведомляет FanController, не cycle.
Cycle не имеет explicit power/session epoch; наличие DeviceOperation gate само
по себе не является уведомлением «была подтверждённая гибернация».

Владение741.0: FanControlWindows.cpp:491–510 выставляет APP presence свежей
маской при разрешённом lifecycle; учитывает retained RAM owner. Default/exit
не снимают этот общий gate по FAN_MODES. Из-за этого native autooff может вести
себя иначе, чем до запуска MagicControl. Переключать741.0 из галки idle нельзя.
Activity wake512–526 только strobe78C.4 при положительном уровне и bit1=0,
то есть не переигрывает cached level и не отменяет явный Off.
OsdSystemMonitor.cpp:196,264–272 наблюдает только keyboard Raw Input, отправляя
задачу FanController::keyboardActivity:1338–1341 с throttle1с/delay75мс.
Мышь сейчас не является wake source MagicControl; это не OEM CloseTimer policy.

Сериализация: Global EC transaction исключает смешивание кооперативных операций;
GUI/CLI Global single instance не блокирует чужой OEM-сервис. Wujie applyLighting
идёт прямо в общий core, без GM6 OEM process exclusion. Fan lease останавливает
GCUBridge лишь в собственных ручных режимах, Default этого не гарантирует.

5. Конкретные замечания
K1 [P2] Нет согласованного lifecycle cycle/restore/adapter flash.
  core KeyboardBacklight.cpp:118–128, ConfigurationRestoreWindows.cpp:110–140,
  239–249, MainWindow.cpp:447–452. Собственный flash/restore воспринимается как
  внешняя смена и прекращает цикл; suspend в цикле явно не представлен.
  Дополнительно model():19 на одном несовпавшем live identity инвалидирует
  весь EcAccess. Без power epoch ранний resume read может принять transient
  identity за заменённую плату. Это статический риск, не новый аппаратный repro.
  Исправление: общий lighting session с pause(reason)/resume и power epoch,
  явная граница своих временных эффектов; неизвестное после сна не писать и
  не объявлять готовой identity. Внешние изменения по-прежнему уважать.

K2 [P2] Adapter flash может сохранить временный idle blank как явный Off.
  ConfigurationRestoreWindows.cpp:130–135 вычисляет liveBrightness=0 по78C.1,
  затем rememberDevicePreferences(KeyboardLevel=0), если во время flash bit1=1.
  Но найденный OEM idle path ставит только bit1 при сохранённом выбранном уровне4,
  это НЕ доказательство пользовательского выбора Off. Получается стирание
  desired brightness по временному effective state. Подтверждена ветка кода;
  нужное совпадение событий на устройстве здесь не воспроизводилось.
  Исправление: desired/effective разделить, не сохранять preference от transient
  power-disable без подтверждённой команды пользователя/авторитетного события.

K3 [P2] Ошибки/ownership loss rollback скрыты от caller.
  KeyboardBacklight.cpp:32–38 пишет rollback skipped/unconfirmed лишь в log,
  caller получает исходную ошибку. Возможен частично восстановленный RGB/effect
  без явного результата«откат не подтверждён». В mixed-ownership случае RGB
  strobe отменяется целиком, поэтому физический возврат дополнительно неизвестен.
  Исправление: явный bounded rollback result с own-mask журналом и fresh actual
  read; aggregate original+rollback error. Не посылать триггер на чужую RGB группу.

K4 [P2] Общий process gate не исключает OEM writer Wujie.
  SettingsPage.cpp:728–729/applyLighting, core model15–20 и apply68–100 не проверяют
  GCUService/AiStone owner; cooperative locks OEM не обязан использовать.
  Cycle detects RGB takeover лишь на следующем шаге; timeout/baseline getters
  тоже не гарантируют эксклюзивного владения. В Default GCUBridge может работать.
  Исправление: общий read-only ownership/capability preflight точного backend,
  declined/unknown вместо ложной эксклюзивности; службой не управлять самовольно.

K5 [P3, семантика] «Штатный режим» не firmware ownership reset.
  SettingsPage.cpp:1464–1466 ставит level4/Mono/cyan и сохраняет это как preference.
  Оно не восстанавливает OEM mode/таймер или741.0. Не обещать takeover native
  словом«штатный». Уточнение поведения требует отдельного решения владельца;
  геометрию/скролл и подписи самовольно не менять.

6. План общего idle backend без изменения эталонного UI
Не использовать нынешний setLevel(0) как idle blank: KeyboardBacklight.cpp:96
маскойE2 стирает level bits и ставитbit1. Это правильный explicit Off API,
но не эквивалент native SetPowerDisable_EC, сохраняющего выбранный level.
Нужны desiredLevel/effect/RGB и effectivePowerDisabled; blank только собственной
маской78C.1, wake только при своей blank session и неизменившемся desired state.
Явный Off/внешний владелец/сон отменяют право wake, stale snapshot не replay.
Input policy объявлять явно: native EC keyboard-only observation, OEM app
keyboard+mouse и собственный будущий host idle не взаимозаменяемы автоматически.
Host idle живёт только пока процесс работает; не выдавать его за сохраняемый
после выхода аппаратный таймер. Cycle interval — отдельное поле и смысл.
Один shared state machine для всех profiles, transport/capability adapter для
каждой платы, существующие карточки/контролы/scrollbar остаются прежними.

7. Калибровка и Linux — не смешивать с подтверждением физики
Wujie текущая palette43: white50/50/50,orange50/10/0,purple35/0/50; custom57
round(v*50/255). Старый Fan_X15Pro Set2EcSettings.Keyboard.cs:8–15:
white50/40/40,custom divide5/min1 с исключениями. Это различие версий калибровки,
не автоматическое основание менять работающий визуальный эталон. Readback не
доказывает точный perceived RGB. Cycle6 default orange в UI255/102/0 тоже
отличается от статического orange raw50/10/0; нельзя обещать одинаковуюкалибровку.
Reference_Projects/LumaDesk/repository/src/core/driver/keyboard.rs:1–34,70–110
подтверждает сходную карту и свою floor/min1 конверсию; это не независимое
аппаратное доказательство Wujie и не источник для замены нашей калибровки.

Linux: platform/linux/BackendLinux.cpp:6–20 EC отсутствует. Linux SettingsPage
effects/cycle154,levels173,timeout223–231 disabled для Wujie; Huawei sysfs
доступность не переносится X5. На Wujie Linux нет ни RGB writer, ни idle/cycle
исполнителя; одинаковый макет не означает одинаковые hardware capabilities.

8. Подтверждения и ограничения

старые successful readback; новых optical/runtime проб0.1.88 здесь нет.

разных состояния. Не выводить поддержку таймера из741.2,6FA или чужого ITE1A.
Следующая работа — согласованная программная архитектура и отдельно разрешённые
проверки; никаких production изменений в этой исследовательской задаче нет.
