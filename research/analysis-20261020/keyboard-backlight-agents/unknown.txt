Главный вывод
Unknown сейчас правильно не получает writer подсветки другой платы. Обычный
Windows dump уже собирает HID metadata и драйверы; заново делать этот collector
не нужно. Эти данные позволяют выбрать кандидата для исследования, но не
доказывают singleRGB/per-key/white, протокол эффектов или безопасный setter.
Нативные LampArray/LED interfaces могут стать отдельными typed adapters после
подтверждения конкретного устройства. Наличие подсветки/драйвера/PawnIO не
разрешает копировать регистры Wujie. Общая карточка Wujie и скролл сохраняются.

Условные стандартные пути, без обещания универсальной поддержки

Windows HID LampArray / Dynamic Lighting
  Microsoft поддерживает устройства, реализующие открытый HID LampArray,
  непосредственно firmware либо VHF driver. Это условие устройства, не любого
  Windows ноутбука. HID lighting page0x59 — discovery lead; обычная LED page0x08
  не эквивалентна ему. Источники S1,S2.
  LampArray GetDeviceSelector/DeviceWatcher и typed device identity дают путь
  к capabilities: Kind, LampCount, SupportsVirtualKeys, MinUpdateInterval,
  GetLampInfo и key mappings. IsAvailable/AvailabilityChanged — отдельное
  runtime разрешение управления. S3.
  LampInfo FixedColor и RGB/Gain level counts позволяют описать заявленный
  fixed-color/RGB диапазон, positions/purposes — логическую топологию. S4.
  LampCount>1 сам по себе не доказывает per-key keyboard; нужна привязка разных
  programmable indices к конкретным клавишам, а не к декоративной полосе.
  Это reported topology, физическое исполнение остаётся отдельной проверкой.

  В рассмотренной public LampArray поверхности нет getter текущего RGB каждого
  индекса, эквивалентного нашему EC readback. FixedColor — capability, не текущий
  output. Нельзя показывать собственный cache или saved color как actual RGB.
  Ownership через OS availability/focus policy нельзя заменить существующим
  сравнением EC bytes. S3,S4. Setter/FromIdAsync/GetFeature здесь не вызывались;
  даже high-level device acquisition перед интеграцией требует проверки его
  I/O/lifecycle, нельзя автоматически добавлять его в passive dump как zero-I/O.

Linux LED class / multicolor
  Только конкретный native LED, связанный с keyboard parent: brightness,
  max_brightness, trigger и доступные hardware-change данные. :kbd_backlight
  относится к единой зоне; :kbd_zoned_backlight-* — к ограниченному числу зон.
  Per-key keyboard не следует реализовывать через эти sysfs LED nodes. S5.
  Multicolor multi_index задаёт реальный порядок каналов, multi_intensity —
  значения; где доступен multi_max_intensity, учитывать ограничения/клампинг.
  Не считать порядок RGB и max255 универсальными. S6.
  Отсутствие multicolor атрибутов означает отсутствие такого native RGB API,
  а не обязательно white hardware. White доказывается фиксированным белым
  каналом/цветом/точным native driver, иначе 'mono/fixed-color/unknown'.
  trigger timer/интервалы blink — не inactivity timeout и не OEM rainbow.
  Чтение configured values не подтверждает физическую яркость. S5,S6.

Конкретные пробелы/замечания
K1 [P2, support gap] Общий цикл пока не transport-neutral.
  KeyboardBacklight.h:10–15 кодирует только SingleZoneModel{Wujie,Gm6} и EC bytes;
  KeyboardBacklight.cpp:114–126 сам вызывает keyboardColorLevels(model, UI RGB).
  LampArray/LED/white/per-key нельзя подключить, назвав Unknown 'Wujie' или 'GM6'.
  План: выделить canonical UI RGB/brightness/effect capabilities и typed adapter
  conversion/ownership policy; использовать одну existing карточку и один scheduler.
  Сейчас Unknown guard это предотвращает; это не найденный активный unsafe writer.

K2 [P2, diagnostic gap] Нет явной HID→PnP/USB parent binding и report schema.
  NativeInterfaceInventoryWindows.h:132 исключает произвольные USB-class parents;
  :168 передаёт nullptr вместо SP_DEVINFO_DATA при получении HID interface detail.
  Interface/VID/PID/caps записаны, но явного parent/container/location/USB interface
  relation к driver record нет. Несколько одинаковых VID/PID нельзя выбирать
  по первому совпадению. :177–178 сохраняет длины, но не ReportIDs/value/button
  capability arrays и не protocol version.
  План: расширять ЭТОТ collector явной SetupAPI association и metadata-only
  разбором preparsed HID capability arrays; не писать дубликат и не запрашивать
  undocumented reports. Схема сама ещё не доказывает vendor command semantics. S7.

K3 [P2, Linux discovery gap] Generic keyboard LED inventory отсутствует.
  InventoryLinux.cpp:108–145 содержит DMI/OS inventory; DiagnosticSensorsLinux.cpp:
  21–45 перечисляет hwmon/thermal/power_supply/cpufreq, не /sys/class/leds.
  Подключать Known Huawei LED к Unknown нельзя. План: bounded read-only metadata
  существующих keyboard LED nodes, canonical parent/driver identity, brightness/
  max/trigger/multicolor/error/permissions; без trigger/writer/chmod/modprobe.

K4 [P3, completeness] Ошибка корня HID enumeration может выглядеть completed.
  NativeInterfaceInventoryWindows.h:160 возвращает rows при invalid HDEVINFO,
  не меняя rows.complete=false; :129 и164 при non-terminal enumeration error
  также не снимают complete. DiagnosticWmiWindows.cpp:60 переносит этот флаг
  в QueryCompletion. Ошибка в строках есть, но generic 'полный HID inventory'
  нельзя выводить из одного completion=true. План: явный partial для этих веток;
  endpoint unsupported/denied отдельно от absence. В этой задаче код не менялся.
  Дополнительно :122–127,148,161–162 — общий20s budget сначала расходуется на
  SetupAPI/SCM/hash/signature, затем на HID. HID phase может не начаться/не успеть;
  обычный dump не гарантирует descriptor каждой клавиатуры. Per-endpoint errors
  attributes/preparsed/caps — отдельные наблюдения, не автоматически отсутствие
  устройства. Разделять collection_finished, enumeration_complete и descriptor
  status, сохраняя partial rows; не считать любой complete флаг доказательством RGB.

Onboarding contract до первого разрешённого управления
  1. Actual board/BIOS/EC + native logical-device identity: PnP instance/container/
     parent, HID interface/collection/MI, VID/PID/revision, usage/page, report IDs/
     exact lengths, driver version/hash; встроенная keyboard vs external peripheral.
  2. Стандартный подтверждённый API либо точный восстановленный OEM код/версия,
     transport/protocol version, report framing/checksums, field masks/scales,
     effect palette, brightness range и real getter availability. Не адресный поиск.
  3. Capabilities per field: brightness/fixedColor/RGB/zones/per-key/nativeEffect/
     softwareEffect/nativeTimeout. Getter source, raw, sampled time и errors.
     requested/saved/accepted/actual/physicalObserved — раздельно; unknown остаётся
     unknown. Не включать все controls только из connected/PawnIO installed.
  4. Read-only discovery не захватывает автономное управление. Перед writer:
     проверка native availability/OEM/external owner; общий DeviceOperation gate;
     initial state/ownership snapshot и подтверждённый exit/rollback. При external
     change остановиться; не сбрасывать чужие цвета/режим/яркость заводским reset.
  5. Readback возможен — bounded expected-state checks/conditional rollback.
     Readback отсутствует — явно commanded-only и отдельная OS ownership policy,
     никакого выдуманного actual RGB или обещания подтверждённого rollback.
  6. Таймер6цветов допускается только с реальным typed writer и его cadence/owner
     semantics. Cycle interval, hardware effect speed и inactivity timeout — разные
     поля. Поддержка одного не включает другие. White-only RGB cycle недоступен.
  7. Disconnect/sleep/resume/availability loss/foreign change: прекратить записи,
     заново подтвердить identity/capabilities/ownership. Не включать startup autoplay
     из одного INI. На exit не воспроизводить старой чужой snapshot.

Нынешний общий cycle (KeyboardBacklight.cpp:106–128, header:29–47) — host timer,
6 цветов/1..3600с; background DeviceOperation, expected RGB/effect, остановка при
чужом изменении. Яркость hotkeys не входит в его ownership. Stop/exit оставляет
последний статический цвет. PortableSettings.cpp:318–338 хранит параметры цикла,
не доказывает состояние оборудования; startup autoplay не реализован.
