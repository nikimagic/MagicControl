GM6IR0C / HYDROC-16 G2: наши100/95/85 и родные режимы батареи
20.10.2026. Статический разбор, без запуска OEM/драйверов и аппаратных записей.

РЕЗУЛЬТАТ
Обе точные программы имеют вызываемый BatteryProtection2 с тремя профилями,
а не доказанным API верхних процентов100/95/85. Новая проверка ресурсов UI
обоих исходных пакетов независимо подтвердила названия и смысл этих профилей.
Сопоставление mode0/1/2 ->100/95/85 отсутствует в изученной рабочей цепочке.
Нельзя переименовать три имеющиеся команды в проценты и объявить задачу решённой.

РОДНОЙ ИНТЕРФЕЙС — НОВЫЕ МАТЕРИАЛЫ
GM6: из оригинального Mechrevo-Research-GM6IR0C-20261017-215647.zip извлечён
GamingCenter3_Cross.UWP_5.52.50.23_x64.msixbundle. SHA256 bundle:
fc0774ff548b8f7c3a69011ba8bb0c55e3309131c2926fd29aca62f874c868b3.
Из вложенного x64.msix прочитан resources.pri; Windows SDK makepri dump
создал XML без запуска UWP. HYDROC: исходный UWP5.23.51.56 из Eluktronics V4.

В английских строках обоих точных пакетов совпадают:
- strBatteryPerformance: High Capacity Mode — максимальная автономность.
- strBatteryBalanced: Balanced Mode — смешанное использование.
- strBatteryHealthy: Stationary Mode — преимущественная работа от адаптера.
- strBatteryModeInfo: защита срока службы от высокого напряжения.
Китайские строки указывают 长效模式 / 平衡模式 / 工作站模式, соответственно.
Проценты100/95/85 в этих восьми описаниях профилей не заданы. Это утверждение
об исследованных профильных строках, а не об отсутствии чисел во всём UI-пакете.
Проверенные локали и исходный текст сохранены в oem-ui-strings.json.

ПОЧЕМУ НАЙДЕННЫЕ100 И95 НЕ РЕШАЮТ100/95/85
В обоих BatteryProtection2 есть поля Up_Default=100 и Down_Default=95.
Это предполагаемая пара верхнего/нижнего порога, а не два из трёх профилей.
Нижний порог означает возобновление зарядки. Он не равен средней кнопке95%.

Отдельные private SetBatteryChargingLimit_Up/Down умеют кодировать процент:
- 0x7B9 &0x7F: верхний порог;100 кодируется0, бит7 сохраняется.
- 0x7D0 &0x7F: нижний порог1..95; бит7 сохраняется.
Это тела имеющихся методов, а не новые разрешения на запись наших плат.
Свежий поиск по всему C# all-active GM6 находит только определения Up/Down/
LoadBatteryLimitationDefault, без ссылок на их имена из других методов.
Для HYDROC сохранённый точный IL call graph audit.json также показывает
0 direct calls / function-pointer references для всех трёх методов.
Этим не исключается любой мыслимый reflection-вызов, но рабочая цепочка
Receive/Init/Resume напрямую вызывает только профили, не процентные методы.

Процентные свойства обращаются к NvramVariable.SetFwVars с именами
ChargeMaximumLimit/ChargeMinimumLimit/BatteryLimitation. В рассмотренном
switch SetFwVars этих ключей нет. Нельзя выводить способ включения из наличия
полей структуры или записывать UEFI-структуру ради восстановления этих методов.

MyFanManager_QC — другая ветка: список допустимых процентов60/70/80/90/100;
в нём нет95/85. Setter пишет7B9, но конструкторы MyFanCtrl обоих сервисов
выбирают MyFanManager / RamFan1p5, не MyFanManager_QC. Это не готовый backend
процентов для GM6 Project25 или HYDROC Project26.

ЧТО ОБЩЕГО У ДРАЙВЕРОВ
Общий EC API ACPIDriver Read/Write не задаёт политику зарядки и не раскрывает
порог напряжения. В поставляемом каталоге находятся разные OEM-пакеты
10.48.11.331 и11.2.18.347 с разными SHA256 SYS. Поэтому корректно говорить
об общем семействе/интерфейсе транспорта, не о побайтно одном драйвере.
Совпадение драйвера или EC-адреса не доказывает одинаковую прошивку зарядки.

ВНЕШНЕЕ ПОДТВЕРЖДЕНИЕ ПРИНЦИПА, НЕ КАЛИБРОВКА НАШИХ ПЛАТ
XMG официально разделяет три фоновых charging profiles и процентный
FlexiCharger. Для CORE/NEO с профилями Windows может сообщать100% при
сниженных фактической ёмкости и скорости зарядки. Это объясняет, почему
наблюдение100% само по себе не опровергает профиль защиты. Документ XMG
не задаёт напряжение или проценты GM6/HYDROC и не служит картой их EC.
Первичные источники:
https://help.xmg.gg/hc/en-gb/articles/17824821322653-How-can-I-give-my-battery-the-best-health-and-longest-life-possible
https://download.schenker-tech.de/temp/Quick%20Start%20Guide%20Control%20Center%20for%20XMG-2021_v1.2_en.pdf

ЧТО НУЖНО ДЛЯ НАСТОЯЩИХ100/95/85
1. Проследить выполнение процентного порога в точной исполняемой прошивке
   каждой платы либо получить контролируемое свидетельство поддержанного
   OEM percentage API.4096 байт ec.bin — RAM, не исполняемый образ EC.
2. Раздельно подтвердить включение/отключение порога, верхний cutoff и нижний
   restart. Запись95 в7B9 и чтение95 не доказывают прекращение тока.
3. При аппаратной проверке сопоставлять профиль/EC и источник питания,
   SOC, voltage, rate/current, remaining/full/design capacity во времени.
   Для испытания native profiles нужны три сопоставимых состояния и
   подтверждённый возврат; для процентного API — наблюдение самого cutoff.
   Минута лога не заменяет ожидание достижения порога. Не расходовать батарею
   или переключать защиту автоматически только ради этой статической ревизии.
4. Если процентный режим не поддержан, наши три процента остаются отдельной
   неподтверждённой возможностью; существующий native controller продолжает
   выбирать только именованные профили. Не делать mode1=95/mode2=85 наугад.
