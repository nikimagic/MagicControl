## 1. Default/Manual: команды работают, третья точка скрыта представлением

В журнале три Manual и два Default, все через общий fans.execute с
`readback_confirmed`. Время от запроса до завершения130–162мс; собственный
HPBSD writer99–126мс. Это подтверждение RAM readback, не нагрузочный тест.

Свежий4096-байтный ec.bin имеет4096валидных байтов. Selector0x32F=B1,
0x361=0C. Начальный снимок соответствует каноническому Default B1:

* CPU8полос: последняя — защитная51/100/93; обычных пользовательских7.
* System3полосы: `[base0,up25,down0]`, `[15,83,25]`, `[40,100,83]`.
  Последняя — защитная MAX; обычных пользовательских2.

В FansPage.cpp при mode==Manual скрывается последняя колонка для обоих
каналов (`bandCount - 1`). Поэтому System показывает2колонки вместо3,
CPU7вместо8. Это не пропажа байтов EC или обычной редактируемой точки.
Факт скрытия подтверждён исходником0.1.429; аппаратный codec хранит защитную
строку отдельно и её максимальное целевое значение не разрешает редактировать.

Сохранённый hpbsd-fan-curves.txt уже содержит пользовательские узлы30..80C.
Это значения кривой, не диапазон ввода. Ввод20–100C/5–100% сохранён. Manual
применяет этот прежний draft, поэтому MAX срабатывает раньше: CPU81C,
System80C; Default имеет прежние94C/83C. Точки не пересоздавались и здесь
не исправлялись/нормализовались. Видимость защиты только в подписи делает
различие колонок непонятным; это вопрос общего представления, не повод
добавлять несуществующие строки к таблице или менять рабочие кривые.

Сверху27–31% — реальный PWM1803/1804 относительно периода1841=127. В редакторе
36/38% — номинальные цели RPM. Это разные величины; равенства им не требуется.

## 2. APU измеряется, серые лимиты не являются readback

Сохранённый PM table0x4C0009 дал61согласованное чтение:

| Поле | Фактическое значение/диапазон |
|---|---|
| STAPM limit | 54.4000015Вт, без изменений |
| Slow PPT limit | 60.0000038Вт, без изменений |
| Fast PPT limit | 65Вт, без изменений |
| Fast-window power | 4.9217–10.5902Вт |
| Package power, MSR | 4.8458–9.9290Вт |
| CPU core energy power | 0.7086–7.4245Вт |

APU в нижнем CPU-блоке FANs — package power; SETs показывает отдельное
Fast-window power SMU. Системная температура35C идёт из EC0305. Подпись
источников двух строк объединена, это не чтение ватт из0305.

HPBSD profile публикует fans + SMU telemetry; публичного power writer в
SETs/общем CPU resource для HPBSD нет. Поэтому кнопки Office/Gaming/Turbo,
Custom и пресеты действительно отключены, их команд применения нет в логе.
25/25/30в серых полях — общий draft редактора, не реально принятые лимиты.
`Limit1/2/3` — запасные подписи неподключённой модели, не нативные имена.
Это недоработанное подключение HPBSD, а не доказательство плохого применения
трёх профилей. Нельзя включить только capability и унаследовать Wujie100/105Вт.

## 3. Нативная мощность: свежая прошивка совпала с уже разобранной

Новый BIOS32MiB имеет SHA
`75220b7b7f684a27b3d1241a4dcb4a71800ab5b1722176050f2f8faf4d4d3103`.
Оба прохода полностью совпадают. AFU manifest честно оставляет физическую
полноту SPI unknown: это declared_rom_image, не новая аппаратная аттестация.

Первые128KiB побайтно совпадают с разобранным EC update-кандидатом:
SHA `15fb6994c9c5292df51441cf49b876070785f95314efe02a03fea3c55065a994`.
Это встроенный образ, не независимый live EC-flash дамп.

Из свежего BIOS отдельно распакован FchTacomaSmmInit,34304байта,
SHA `1a7e674a1da97adcf06721b0f69cf20b7dc49890bc01ef49aa4c2cec1d1095fa`:
**побайтно тот же модуль**, на котором выполнен прежний полный разбор.
Повторять декомпиляцию неизменившихся инструкций не требуется.

По точному разбору ниже — не предположенные Office/Gaming/Turbo:

* Для EC61=0C и CMOS65.bit0=0 ветка CMOS63=B1 запрашивает54.4/60/65Вт.
  Это согласуется с нынешними selectorB1, I2EC361=0C и измеренными SMU limits.
* В тех же условиях B2/Performance запрашивает70.8/70.8/70.8Вт. **На железе
  эту ветку здесь не включали и фактическое применение B2 не проверяли.**
* BIOS Setup+2D, CMOS и команды B0/B1/B2 имеют отдельный lifecycle. Прежний
  разбор не доказывает безопасную разовую замену всей цепочки из Windows.
* EC B1/B2 перезаписывают обе FAN-таблицы. Их нельзя молча вызывать поверх
  пользовательского Manual и считать переключением только ватт.

Предыдущий приватный MP1 setter5–65Вт с response3B10578 подтверждал20/25/30
и8/10/12Вт и возврат baseline. Он не подключён к публичным кнопкам; его
граница65Вт не является допуском B2=70.8Вт. Подключение должно идти через
общий CPU resource с точной политикой HPBSD и согласованием FAN owner.
Не менять CMOS/EC/SMU для проверки этой гипотезы без отдельного поручения.

Точные инструкции/условия:
`../minipc-hpbsd-20261026/power-memory/native-profiles-deeper-20261028/REPORT.txt`.

## 5. Батарея/подсветка и объём лога

Пользователь подтвердил физическое отсутствие батареи и подсветки; Windows
тоже сообщает отсутствие батареи. Их setters не подключены. Пустые карточки
SETs — общий неподходящий шаблон представления, не найденное оборудование.
Будущий фильтр карточек должен опираться на наличие ресурсов, сохраняя общий
стиль и владельца layout; чужие Uniwill charge/RGB регистры не применяются.

Основной лог52.7МБ:62658низкоуровневых pawnio.lpc команд/ответов,
из них47360в explicit EC dump и остальное при5FAN-командах. Они пишутся
при активном audit action ID; периодический пассивный опрос этого потока
не создаёт. Поэтому большой файл здесь объясняется wire audit, а не
самопроизвольным повторением FAN-команд. Возможная оптимизация — перенос
детального wire audit в файл операции; в этом разборе логирование не меняли.
