DPI/scale
WindowsDisplay.cpp:82–93 records process/thread awareness metadata. It uses
GetScaleFactorForMonitor successS_OK+valid factor only, discards failure fallback
output and reports HRESULT/API absence. effectiveDpi is explicitly factor*96/100,
not raw physical panel DPI or independent custom override measurement. This
avoids implying that awareness-virtualized GetDpiForMonitor is a raw measurement.
GDK per-monitor fractional scale is optional; rounded integer scale is metadata
only. Derived96*scale DPI is labeled application convention. Window-surface scale
belongs only to the action window and is not copied to every monitor. Missing
primary monitor remains null; first/window monitor is not guessed as primary.

Cancellation, thread ownership and lifetime
DiagnosticDump.cpp:567–570 consumes a by-value serialized string or calls the OS
fallback. Exceptions become a structured unknown/error display document. Display
capture does not invoke EC/controller/fan/brightness/scale setters.
Linux BiosPage.cpp:149–166 captures GDK evidence in the GTK callback before
starting the worker. Ui.cpp:262–265 explicitly refuses off-main-context capture.
The worker captures only shared job,mode and moved std::string snapshot; no GTK
object/state pointer crosses into it. createDiagnosticDump owns another string
value; its delayed collection cannot mutate or free the original GTK objects.
Result publication uses release/acquire done flag(:165/:169); job survives page
closure. A GUI snapshot completed before later dump cancellation correctly keeps
its own capture result; overall dump cancellation is separate.
Windows getter uses local vectors/strings and RAII Shcore handle; function-pointer
calls occur while the library is held. OS handles may invalidate under hotplug;
errors/null fields are retained rather than cached pointers sent to another task.

Known limits

all API paths succeed on the user's two laptops. Snapshots are deliberately
non-atomic. Unsupported getters/primary/custom scaling remain explicit unknowns.
No out-of-scope lighting/fan/battery/firmware action was performed by reviewer.
