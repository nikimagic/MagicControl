API / worker ownership
FanController::prepareDiagnostic() returns the root-shared FanDiagnosticSession.
A DiagnosticPrepare request and awaited promise execute on the same single FAN
worker as explicitManual/Max/online/Default. Snapshot source is the worker's
confirmed own Intent, never editor drafts, savedCSV, a button highlight or a
foreign-session payload. Before copying intent, fresh owned flags and RAM bytes
must match expected. AutonomousManual checks only CPU47 owned bytes, ignoring
Down[0] and never reading GPU table. Online checks48 bytes per controlled channel;
Max is flags-only. A mismatch/unknown becomes Unconfirmed with no old-intent
replay; explicit requestedDefault may still proceed.

The ordinaryNative writer then establishesDefault; its normalrelease behavior
releases the channel/service lease. No lease/OEM service remains paused throughout
the dump. AfterDefault and lease release, the worker rechecksDefault and captures
the six masked control fields. Only this prepared readback fulfills the promise.
If preparation throws, promise exceptions are propagated; no callback is returned.

Automatic restore admission
The one-shot plan captures userGeneration, X5 powerEpoch and shared commonEpoch.
commonEpoch is diagnosticFanEpoch(), used only for cancel/admission invalidation. A normal accepted FAN
intent incrementsuserGeneration, including an explicitDefault no-op. Diagnostic
prepare/restore, MaximumProbe and Performance do not increment it. Power events
still increment the existing X5 epoch. A newer generation/epoch returns
superseded=true,confirmed=false without old replay. Foreign/unknown is not
classified as superseded; it is unconfirmed for the root warning/report.

The callback admits its own DeviceOperation (bounded5s wait for brief other work),
queues DiagnosticRestore and awaits its promise. Generation/epoch are checked
before admission/wait, request queue insertion and again by the worker. The
exception superseded flag uses the same three checks. Before writes, freshDefault and the
six masked post-Default fields must match the plan. It rechecks after acquiring
its channel lease. A previousDefault plan is a read-only confirmedno-op and needs
no OEMabsence preflight; a previousunconfirmed intent is not fabricated asManual.

For Manual/online/Max replay, the existing shared read-only OEM service/process
preflight must be known inactive; active/unknown yields refusal. Automaticbegin
