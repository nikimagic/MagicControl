Схема согласована с родительским агентом ДО реализации:
- setCpuPreset(0Office,1Balanced/Gaming,2Turbo) свежо читает соответствующую
  тройку из firmware default registers, проверяет границы и порядок, пишет
  ТОЛЬКО783/784/785, затем подтверждает всю тройку readback.
- Архивные45/75/140 и прочие ватты не подставляются при отсутствии данных.
- Нулевые, частичные/выходящие за reviewed bounds или ошибочные defaults
  оставляют этот пресет unavailable; необоснованной factory fallback нет.
- Это application CPU PL preset using firmware defaults. Это НЕ native
  whole-system Office/Gaming/Turbo, который связан с FANs/GPU/TCC.
- AC-only и запрет неизвестного PL4 Double сохранены;0/0/0 как явный Manual
  reset возвращает только CPU overrides прошивке, а не означает0Вт.
- Max bounds140/165/250 и минимум10 взяты из exact OEM Fan/Status на этом
  GM6; они не объявляются физически измеренными/эффективными лимитами CPU.
- Нет stopOnline, putTables,751 writes, commit/custom/light/respective/FAN
  writes. Online продолжает тот же intent и собственные RAM/flags.
- Старый setMode(int) теперь только совместимый вызов setCpuPreset: забытый
  старый потребитель больше не может переприменить FANs из SETs.

Actual state отдельно от native mode:
Gm6State.mode — прежнее наблюдение whole-system751, не выбор CPU-кнопки;
Gm6State.cpuPreset —0/1/2 только при одном совпадении actual overrides с
прочитанными валидными defaults. Нет совпадения/неоднозначность/Auto=>-1.
Gm6State.cpuPresetLimits[3] — optional<array<int,3>>, доступность каждого пресета;
Gm6State.cpuPresetWritable — OEM writable, AC подтверждён, известен хотя бы
один PL-пресет, PL4 Double отсутствует. GUI дополнительно проверяет optional
именно своей кнопки. Gm6State.cpuPresetStatus объясняет ограничения.
Новые observation logs сохраняют source registers/default triples/actual
limits/совпадение/writable, но не выполняют никаких writes.

2. GM6-02: сохранение Manual draft в typed backend

setPower(array<int,3>) теперь выполняет общую CPU-only механику:
validated values -> точный guard и transaction -> PL writes -> readback ВСЕЙ
тройки -> savePortableText(portableSettingsPath("gm6ir0c-power.txt"),text,error).
Формат прежний,3 ASCII целых через пробел и newline.
Общий savePortableText добавлен родительским агентом в PortableSettings,
повторно использует существующий temp+checked write/flush/close+atomic replace.
Свою дублирующую файловую механику модель не создавала.

Ошибки save/write/readback приводят к явной попытке rollback только наших
неизменённых PL fields. Journal теперь возвращает ошибку rollback; она
присоединяется к ошибке операции и журналируется, не теряется в destructor.
Перед каждым CPU rollback-write заново проверяются exact guard/OEM owner.
Если поле уже исходное, оно не записывается; если не исходное и не наше,
старое значение не навязывается, возврат считается неподтверждённым.
Файловая ошибка не объявляется удачным сохранением. Другие EC функции,
батарея, FANs и подсветка в rollback CPU-операции не участвуют.

loadPowerDraft(string& error) предоставляет typed read-only API для GUI:
optional<array<int,3>>, отсутствие файла=>nullopt+empty error; открытие,
формат/полнота/размер>4096/границы дают явный error. Никакой записи при чтении.
CPU preset не заменяет сохранённый ручной черновик и не включает power restore
на старте/после сна. GUI должен убрать прежний собственный truncating ofstream
и прочитать/показать typed draft, не выдавая75/75/200 за factory fallback.
Эту общую SettingsPage интеграцию делает родительский агент.

3. GM6-01: plateau отдельно от observed fan response

Используются новые shared FanMaximumResult.commandApplied/responseObserved,
добавленные родительским агентом. readbackConfirmed устанавливается только
при commandApplied&&restored, а fanResponseConfirmed только при
commandApplied&&responseObserved&&restored. settled больше не используется
для утверждения физической реакции. Если baseline ужеMax, стабильность без
изменения не выдаётся за наблюдение реакции. Без возврата успех не фиксируется.
Сам masked751.6 Boost setter и30-секундный sampling policy модель не меняла.

4. ГРАНИЦЫ / ОСТАВШЕЕСЯ В ОБЩЕЙ ОЧЕРЕДИ

Fresh factory FAN mailbox dump — следующая общая работа/HYDROC агент;
эту механику GM6 агент не дублировал. Shared SSD provenance — общая правка.
UI сохраняет Wujie эталон: новые страницы, controls, геометрия и скролл
не создавались/не редактировались. Shared docs нуждаются в уточнении:
  GM6 SETs CPU presets не whole-system OEM mode и не переприменяют FANs;
 0x751 native mode остается observation, cpuPreset отдельный PL-readback;
 Manual draft хранит typed controller через общий атомарный writer;
 plateau не является физической реакцией на Max.

Физическое применение PL через firmware на GM6 этой работой не измерялось.
Readback означает только значения EC; не утверждается гарантированное
MSR/RAPL enforcement, не измерялись ток/зарядка/новые RPM. Бинарники и portable
этот агент не собирал/не обновлял, итоговая сборка принадлежит родителю.
