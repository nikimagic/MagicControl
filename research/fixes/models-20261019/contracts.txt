Дополнительная разрешённая правка NativeBatteryWindows.cpp
В apply() раньше rollback skipped/failed писал только log, после чего исходная
ошибка уходила caller без статуса восстановления. Теперь:
- До любой attempted write исходный exception_type сохраняется, чтобы bounded
  retry продолжал различать только разрешённые pre-write transient failures.
- После attempted write исходная причина объединяется с результатомrollback:
  verified restore, already original/no-op либо unconfirmed/actualunknown.
- Третья policy value/OEM arrival/ошибкачтения не провоцируют переписывание
  чужого policy. При skipped/failed rollback exception явно несётunknown;
  журнал сохранён. Сам maskedwrite/readbackallowlist не расширен.
- restore5attempts/30s, backoff, OEMadmission, restoreCanRetry=false послезаписи,
  explicitcancel, settingsfiles и noexitreset не менялись.
Новый API для UI не нужен: setter по-прежнему throws, но причина полнее;
caller должен показать ошибку и выполнить существующее freshactualread.

Повторная статическая проверка Honor ownership
- automatic(false) возвращает AlreadyAuto безwrites при снятомmanual;
  при чужихtargets/отсутствииowned возвращаетOwnershipLost доwrite.
- watchdog/destructor/Maxcleanup используют false. Только явнаяDefault
  вызывает explicittrue; это намеренное переключение пользователя, неcleanup.
- Fixedrollback отвергаетtargets с третьими значениями; неудачная попытка
  не превращается в успех. Battery Win/Linux и backlight тоже проверяют
  attempted/original значения. Нового наблюдаемогоforeigncleanup дефекта
  в этих ветках не найдено. Mutex не объявляется firmware compare-and-swap.
