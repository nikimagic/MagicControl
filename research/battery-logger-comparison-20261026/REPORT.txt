WUJIE и GM6: полный состав батарейного логгера и границы расшифровки
26.10.2026. Только сохранённые файлы. Железо, утилиты, прошивки не запускались.

Состав результата

FIELD-MAP.txt / field-map.json —103 построчных описания регистров:
WUJIE 62, GM6 основные 27, GM6 CURRENT_CALC 14. Для каждого есть ширина,
порядок байтов, исходное имя логгера, смысл либо явное неизвестное, основание
и границы. METRICS-AND-FLAGS.txt дополняет их всеми группами показателей,
флагами источников и типами сообщений SOC/FLAGS/SNAPSHOT/CHANGED/CURRENT_CALC.

census.json и три *-literal-sites.json — весь адресный состав и bounded DPTR
срезы: WUJIE 618 сайтов, GM6v1.11 470, GM6v1.12 471. Это не exhaustive CFG.
curated-windows.json / CURATED-WINDOWS.asm —32 выбранных byte-linked окна.
Границы окон совпадают с концами декодированных инструкций. Наличие байтов
не подменяет доказательство startup/scheduler reachability или аппаратный тест.

Главные содержательные выводы

1. Поле 7A6.mask30 — native voltage protection, не процент SOC.
WUJIE: bank2C574..C7C8; GM6v1.12: bank2C118..C36C; v1.11: C110..C364.
00=обычный выбор с aging защитой,10=Balanced,20=Healthy.
Balanced даёт минимум 100 мВ/элемент,Healthy минимум 200 мВ/элемент.
Другие aging условия могут выбрать 150/200/250 даже в обычном режиме.
Нельзя обещать универсальные 85/95%SOC по этим значениям.

У WUJIE и GM6 сначала проверяется APP presence741.0. Если оно сброшено,
native consumer сам очищает 7A6.mask30. Это отдельный lifecycle механизм.
В точном CC5.57.1.2 методы SetHealthProtectionHigh/Middle/Low по прежнему
byte/IL разбору пусты. Наличие consumer в EC не доказывает, что конкретная кнопка
этой OEM сборки действительно передаёт режим. Другие пути NVRAM/плагины отдельно.

2. До зарядника прослежена собственная WUJIE цепочка напряжения.
BE030E/030F ->LE0522/0523 после base-Ncells*delta ->0836/0837 ->832.1 ->
bank0D5BD command15 ->подготовка SMBus запроса slave12/protocol8C.
WUJIEtable/source формула не выведена только из сходства с GM6.
522 —target зарядного напряжения, НЕ измеренное напряжение 438 и НЕ ток 434.
Наличие подготовленнойкоманды не доказывает ACK и физическое напряжение.
На DC этот target может быть старым значением с предыдущего сетевого режима.

3. Процентный limiter — другая цепочка.
Проверка допуска platform7C3=4 OR ROM770=4; отдельный SOC/upper7B9.low7,
Reached7B9.7 и нулевой outgoing-current буфер 834/835 ->command14.
В WUJIE firmware управляет 742.2 как gate/status; host не должен писать этот бит.
Число в 7B9 или зеркале 087F само по себе не является доказательством stop.
В разобранной процентной функции Reached снимается ниже того же upper.
Нативное независимое 95/90 этим не установлено.

4. 7D0 не расшифрован как действующий lower restart.
В OEM есть setterDown, в WUJI Е DSDT имя DBD1. В трёх EC нет direct literalDPTR07D0.
Это не доказательство глобальной неиспользуемости: generic mailbox и computed
адреса существуют. Флаг 7D0.7 и имя LOWER_STATUS пока не получили доказанного
native смысла. Публиковать его как работающий нижний порог нельзя.

5. Батарейный логгер содержит и совсем не батарейные поля.
74C — BIOS-family selector/status, не просто power_input.
7C6.2 — gateRAMfanCPU/GPU; low2=WMS0. Это не процентный режим.
783/784/785 — CPU запросы STAPM/Slow/Fast, не фактические SMU ватты.
7D8/7D9/7DA и 7A7/7A8/7A9 публикуются из CODE таблиц; это не живые датчики.
Полный codec единиц этих таблиц ещё не закрыт, значение 90 не даёт права назвать
его температурой батареи 90C. Кандидаты 753/754/721 остаются нерасшифрованными.

6. У WUJIE7A5 есть собственные firmware значения, которых не видно по старым именам.
Bits2/4 формируются в input-source routine из 9063. Титул OVERBOOST для bit4
не является доказанным универсальным назначением этой платы.
Bit3 — thermal latch:CPU43E>=95 или 44F>=85; снимается при обоих<=80;
изменение ставит eventBB вочередь. Это не бит остановки батареи.
Для HIGH_POWERbit7 и LIGHTBARbit1 нет подтверждённого собственного consumer
в этом bounded разборе; чужие Linux/OEM имена остаются исследовательскими метками.

7. 7C8.4 — thermal notification latch, не прямой charging-inhibit.
Собственная WUJIE ветка 837F проверяет 751.7, raw44F>=70 и APPpresent741.0,
ставит eventC8 вочередь и защёлку. При снятии 751.7 защёлка очищается.
Физический источник 44F на APUWUJIE остаётся отдельным вопросом; GPU температура 0
не становится достоверной из наличия этой потенциальной dGPU ветки.

8. Ток и состояние нельзя склеивать.
GM6v1.12:434 —unsigned модуль из 050A; есть native фильтр и selected×34 ветки.
WUJIE4A4 публикует альтернативный abs050E ссобственными guards/clamps/idle обнулением.
Следовательно, ярлык BMS_current_mirror?не доказан и 434/4A4 могут различаться.
Idle+ненулевой 434 не даёт знак мощности. OSRate и расчёт I=W/V отдельны.
Ни внутренний 0370ADC отсчёт,ни 834preparedcurrent не являются измерением тока
независимым прибором. Полный аппаратный origin и калибровкаещё не закрыты.

9. Есть различия в полноте двух действующих форматов логгера.
WUJIE core берёт SOC из 4AB; GM6 core считает remaining/full. Общий percent не означает
одинаковыйрегистровыйисточник. WUJIEECstream может писать capacity/ac=unknown,
хотя отдельные RAWsnapshot поля содержат соответствующие слова/490.
У GM6 в 27 основныхполяхнет 4A2/740/74C/7C3/770/742; temperatureStatus явно unknown.
Идентификаторы новых запусков есть в отдельных project_id/platform_id/rom_id.
Эти пробелы/различия описаны, но программа в этой исследовательской задаче
не переделывалась. Не нужно объявлять отсутствие поля ошибкой батареи/EC.

Дополнительный настоящий stop-input, не поле батарейного каталога

0984.3 участвует в firmware цепочке остановки наряду с 494/7B9.7 и safetyflags.
В WUJIE его циклически обновляет bank2B9D2 по собственным условиям/таймерам.
Он не доказан как свободная host защёлка для 95/90; runtime097C/7F4/7F5/7F6
нельзя подменять новым пользовательским chargingAPI. Доступность privateXRAM
через наш hostwindow отдельна от существования внутреннего адреса.
Основание: research/wujie-charge-gate-20261025/restart-evidence.json,
точный тот же SHAcore. Аналогичность GM6 подтверждается только собственными
его образами, а не переносом адреса WUJIE.

Что ещё не установлено

физическая калибровка ADC, единицы privateH по времени и аппаратный ACK stop/CV.

вся логика каждой прошивки восстановлена. Неподтверждённые единицы не присвоены.
Новых writer, UI изменений, автоприменений или аппаратных проверок не было.
